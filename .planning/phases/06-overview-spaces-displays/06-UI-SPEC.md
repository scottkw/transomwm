# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 6 adds the overview, Spaces awareness, the opt-in Mission Control takeover and per-display layouts. It **extends** `04-UI-SPEC.md` (approved 2026-10-27) and `05-UI-SPEC.md` and keeps every token, timing, stage property, tile style, colour, copy rule, Debug-line style and announcement pattern from them. It also keeps the Phase 3 rules those specs kept (toast panel, conflict alert style, menu disabled rules). Where this spec says "Phase 4 Surface N", that surface applies unchanged.

Phase 6 adds eight surfaces:

1. the **overview**: one panel per display, built on the Phase 4 `StagePanel`, showing that display's windows in place, scaled down (OVER-01, D-02)
2. the **Spaces strip** along the top of each overview panel: one thumbnail per Space, current Space marked, click to switch, hidden without the Spaces lookup (D-15, D-16)
3. **selection**: one highlight shared by pointer and keyboard, with arrow keys, Tab, Return and Esc (D-04)
4. the **Show Overview** command: hotkey, menu item, URL and Shortcuts-window row (D-01)
5. the **Replace Mission Control** toggle, its one-time explanation alert and its failure and crash notices (OVER-02, OVER-03, D-05..D-07)
6. **display and Space changes** the user can see: the unplug notice when windows float (D-10), and what stays silent (re-plug, arrangement switch, Spaces off/on, D-09..D-14)
7. new and changed **Debug submenu lines** (Spaces, displays and arrangement, Mission Control takeover, last overview)
8. **log lines**, **announcements** and the **user hardware checklist** (multi-display checks the Tart VM can't do)

Not in this phase: creating, deleting or reordering Spaces, dragging windows between Spaces or displays in the overview, taking over ⌃←/→ (D-08, D-16, deferred); the Settings window (Phase 9, which folds Shortcuts and the takeover toggle into it); saved views ⌥1–9 (Phase 8).

**Platform rule (unchanged).** Native macOS only. Shell = AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`, `NSAlert`). Overlays = layer-backed AppKit views drawn with Core Animation. SwiftUI only inside `NSHostingController` (the Shortcuts window). Every colour is a semantic system colour except the Phase 4 app colour. Every font is a system text style.

**Phase 2/3/4 review rules still apply:** no `.font(.system(size:))` for glyphs, no padding stacked on a system inset, no duplicated controls within one surface, no per-row AppKit lookups when the menu rebuilds. App names, icons and app colours come from the per-pid cache.

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom. None of TrellisWM's overview visuals, copy or hotkeys is used, and Mission Control's look is not copied (no darkened backdrop, no window spreading).

**Spelling.** UI strings use US English. Planning prose may stay British.

**Vocabulary added by this spec.**
- **Space**: a macOS desktop (Mission Control calls them "Desktop 1", "Desktop 2"). On-screen copy says **"desktop"** in sentences and **"Desktop {n}"** in labels, because that is what macOS shows users. "Space" appears only in Debug lines and logs, where it matches the code.
- **Overview**: the state where every display shows its overview panel. **Open**, **pick** (choose a window or a Space, which closes it), **dismiss** (close without choosing).
- **Main area**: the part of an overview panel below the strip, showing the current Space's windows in place.
- **Thumbnail**: one Space in the strip.
- **Takeover**: Replace Mission Control is on and Transom owns the Mission Control keys.
- **Dormant desk**: a desk whose display is unplugged, kept in the World but not planned (D-10).

## Spacing Scale

All values are in points. The token scale is unchanged: 4 / 8 / 16 / 24 / 32 / 48 / 64.

| Token | Value | Phase 6 usage |
|-------|-------|---------------|
| xs | 4pt | Vertical padding inside label capsules (Space labels, selected-window title capsule); outset of the thumbnail selection ring from the thumbnail edge; pointer travel below which a press on a tile still counts as a click |
| sm | 8pt | Gap between a thumbnail and its label capsule; horizontal padding inside label capsules; inset of the selected-window title capsule from the tile's bottom edge |
| md | 16pt | Gap between thumbnails; padding above the thumbnail row and below the label row inside the strip band; minimum clearance around a tile's title capsule |
| lg | 24pt | Main-area margin on the left, right and bottom of the display's `visibleFrame`, and above the main area when the strip is hidden |
| xl–3xl | 32 / 48 / 64pt | 32pt only as the cap of the mini fallback-tile icon inside a thumbnail (Phase 4 collapsed-block rule) and as the minimum thumbnail height (a size, see Exceptions); 64pt only as the Phase 4 fallback-tile icon size. Not used as spacing |

Exceptions (non-spacing metrics, listed so the checker and auditor can find them):
- **Thumbnail corner radius: 8pt** (new). Thumbnails are smaller than tiles, so the Phase 4 12pt tile radius would read as a pill. The selection ring around a thumbnail uses 8 + 4 = 12pt.
- **Mini tiles inside a thumbnail**: corner radius = 12pt × the thumbnail's scale, at least 2pt. Icon `min(32, shorter side − 8)`, hidden below 16pt (Phase 4 collapsed-block rule). No title.
- **Thumbnail height**: `clamp(visibleFrame.height × 0.12, 64, 112)`pt, width from the display's aspect ratio. When the row would be wider than `visibleFrame.width − 48`, every thumbnail shrinks by the same factor down to a 32pt height. The strip never scrolls: macOS allows at most 16 Spaces per display, and 16 thumbnails at 32pt (57pt wide at 16:9) plus 15 gaps of 16pt take 1152pt, which fits a 1280pt-wide display (1232pt available).
- **Strip band height** = 16 + thumbnail height + 8 + label capsule height + 16. Label capsule height = Label line height 13pt + 2 × 4pt = 21pt.
- **Stroke widths**: 2pt for the selection ring (main-area tiles, mini tiles, thumbnails) and the current-Space border; 1pt for thumbnail borders at rest and label-capsule borders. Phase 4's 1pt `separatorColor` borders on fallback tiles are unchanged.
- **System metrics**: menu, alert, toast, `Form` and `Recorder` metrics are system-drawn or Phase 3's. Never override them.

Semantic system colours only, no hex literals in code. Hex values are references resolved on macOS 27 with the default appearance. The Phase 3 appearance rule applies: `CGColor`s re-resolved inside `effectiveAppearance.performAsCurrentDrawingAppearance { … }` on appearance change and on `NSColor.systemColorsDidChangeNotification`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | The user's windows and wallpaper. On the overview: window snapshots plus the Phase 4 stage backdrop (the display's wallpaper from `desktopImageURL(for:)`, static, aspect-fill), or `windowBackgroundColor` (ref light `#FFFFFF`, dark `#1E1E1E`) when it can't load | The overview is the screen, scaled. No scrim, no dimming, no band fill: Transom adds no opaque chrome of its own |
| Secondary (30%) | App colour (Phase 4) for fallback and mini tiles; `windowBackgroundColor` for label and title capsules; `separatorColor` for 1pt borders; `labelColor` 85% for the 2pt current-Space border; the Phase 3 toast material | Tiles that stand in for windows, labels, and the "you are here" marker |
| Accent (10%) | `NSColor.controlAccentColor` (ref default `#0088FF` light, `#0091FF` dark) | Only the elements listed below |
| Destructive / refusal | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | **Not used by any Phase 6 element.** Phase 6 has no destructive action |
| Warning | `NSColor.systemOrange` | Phase 3 toast N7 (unchanged), plus the glyph of new toast **N11** (takeover couldn't be applied), which is the same kind of notice as N7: Transom tried to change a macOS setting and the read-back failed |

Accent reserved for exactly these elements (extends the Phase 3/4 list, which stays valid):
1. Phase 3 and Phase 4 uses (drop preview, swap origin, gap handles, rect-zoom target preview, pick-mode hover ring, collapsed-block hover ring, system-drawn uses)
2. The **overview selection ring**: around the selected main-area tile, the selected mini tile, or the selected thumbnail

The accent is **not** used for the current-Space marker (that is `labelColor` plus semibold), the strip, thumbnails at rest, labels, the empty main-area message, toasts N10/N12, or menu items. The Replace Mission Control checkmark is system-drawn.

**Overlay colour recipe (new rows).** Alpha is applied to the semantic colour.

| Element | Fill | Border | Label |
|---|---|---|---|
| Main-area tile (snapshot or fallback) | Phase 4 Surface 1 tile contents, scaled | Phase 4 (none for snapshots, 1pt `separatorColor` for fallback) | Phase 4 |
| Main-area tile, selected | as above | adds 2pt `controlAccentColor` 85%, inside the tile rect, the tile's radius | snapshot tiles add a title capsule (below) |
| Selected-window title capsule | `windowBackgroundColor` 100% | `separatorColor` 1pt | window title, `labelColor`, Body |
| Thumbnail, rest | wallpaper backdrop, aspect-fill, 8pt radius, `masksToBounds` | `separatorColor` 1pt | — |
| Thumbnail, current Space | as rest | 2pt `labelColor` 85%, inside (replaces the 1pt border) | — |
| Thumbnail, selected | as rest | 2pt `controlAccentColor` 85%, drawn 4pt outside the thumbnail, radius 12pt. Coexists with the current-Space border | — |
| Mini tile in a thumbnail | snapshot if cached, else app colour 100% with icon | snapshot: none; fallback: `separatorColor` 1pt | none |

## Surface 1 — The overview (OVER-01, D-02, D-03)

**What it is.** Show Overview opens a panel on **every display** at once. Each display's panel shows that display's own windows in place, scaled down so the Spaces strip fits above them. There is no combined cross-display panel (D-02). Real windows never move while the overview is open: everything is drawn on the stage.

**Panel.** The Phase 4 `StagePanel` of each display, in a new overview mode. Every Phase 4 Surface 1 panel property is unchanged (`[.borderless, .nonactivatingPanel]`, never key or main, `.floating`, `[.canJoinAllSpaces, .stationary, .ignoresCycle]`, `sharingType = .none`, opaque, no shadow, `ignoresMouseEvents = false` while shown). Created lazily, as in Phase 4. A display showing a full-screen Space gets no overview panel (no `.fullScreenAuxiliary`, Phase 4 rule).

**Layer tree (per display).** Backdrop (wallpaper, static) → main-area tiles in back-to-front window order → strip (thumbnails, mini tiles, label capsules) → selection ring and title capsule → empty-message capsule when shown.

**Which windows appear.**

| Window | Where | Contents |
|---|---|---|
| Docked or floating, on this display's current Space, on screen | Main area, at its real frame scaled | Snapshot (fresh capture or cached) or Phase 4 fallback tile |
| Collapsed or parked by the zoom camera (the display is not at the home view) | Main area, at its **home-view** tile rect scaled. A collapsed window draws as a Phase 4 collapsed block | Cached snapshot or collapsed block |
| On another Space of this display | Inside that Space's thumbnail, at its frame scaled to the thumbnail | Last snapshot taken this session, else app colour + icon (D-03). Never captured while its Space is hidden |
| The window of a full-screen Space | Fills that Space's thumbnail | Cached snapshot, else app colour + icon |
| Minimized, in a hidden app (⌘H), a hidden native tab, excluded from tracking, or Transom's own panels | Not shown | — |

The main area always shows the home-view layout: with the camera at home (the usual case) that is exactly the screen; when zoomed in, it shows where every window lives rather than 1pt parking slivers.

**Main-area geometry.** The area is the display's `visibleFrame` minus the strip band at the top, inset 24pt left, right and bottom. The home-view layout of the whole `visibleFrame` is scaled uniformly (aspect preserved) to fit that area and centred in it. With the strip hidden (Surface 2), the area is the `visibleFrame` inset 24pt on all four sides. Tile radius, icon and capsule rules are Phase 4's at the scaled size.

**Snapshots.**
- On open, with Screen Recording granted: one-shot captures of the on-screen windows of every display's current Space, concurrency 4, at the tile's main-area size × `backingScaleFactor` (Phase 4 capture rules). The overview opens when they return or after **120 ms**, whichever comes first; a late window uses its cached snapshot or a fallback tile, and a capture that lands while the overview is open crossfades in over **120 ms** (Phase 5 rule).
- So other Spaces have something to show: after each Space change settles (**1 s** with no further Space change), Transom captures the newly shown Space's visible windows once per visit, at main-area size, in the background. Only with zoom on and Screen Recording granted. Nothing on screen changes.
- Without Screen Recording: every tile is a fallback tile (Phase 4). If the Phase 4 explainer has never been shown, the first overview counts as "the first move" and the explainer shows once **after the overview closes** (Phase 4 Surface 2, never during it).

**Motion.** Every value is a Phase 4 constant.

| Step | Reduce Motion off | Reduce Motion on |
|---|---|---|
| Open | Captures (≤ 120 ms), then the stage orders in **instantly** with every tile exactly over its real window (invisible by design). Main-area tiles move and scale to their overview rects over **250 ms** `.easeOut`; tiles for parked windows slide in from the display edge (Phase 4 entering-tile rule); the strip fades in 0→1 over the same 250 ms (opacity only, it does not slide) | **250 ms crossfade** (`.easeInEaseOut`): the real-frame tile set fades 1→0 while the overview (main area and strip) fades 0→1 |
| Pick a window on the current Space, visible in the current view | Transom focuses and raises it as the reverse animation starts. Tiles return to their real frames over **250 ms** `.easeOut`, with the picked tile ordered on top (the post-focus window order). The strip fades out over the same 250 ms. The stage then fades out over **120 ms** once the focus has landed (cap 250 ms after the animation) | The stage fades out over **250 ms**: the real windows are already in place underneath |
| Pick a parked or collapsed window (display zoomed in) | The overview closes as above, then a Phase 4 camera move frames that window's leaf and focuses it at settle (Frame Focused Window semantics) | Phase 4 crossfade |
| Pick a window on another Space, or click a thumbnail | The stage fades out over **120 ms**, then Transom switches to that Space (macOS plays its own Space transition) and, for a window, focuses it | Same (opacity only) |
| Dismiss (Esc, Show Overview again, a click on the backdrop) | The reverse of Open: 250 ms `.easeOut` back to real frames, strip fades out, then the stage fades out over 120 ms. No AX write: the real windows never moved | The stage fades out over 250 ms |
| Interrupted (any Transom command, the status menu opening, a Space change by the user, a display change, sleep or lock, the frontmost app changing by ⌘Tab or the Dock) | The stage fades out over **120 ms** at once, no reverse animation. A Transom command then runs normally | Same |

**While open.** Windows that open or close update the overview: a new window's tile fades in over 120 ms at its scaled position; a closed window's tile fades out over 120 ms and, if it was selected, selection moves to the nearest remaining item (Surface 3 rule). Toasts stay readable (Phase 4: re-ordered front). Gestures are not armed (Phase 5 not-armed list gains "overview open"), so a pinch or scroll does nothing. Pick mode, rubber band and collapsed-block panels are ended or ordered out, as for a Phase 4 move. The overview sends no window command until a pick.

**Availability.**

| Condition | Result |
|---|---|
| Zoom off | Show Overview is not in the menu, its hotkey is disabled with the other zoom names (`KeyboardShortcuts.disable`), its URL is ignored and logged. The takeover is lifted (Surface 5) |
| Arranging paused (any reason) | **Allowed.** The overview moves no window; a pick only focuses and switches Space. A pick that would need a camera move (parked window) focuses without moving the camera |
| Accessibility not ready | Refused: beep + "Transom needs Accessibility access" (Phase 4 text) |
| Every display shows a full-screen Space | Refused: beep + "The overview isn't available in full screen". With the takeover on, the Mission Control key opens macOS Mission Control instead (Surface 5) |
| Some displays full screen, others not | Opens on the others only |
| Overview already open | Show Overview (any trigger) dismisses it |

**Empty main area.** A current Space with no shown windows draws the backdrop only, plus one centred capsule: **"No windows on this desktop"** (Body, `secondaryLabelColor`, Phase 4 capsule padding 8 / 4pt). The capsule is not selectable. Keyboard selection starts on the current Space's thumbnail, or on the next display that has a window when the strip is hidden.

## Surface 2 — The Spaces strip (OVER-01, D-12, D-15, D-16)

**When shown.** Only when the Spaces lookup (capability `Spaces`, `SLSCopyManagedDisplaySpaces`) works. Without it (capability off, symbols missing, `--disable-private=Spaces`) the strip is **hidden on every display** and the main area grows to the top (D-15). There is no placeholder, message or disabled strip: the Debug line says why (Surface 7).

**Layout.** A band across the top of the display's `visibleFrame` (below the menu bar), with no fill of its own. One thumbnail per Space of that display, in macOS's order, centred horizontally as a row, 16pt apart, with a label capsule centred 8pt below each thumbnail. Sizes are in Spacing Scale exceptions. A display with a single Space still shows its one thumbnail, so the strip's presence never depends on the Space count.

**"Displays have separate Spaces" off** (D-12, detected from SkyLight, never prompted). Spaces are shared across displays, so the strip is drawn **only on the main display** (the one that has the menu bar in that mode). Thumbnails show the main display's part of each Space. Other displays' panels have no strip and use the strip-hidden geometry. Desks stay keyed per display UUID; nothing else changes visibly.

**Thumbnail contents.** The current wallpaper of that display (macOS gives one wallpaper URL per screen, so every thumbnail of a display shows the same wallpaper), aspect-fill, 8pt radius. On top, the Space's windows as mini tiles at their frames scaled to the thumbnail, back to front. A Space with no windows shows wallpaper only (no message: the label is enough). A full-screen Space shows its window filling the thumbnail.

**Labels.**

| Space | Label |
|---|---|
| Desktop Space | "Desktop {n}", numbered 1… in strip order per display (per main display when Spaces are shared), matching Mission Control's numbering |
| Full-screen Space | The app's name (truncated, 32 + "…"); with two apps in one split full-screen Space, "{App 1} and {App 2}" |
| Current Space | Same text in Label Semibold, and the thumbnail gets the 2pt `labelColor` 85% border |
| A mini tile in this thumbnail is selected | The window title replaces the label (AX title; empty title → app name), Label Regular, middle-truncated to the thumbnail width |

**Interaction (read-only, D-16).**

| Pointer action | Result |
|---|---|
| Hover a thumbnail's background (not a mini tile) | Selects the thumbnail (outset accent ring) |
| Hover a mini tile | Selects that window (inset accent ring on the mini tile, title replaces the label) |
| Click a thumbnail's background | Switches to that Space and closes the overview (Surface 1 motion). Clicking the **current** Space's thumbnail dismisses the overview (there is nowhere to switch) |
| Click a mini tile | Switches to that Space, focuses the window, closes the overview |
| Drag a thumbnail or a mini tile | Nothing. A press that travels 4pt or more before release is not a click; no drag image, no reorder (D-16) |
| Right-click, ⌘-click, ⌥-click, double-click | Treated as a plain click (single action, never twice) |

**Switching Space** (method is Claude's discretion, decided in research: public API, SkyLight, or focusing a window on that Space). What the user sees is always macOS's own Space transition, with nothing drawn by Transom on top. If the Space has not changed within **1 s** of the request, Transom beeps, announces "Couldn't switch to Desktop {n}" (or the app's name for a full-screen Space) and logs it. No toast. The overview is already closed by then.

## Surface 3 — Selection and keyboard (D-04)

**One selection.** There is exactly one selected item across all displays: a main-area tile, a mini tile, or a thumbnail. Pointer and keyboard drive the same selection. Moving the pointer onto an item selects it; moving it over the backdrop, a gap or the empty-message capsule leaves the selection where it was (so a resting pointer never fights the keyboard). Selection rings fade in over **80 ms** and out over **120 ms** (Phase 4 hover-ring timing); under Reduce Motion they do the same (opacity).

**Initial selection** when the overview opens: the focused window if it is shown; else the main-area tile under the pointer; else the largest main-area tile on the pointer's display; else that display's current-Space thumbnail; else the first display (left to right) with a main-area tile.

**Keys while the overview is open.** Heard through temporary Carbon hotkeys registered only while the overview is open, exactly like Phase 4's pick-mode Esc, so the keys never reach the app behind and the event tap mask stays mouse-only (T-03-28). Unregistered the moment the overview closes. Not rebindable; not in the Shortcuts window.

| Key | Action |
|---|---|
| ← → ↑ ↓ | Move the selection to the nearest item in that direction **on the same display**: main-area tiles by their scaled centres (the Phase 3 Focus-direction rule: nearest centre within a 45° cone, then any item on that side); ↑ from the top row of the main area goes to the strip (the thumbnail nearest in x); ↓ from the strip goes back to the main-area tile nearest in x; ← → in the strip move between thumbnails. Mini tiles are pointer-only. At an edge with nothing beyond: no move, no beep (repeat-safe) |
| Tab / ⇧Tab | Move the selection to the next / previous display, left to right by display frame, wrapping. It lands on that display's initial item (rule above, applied to that display) |
| Return (and keypad Enter) | Pick the selected item: a tile → go to the window; a mini tile → switch Space and focus; a thumbnail → switch to that Space (current Space: dismiss) |
| Esc | Dismiss |
| The Show Overview hotkey, or F3 / ⌃↑ with the takeover on | Dismiss |
| Any other key | Not heard by Transom; reaches the frontmost app as usual. The overview stays open |

**Selected-window title capsule.** A selected **snapshot** tile in the main area shows a title capsule centred horizontally, 8pt above the tile's bottom edge, inside the tile (Body, middle-truncated, max width tile width − 32pt). If the tile is shorter than the capsule + 16pt, the capsule sits 8pt below the tile instead, clamped inside the main area. A selected **fallback** tile shows no extra capsule: it already has its own (no duplicated controls). AX titles only, never `kCGWindowName`; an empty title shows the app name.

**Cursor.** `NSCursor.pointingHand` over tiles, mini tiles and thumbnails; the system arrow elsewhere.

## Surface 4 — Show Overview: hotkey, menu, URL, Shortcuts row (D-01)

| Command | Menu title (location) | Default | `Name` | `Command` case | URL |
|---|---|---|---|---|---|
| Show or dismiss the overview | Zoom ▸ Show Overview | **⌃⌥⌘A** | `showOverview` | `.camera(.overview)` | `transom://overview` |

- **Why ⌃⌥⌘A** (Claude's discretion). The free ⌃⌥⌘ letters after Phase 4 are A, L, Q, T, V, W, Y. A reads as "all windows, all displays", sits under the left hand next to S (Swap) and D (Dock), and leaves V and W for Phase 8's saved views. ⌃⌥⌘O keeps its Phase 4 meaning (D-01).
- **System-shortcut check (2026-10-31, macOS 27.2).** `com.apple.symbolichotkeys` on the dev machine has no entry using ⌃⌥⌘ at all, so ⌃⌥⌘A collides with no macOS default. The launch-time `isTakenBySystem` log (Phase 4) covers user changes.
- The `Name` raw value `showOverview` is a persistent contract (Pitfall 13): never rename it. It joins `Hotkeys.zoomNames` through the `.camera` case, so zoom off disables it with the others.
- **URL.** Joins `TransomURL.commands` under the Phase 3/4 whitelist and the once-per-second rate limit. It toggles, like the hotkey. While zoom is off, or when it can't act, it does nothing and logs (no beep).
- **VoiceOver fallback** (Phase 3/4): A is a letter chord, so it is disabled with the other letter chords while that fallback is active.

**Menu (Zoom section, zoom on).** One new item and one new toggle. Every other Phase 4 row is unchanged.

| # | Item | Type | Shortcut | Placement and behaviour |
|---|------|------|----------|-------------------------|
| O1 | "Show Overview" | item | ⌃⌥⌘A (`setShortcut(for: .showOverview)`) | First item after the "Zoom" header, before "Zoom Out to All Windows". Disabled while Accessibility is not ready. **Enabled while paused** (Surface 1 Availability). Choosing it closes the menu and opens the overview on every display |
| O2 | "Replace Mission Control" | toggle (checkmark) | none | After "Frame Desktop", before "Allow Window Previews…". `state = .on` while the takeover is active. Surface 5 |

With **zoom off** the section is unchanged from Phase 4: only "Zoom" and "Turn On Zoom". O1 and O2 are not rendered.

**Shortcuts window.** One new row, **first in the Zoom section**: `KeyboardShortcuts.Recorder("Show Overview", name: .showOverview)`. That makes 45 recorder rows. The Zoom section gains a footer (Label role, `.foregroundStyle(.secondary)`): **"With Replace Mission Control on, the Mission Control keys also show the overview."** The Mission Control keys themselves are not recorder rows: they are macOS's, and Transom only borrows them. Restore Defaults also resets `showOverview`.

## Surface 5 — Replace Mission Control (OVER-02, OVER-03, D-05..D-08)

**What it does.** With the takeover on, Transom turns off macOS's Mission Control keyboard shortcuts and handles those keys itself, so they open (or dismiss) the overview. Off by default (D-06). ⌃←/→ Space switching and ⌃↓ (application windows) are never touched (D-08).

**Which triggers** (D-05). The Mission Control key (F3 on Apple keyboards) and the keyboard shortcut macOS has for Mission Control (default ⌃↑, or whatever the user set in Keyboard Shortcuts ▸ Mission Control). The **four-finger swipe up is spike-gated**: it is taken only if the VM spike and the user's host check prove it can be consumed safely. Every string below has two variants, **[swipe kept]** (default, used unless the spike passes) and **[swipe taken]**. The executor ships exactly one, chosen from the spike verdict.

**Turning it on (menu O2).**

| Situation | Behaviour |
|---|---|
| First time ever (explanation never confirmed) | Choosing O2 shows the **explanation alert** (below). The toggle turns on only if the user confirms |
| Explanation confirmed before | Choosing O2 turns the takeover on at once, no alert |
| After a crash turned it off (canary) | Choosing O2 turns it on at once (the user has seen the alert) and clears the canary for this build |
| Private symbols missing or `--disable-private` | O2 reads **"Replace Mission Control (unavailable)"**, disabled. Debug says why |
| Applying fails (read-back still shows the macOS shortcut on) | Transom restores the stored originals, the toggle stays off, toast **N11** shows, log line |

**Explanation alert.** Phase 3 conflict-alert style: modeless `NSAlert`, `alertStyle = .informational` (app icon), shown after `NSApp.activate()`, never during a drag (deferred until mouse-up) and never while the overview is open. Tracking, hotkeys and zoom keep working while it is up. Buttons: **"Replace Mission Control"** (first, default, Return) and **"Not Now"** (Esc; closing the alert is the same). The "confirmed" flag is saved only on confirm, so the alert shows again if the user chose Not Now and later chooses O2.

| Field | Copy |
|---|---|
| `messageText` | "Use the Mission Control keys for Transom's overview?" |
| `informativeText` [swipe kept] | "{Keys} will show Transom's overview instead of Mission Control. Swiping up with four fingers still opens Mission Control. Transom gives Mission Control its keys back when you turn this off or quit, and the next time it opens if it quits unexpectedly." |
| `informativeText` [swipe taken] | "{Keys} and swiping up with four fingers will show Transom's overview instead of Mission Control. Transom gives Mission Control its keys and swipe back when you turn this off or quit, and the next time it opens if it quits unexpectedly." |

`{Keys}` branches on what macOS has for Mission Control when the alert opens:
- default shortcut: "The Mission Control key (F3) and Control-Up Arrow"
- a custom shortcut: "The Mission Control key (F3) and {chord}", the chord in glyph form as in toast N4 (for example "⌥⌘↑")
- the shortcut turned off by the user: "The Mission Control key (F3)"

**While on.**

| Trigger | Result |
|---|---|
| F3 / the Mission Control shortcut [/ four-finger swipe up], overview closed, overview can open | Opens the overview (Surface 1) |
| Same, overview open | Dismisses it |
| Same, overview can't open (every display full screen, Accessibility not ready) | Transom asks the Dock to open **macOS Mission Control** instead (`CoreDockSendNotification`, isolated in `TransomPrivate` with its own capability), so the key always does something. If that symbol is missing too: beep + the Surface 1 refusal announcement |
| Zoom turned off | The takeover is **lifted** (originals restored) while zoom is off and re-applied silently when zoom is turned on again. O2 keeps its saved preference |
| "Restore macOS Window Settings" (Phase 3 item 22) | Also turns the takeover off and restores the originals. The item is enabled while the takeover is on. Then toast N8, unchanged |
| Turning O2 off | Originals restored at once. No alert, no toast |
| Quit | Originals restored before exit (with the Phase 3 quit restore) |

**Crash safety (OVER-03, D-07).** Before the first disable, Transom stores the original symbolic-hotkey state in UserDefaults. At every launch, if stored originals exist and the last run did not end cleanly, they are restored before anything else, whether or not the takeover will be re-applied. A crash while the takeover was on arms the takeover canary (the Phase 5 `MultitouchCanary` pattern, per OS build + app version): the takeover stays **off** for that build until the user chooses O2 again, and toast **N10** explains this once. A clean quit never shows N10.

**Never shown.** No prompt to turn the takeover on (no nag, no onboarding in this phase). No status-glyph change while it is on. The Mission Control keys are never consumed while the takeover is off.

## Surface 6 — Displays and Spaces changes the user can see (OVER-04..06, D-09..D-14)

Almost everything here is silent by design: the layout simply stays right. The table lists every visible consequence.

| Event | What the user sees | Notice |
|---|---|---|
| Switching Space (⌃←/→, swipe, Mission Control, the strip) | That Space's windows in their tiles, as left. A desk that changed while hidden is re-planned when shown (D-14); its windows may move once, right after macOS's transition | none |
| Display unplugged (or the lid closed into clamshell) | After the **1.5 s** debounce (D-11), the vanished display's desks become dormant. Its windows float on a remaining display (the main display, else the nearest), at their own size, cascaded from the top-left of that display's Desktop tile, clamped on screen. If the new arrangement has a remembered layout set (OVER-06), its windows go to their tiles in that set instead and nothing floats | **N12**, only when at least one window floated |
| Display re-plugged | After the debounce, its desks wake and its windows return to their tiles, matched by display UUID | none (the windows moving home is the feedback). Log line |
| Arrangement changed to one seen before (dock / undock) | That arrangement's layout set is applied: every display's windows go to their remembered tiles | none. Log + Debug |
| Arrangement never seen before | Current layouts carry over to the displays that remain; a new display starts with an empty desk (Phase 3 behaviour) | none. Log + Debug |
| Display rearranged or resolution changed, same set of displays | Same arrangement (D-09: positions and resolution ignored). Tiles re-plan to the new frames | none |
| Reconfiguration during sleep or lock | Nothing is acted on until wake/unlock plus the debounce (D-11, SessionGate) | Any N12 shows after wake |
| "Displays have separate Spaces" turned on or off (needs a logout in macOS) | Detected at launch; handled silently (D-12). Strip placement per Surface 2 | none |
| Overview open during any of the above | The overview is interrupted (Surface 1: 120 ms fade) before anything moves | — |

**Floating on unplug (D-10) — copy N12.** Glyph `display`, `secondaryLabelColor` (not a warning). Shown on the display that received the windows. `{Display}` is `NSScreen.localizedName` captured before the display left, in curly quotes, truncated to 32 characters + "…".

| Case | Copy |
|---|---|
| One display, 1 window | "“{Display}” was disconnected, so 1 window from it is floating here until you reconnect it." |
| One display, n windows | "“{Display}” was disconnected, so {n} windows from it are floating here until you reconnect it." |
| Several displays at once | "{d} displays were disconnected, so {n} windows from them are floating here until you reconnect them." ({n} = 1 uses "1 window … is floating") |

N12 joins the Phase 3 `NoticeQueue` as a normal notice (not a crash notice). Two N12s within the toast's lifetime merge into the several-displays form. Floated windows are ordinary floaters: the user may dock them; a window the user docked elsewhere while its display was away stays where the user put it on re-plug (user action wins, Phase 3 wanted-frame rule).

Show Overview itself is in the menu, rebindable, and has a URL.

**Reduce Motion.** Surface 1 Motion table: open and close crossfade (250 ms), dismiss and pick fade the stage (250 ms), all opacity fades stay. Nothing slides or scales. Observed live (Phase 4).

### User hardware checklist (multi-display; the Tart VM can't hot-plug displays)

Wording is fixed so the agent can paste it into `06-UAT.md`. Each item says what to do and what should happen; answer **"pass"** or what you saw instead. Use the MacBook Air plus the DELL.
