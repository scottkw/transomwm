# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 8 adds saved views, view URLs, the `transom` command-line tool and re-matching after relaunches and reboots (VIEW-01..05). It **extends** `03-UI-SPEC.md`, `04-UI-SPEC.md`, `06-UI-SPEC.md` and `07-UI-SPEC.md` and keeps every token, timing, panel property, colour recipe, copy rule, Debug-line style and announcement pattern from them. Where this spec says "Phase 3 Surface N" or "Phase 4 Surface N", that surface applies unchanged.

Phase 8 adds five surfaces:

1. **saved views**: going to and saving views 1–9, the brief view toasts and their announcements (VIEW-01, VIEW-02, D-01..D-05, D-15..D-17)
2. **placeholder tiles**: a dim app-colour tile with "Waiting for {App}…" for a window that hasn't been re-matched yet (VIEW-04, D-10..D-13)
3. **hotkeys and Shortcuts rows**: ⌥1–9 / ⇧⌥1–9 with the ⌃⌥ fallback, a new "Saved Views" section in the Shortcuts window (D-01, D-17)
4. **URLs**: `transom://view/<1-9>` and `transom://save-view/<1-9>` under the existing allow-list and rate limit (VIEW-03, D-06)
5. the **`transom` command-line tool**: help text, error messages and exit codes (VIEW-05, D-07..D-09), plus the README lines, Debug lines and log lines for all of the above

Not in this phase: menu items for views (views are reached by hotkey, URL and CLI, and the Shortcuts window lists the hotkeys), a clear-slot command (D-16), an "Install Command-Line Tool…" button and the Settings window (Phase 9), a keyboard, URL or CLI way to form a tab group (deferred, needs a backlog entry), dropping a window onto a placeholder to fill it, and multi-display work beyond Phase 6.

**Platform rule (unchanged).** Native macOS only. Shell = AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`). Overlays = layer-backed AppKit views drawn with Core Animation. SwiftUI only inside `NSHostingController` / `NSHostingView` (the Shortcuts window and the existing toast content). Every colour is a semantic system colour except the Phase 4 app colour. Every font is a system text style. The CLI writes plain text to a terminal and has no visual design beyond the copy below.

**Phase 2–7 review rules still apply:** no `.font(.system(size:))` for glyphs, no padding stacked on a system inset, no duplicated controls within one surface, no per-row AppKit lookups when the menu rebuilds. App names, icons and app colours come from the per-pid cache, or for an app that isn't running, from its bundle (Surface 2).

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom. TrellisWM's saved-view copy, placeholder visuals and CLI wording are not used.

**Spelling.** UI strings use US English. Planning prose may stay British.

**Vocabulary added by this spec.**
- **View** (UI copy) / **saved view** (this spec): a camera view stored in a slot 1–9. It holds its display, its Space and the windows inside the zoomed area, or "home" for a whole-desk view (D-02).
- **Slot**: one of the nine places a view can be saved. Slots are numbered 1–9 in copy, never 0-based.
- **Placeholder**: a tile whose window has not come back yet after a relaunch, reboot or app quit. It is drawn as a placeholder tile until the window is re-matched or the placeholder expires (D-12, D-13).
- **Re-match**: giving a returning window, with a new window ID, its old tile from persisted hints (D-10). Never shown as a word in UI copy.

## Spacing Scale

All values are in points. The token scale is unchanged: 4 / 8 / 16 / 24 / 32 / 48 / 64.

| Token | Value | Phase 8 usage |
|-------|-------|---------------|
| xs | 4pt | Vertical padding of the placeholder's text capsule (Phase 4 fallback-tile capsule) |
| sm | 8pt | Gap between the placeholder's icon and its capsule; horizontal padding of the capsule; gap between the toast glyph and text (Phase 3, unchanged); toast vertical padding (Phase 3, unchanged) |
| md | 16pt | Minimum clearance around the placeholder's icon and capsule on each side (Phase 4 fallback-tile rule); toast horizontal padding and its offset below the top of the visible frame (Phase 3, unchanged) |
| lg–3xl | 24 / 32 / 48 / 64pt | 64pt only as the placeholder icon's maximum size (a size, see Exceptions). Not used as spacing |

Exceptions (non-spacing metrics, listed so the checker and auditor can find them):
- **Placeholder rect** = exactly the tile rect the absent window would get from the plan (gaps already applied). No extra inset.
- **Placeholder icon**: `min(64, shorter side − 32)`, hidden below 16pt (Phase 4 fallback-tile sizes).
- **Placeholder capsule**: shown only when the tile is at least icon + 8 + capsule height + 32pt tall and capsule width + 32pt wide; max width tile width − 32pt (Phase 4 rule).
- **Corner radius**: placeholder 12pt (Phase 3/4 tile token); capsule radius = height / 2.
- **Stroke**: placeholder border 1pt, dashed 8pt on / 4pt off (the Phase 3 clamp-ghost dash pattern). Capsule border 1pt solid `separatorColor` (Phase 4).
- **Toast**: max text width 360pt, up to 3 lines, 12pt radius (Phase 3, unchanged). Never overridden.
- **System metrics**: Shortcuts window, `Recorder` and menu metrics are system-drawn or Phase 4's. Never override them.

## Color

Semantic system colours only, no hex literals in code. Hex values are references resolved on macOS 27 with the default appearance. The Phase 3 appearance rule applies to the placeholder: `CGColor`s re-resolved inside `effectiveAppearance.performAsCurrentDrawingAppearance { … }` (or `updateLayer`) on appearance change, on `NSColor.systemColorsDidChangeNotification` and on `accessibilityDisplayOptionsDidChangeNotification`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | The user's windows and wallpaper | Transom adds no opaque surface in Phase 8. A placeholder replaces only bare wallpaper inside an empty tile |
| Secondary (30%) | Phase 3 toast material (`.hudWindow`) with `labelColor` text and `secondaryLabelColor` glyph; **app colour** (Phase 4) at 40% for the placeholder fill; `labelColor` 50% for its dashed border; `windowBackgroundColor` capsule with a 1pt `separatorColor` border and `secondaryLabelColor` text | Quiet, neutral feedback; the placeholder reads as "something belongs here" without looking like a live window |
| Accent (10%) | `NSColor.controlAccentColor` (ref default `#0088FF` light, `#0091FF` dark) | Only the elements listed below |
| Destructive / refusal | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | Not used by Phase 8. Phase 8 has no destructive action: saving over a slot replaces it with no confirmation (D-15), placeholder expiry is the normal close path |
| Warning | `NSColor.systemOrange` | Not used by Phase 8 (stays N7 / N11 only) |

Accent reserved for exactly these elements (the Phase 3, 4, 6 and 7 list, unchanged):
1. Phase 3, 4, 6 and 7 uses (drop preview, swap origin, gap handles, rect-zoom target preview, pick-mode ring, collapsed-block hover ring, overview selection ring, Group drop preview, system-drawn uses)
2. Nothing new. The accent is **not** used in the view toasts, the placeholder, the Saved Views Shortcuts section (except the `Recorder`'s own recording state, system-drawn) or anywhere in CLI output

**Overlay colour recipe (new rows).** Alpha is applied to the colour.

| Element | Fill | Border | Content |
|---|---|---|---|
| Placeholder | app colour 40%, 12pt radius | `labelColor` 50%, 1pt, dashed 8/4, inside | app icon 100%, centred, then the capsule 8pt below |
| Placeholder capsule | `windowBackgroundColor` 100%, capsule | `separatorColor` 1pt | "Waiting for {App}…", `secondaryLabelColor`, Body |
| View toasts N13–N19 | Phase 3 toast (`.hudWindow`, 12pt radius) | none | glyph `secondaryLabelColor`, text `labelColor`, Body |

The placeholder's app colour is `AppColor.color(forBundleID:icon:)` with the icon from the bundle (Surface 2); with no icon it is `systemGray` (existing fallback). The dim fill plus dashed border tells a placeholder apart from the Phase 4 fallback tile (100% fill, solid border).

**Increase Contrast**: Phase 3 rule. Placeholder fill 40% → 60%, border `labelColor` 100%, capsule text `labelColor`. `separatorColor` and `windowBackgroundColor` adapt by themselves. **Differentiate Without Color**: a placeholder differs from a live tile by its dashed border and its text, not only by its dimmer fill. **Reduce Transparency**: the placeholder fill is a tint, not a material (Phase 4 rule: tints stay); the toast's `.hudWindow` material follows the system's own Reduce Transparency handling (Phase 3, unchanged).

## Surface 1 — Saved views (VIEW-01, VIEW-02, D-01..D-05, D-15..D-17)

### Saving a view

**Trigger.** ⇧⌥{n} (Surface 3), `transom://save-view/{n}` or `transom save-view {n}`. Saving acts on the display under the pointer (Phase 4 rule for camera commands).

**What is stored** (D-02): that display, its current Space, and the identities of the windows inside the current view, or "home" when the display is at home. If a camera move is in progress, the move's **target** view is saved (Phase 4: toggles compare against the pending target). If the overview is open, it closes (Phase 6 "interrupted: command") and the camera view under it is saved.

| Situation | Result | Toast (brief) | Beep |
|---|---|---|---|
| Slot empty | Saved | N13 "Saved view {n}" | no |
| Slot already used | Replaced, no confirmation (D-15) | N14 "Replaced view {n}" | no |
| View holds no windows (the Desktop framed with nothing floating on it) | Refused, slot unchanged | N19 "There are no windows in this view to save." | hotkey only |
| Zoom off | Hotkey unregistered, so the chord reaches the app (D-17). URL: ignored, logged. CLI: refused "Zoom is off" | none | no |
| Paused / Accessibility not ready / full-screen Space | Refused (Phase 4 zoom-command refusals) | none; announcement "Arranging is paused" / "Transom needs Accessibility access" / "Zoom isn't available in full screen" | hotkey only |

Saving never moves the camera or any window, and is not an undo step. The views are written to layout.json with the next debounced save (Phase 3: 0.5 s).

### Going to a view

**Trigger.** ⌥{n}, `transom://view/{n}` or `transom view {n}`.

**Where it goes.** The engine finds the saved windows that still exist. The **desk holding most of them** is the target desk (ties: the saved desk). On that desk the camera zooms to the smallest node that holds those windows, or home for a home view (D-02).

| Step | Situation | What the user sees |
|---|---|---|
| 1 | Target desk on the Space already shown | Nothing yet |
| 1 | Target desk on another Space (same or other display) | macOS's own Space transition, through the Phase 6 Space-switch path (D-03). Nothing drawn by Transom on top. If the Space hasn't changed within **1 s**: refused, beep (hotkey only) + "Couldn't switch to Desktop {n}" (Phase 6), camera unchanged |
| 1 | Target desk on another display, Space shown | No switch needed; the camera moves on that display. The pointer does not move |
| 2 | Camera not already at the target | The Phase 4 camera move (capture, stage, 250 ms ease-out, settle, reveal), exactly as for any camera command. Reduce Motion: Phase 4 crossfade |
| 2 | Camera already at the target | Nothing moves (not a refusal) |
| 3 | After settle | If the focused window is not inside the view, the most recently focused window inside it is focused (Phase 3 focus path), so a view on another display or Space is ready for typing. Otherwise focus stays |

Toast N15 "View {n}" shows on the target display when the move starts (or at once when nothing moves). Going to a view is a camera move, so it joins Back / Forward history like any other (Phase 4) and is never an undo step.

**Edge cases.**

| Situation | Result | Toast | Beep |
|---|---|---|---|
| Slot empty | Nothing happens | N16 "No view in slot {n}" (brief) | hotkey only (D-04) |
| Every saved window has gone (D-05) | The saved desk's home view (Space switch first if needed). The slot stays saved | N17 "The windows in view {n} have closed. Showing all windows." (normal, 6 s) instead of N15 | no |
| Some saved windows have gone | The smallest node holding the rest (D-02). No notice | N15 | no |
| Every saved window has gone and the saved display isn't connected | Nothing happens. The slot stays saved | N18 "View {n} is on a display that isn't connected." (brief) | hotkey only |
| Every saved window has gone and the saved Space no longer exists | That display's current Space, home view | N17 | no |
| Zoom off | Hotkey unregistered (D-17). URL ignored, logged. CLI refused "Zoom is off" | none | no |
| Paused / not ready | Refused (Phase 4) | none; Phase 4 announcement | hotkey only |
| Overview open | The overview closes (Phase 6 "interrupted: command"), then step 1 | as above | |
| Pressed again during the move (same or other slot) | Phase 4 retargeting from the stage's current state | the newer toast replaces the older | no |

### View toasts

The Phase 3 toast panel and queue (Surface 4) with one addition: a **brief** class.

| Property | Brief (N13, N14, N15, N16, N18, N19) | Normal (N17) |
|---|---|---|
| Visible for | **1.5 s** after the fade-in | 6 s (Phase 3) |
| Fades | in 160 ms, out 240 ms, opacity only, same under Reduce Motion (Phase 3) | same |
| Replaces | any visible non-crash toast at once; a newer brief toast replaces an older one and restarts the 1.5 s | Phase 3 rules |
| Behind a crash notice (N2/N3) | **dropped, never queued** (it would be stale); its announcement is still posted | queued (Phase 3) |
| Merging | never merged; the newer one wins | never merged |
| Display | the target display (going), the pointer display (saving, empty slot), else the menu-bar display (Phase 3) | the target display |

Toasts are shown for every route (hotkey, URL, CLI): they confirm that something happened even when the user isn't looking at the terminal or launcher. Refusals for URL routes show nothing (Phase 3 rule); CLI refusals print instead (Surface 5).

| ID | When | Glyph | Copy |
|---|---|---|---|
| N13 | View saved into an empty slot | `bookmark` | "Saved view {n}" |
| N14 | View saved into a used slot | `bookmark` | "Replaced view {n}" |
| N15 | Going to a view | `viewfinder` | "View {n}" |
| N16 | Going to an empty slot (hotkey, or a URL or CLI request that the slot check refuses: URL shows nothing, CLI prints) | `viewfinder` | "No view in slot {n}" |
| N17 | Going to a view whose windows have all closed | `info.circle` | "The windows in view {n} have closed. Showing all windows." |
| N18 | Going to a view on a display that isn't connected | `display` | "View {n} is on a display that isn't connected." |
| N19 | Saving a view with no windows in it | `info.circle` | "There are no windows in this view to save." |

`{n}` is the digit 1–9. N13–N16 are short labels with no full stop (D-04 copy, like the Phase 4 announcements "Zoom canceled"); N17–N19 are sentences and end with one (Phase 3 toast style).

## Surface 2 — Placeholder tiles (VIEW-04, D-10..D-13)

### When a placeholder appears

| Path | Which tiles |
|---|---|
| **Transom launch** (restore, reboot or not) | After the first complete inventory, `LayoutRestore` re-attaches by identity, then runs the hint matcher (D-10). Every **docked** saved window still not attached becomes a placeholder |
| **App quits while Transom runs** | Each of that app's docked windows becomes a placeholder instead of closing its tile, so the app's relaunch can re-match them (D-11). See Notes for the planner |
| **Match tie** (D-10) | The tile becomes a placeholder; the tied windows float on the Desktop (Phase 3 new-window float). No toast; log line |

Not a placeholder: a window on a Space not shown at launch (it stays dormant, as today), a window closed with ⌘W while its app keeps running (normal close), a floating saved window (nothing is reserved, so it is simply dropped at the same expiry), a hidden member of a tab group (no tab is drawn for it while it waits; if matched before expiry it rejoins as a hidden tab in its saved position, else it is dropped silently, Phase 7 relaunch rule). A tab group whose members are **all** waiting shows one placeholder for its selected member's app.

### How it looks (D-13)

A **sibling view**, not `CollapsedBlockView` itself (that view has a hover ring, pointing hand and double-click, which a click-through placeholder must not have). It shares `AppColor`, the Phase 4 fallback-tile layout and `TileLayer` constants.

| Part | Drawing |
|---|---|
| Body | Exactly the tile rect. App colour 40% fill, 12pt radius, 1pt `labelColor` 50% dashed (8/4) border |
| Icon | The app icon, centred (as one group with the capsule), `min(64, shorter side − 32)`, hidden below 16pt |
| Capsule | 8pt below the icon, Phase 4 clearance rule: "Waiting for {App}…" in `secondaryLabelColor`, Body, one line, middle-truncated |
| Names and icons | Running app: the per-pid cache. App not running: `NSWorkspace.shared.urlForApplication(withBundleIdentifier:)` → `FileManager.default.displayName(atPath:)` and `NSWorkspace.shared.icon(forFile:)`. App not installed: "Waiting for a window…", the generic app icon (`NSWorkspace.shared.icon(for: .applicationBundle)`) and `systemGray` |

### Panel

One `NSPanel` per placeholder, from a recycled pool (the `CollapsedPanels` pattern).

| Property | Value | Why |
|---|---|---|
| `styleMask` | `[.borderless, .nonactivatingPanel]` | Never activates Transom |
| `canBecomeKey` / `canBecomeMain` | `false` (subclass override) | Never takes keys |
| `ignoresMouseEvents` | `true` | Clicks pass through to the Desktop beneath (D-13) |
| `level` | `.normal`, ordered to the back of that level (`orderBack`) | Any real window, including the awaited window appearing at its own position before it is matched, shows above the placeholder |
| `collectionBehavior` | `[.stationary, .ignoresCycle]`, **no** `.canJoinAllSpaces` | It belongs to its desk's Space, like the tab strip |
| Space changes | Ordered out when its desk's Space is hidden, re-shown when it returns, replaced through `NSWindow.leftOnAnotherSpace(_:)` if macOS stranded it (Phase 7 rule) | |
| `sharingType` | `.none` | Kept out of Transom's own snapshots (the stage draws placeholders itself) |
| `isOpaque` / `backgroundColor` / `hasShadow` / `animationBehavior` | `false` / `.clear` / `false` / `.none` | The layer draws the tile |
| Camera | Shown only where its tile is on screen in the current view. Ordered out when a camera move starts; fades back in at reveal with the collapsed-block panels (Phase 4, 120 ms). On the stage and in the overview the placeholder is drawn with the same recipe, scaled; in the overview it is not selectable and not counted in "Overview, {n} windows" |

### Lifecycle

| Event | What the user sees | Announcement |
|---|---|---|
| Placeholder created | Fades in over **120 ms** | none (it is background state; Debug line counts it) |
| A window is matched to it | The window is moved into the tile (Phase 3 write); the placeholder fades out over 120 ms once the frame write is sent. Not an undo step | none (the window arriving is the feedback) |
| **Expiry** (D-12): 10 s after its app launched without a match, or 5 min after Transom launched with no launch (launch path), or 30 s after the app quit with no relaunch (app-quit path, user decision 2026-11-03) | Fades out over 120 ms, then the tile closes through the normal close path and its neighbours reflow (Phase 3). Not an undo step | none; log line |
| While paused | Stays visible; expiry still runs (it is not a window command). A match is recorded and the window goes to its tile at Resume (Phase 3 Resume rule) | |
| Restore All Windows, Arrange All, Undo | Unaffected: a placeholder holds its tile like a window. Arrange All docks other windows around it | |
| Quit Transom | Panels disappear. Waiting windows stay in layout.json for the next launch | |
| Drag over its tile | Its edge bands take Dock drops beside it like any tile. Its centre is not a group target (there is no window to group with): Phase 3 miss rules | |

## Surface 3 — Hotkeys and Shortcuts rows (D-01, D-17)

**Defaults.** Bound by key position (KeyboardShortcuts registers by key code), so the physical digit-row keys work on any layout; the Shortcuts window and README show the current layout's character.

| Command | Default | Fallback (macOS 15.0–15.1) | `Name` | `Command` case | URL |
|---|---|---|---|---|---|
| Go to view 1–9 | **⌥1 … ⌥9** | ⌃⌥1 … ⌃⌥9 | `view1` … `view9` | `.camera(.view(1…9))` | `transom://view/1` … `/9` |
| Save view 1–9 | **⇧⌥1 … ⇧⌥9** | ⇧⌃⌥1 … ⇧⌃⌥9 | `saveView1` … `saveView9` | `.camera(.saveView(1…9))` | `transom://save-view/1` … `/9` |

- **Fallback rule.** On macOS 15.0 and 15.1 the `initial` shortcut of all 18 names is the ⌃⌥ form, decided once at launch by OS version. Evidence: KeyboardShortcuts 3.1.0 keeps its registration-failure callback internal (`HotKey.onRegistrationFailed`) and its own `isDisallowed` check treats the 15.0–15.1 refusal as sandbox-only, while STATE.md records conflicting sources; a version check is deterministic, testable headless and matches D-01. A shortcut the user set always wins. Restore Defaults resets to the version's default.
- `Name` raw values `view1`…`view9`, `saveView1`…`saveView9` are a persistent contract (Pitfall 13): never rename them.
- They are **zoom names** (camera commands), so `Hotkeys.zoomNames` disables them while zoom is off and the chords reach apps (D-17). Saved views are kept.
- **System-shortcut check (2026-11-03, macOS 27.2).** `com.apple.symbolichotkeys` on the dev machine has no entry for a digit key with the ⌥, ⇧⌥, ⌃⌥ or ⇧⌃⌥ masks. No collision with ⌃⌥⌘1–3 (snap thirds) or ⌃1–9 (macOS Switch to Desktop). The launch-time `isTakenBySystem` log (Phase 4) covers these names automatically as zoom names.
- **Known overlaps (informational).** ⌥ with a digit types characters on many layouts: on US English ¡ ™ £ ¢ ∞ § ¶ • ª, on German `[ ] | { }` for ⌥5–9 (Pitfall 16). While Transom holds a chord, that character can't be typed. The fix is to rebind in the Shortcuts window (footer below) or turn zoom off. The ⌃⌥ fallback uses VoiceOver's modifier and may shadow VO commands while VoiceOver runs; the same fix applies.
- **Refusals** follow Surface 1 (beep for hotkeys only, nothing for URLs, always a log line).

**Shortcuts window.** A new **"Saved Views"** section directly after "Zoom", 18 rows, go rows first:

| Rows | Titles |
|---|---|
| `Recorder` × 9 | "Go to View 1" … "Go to View 9" |
| `Recorder` × 9 | "Save View 1" … "Save View 9" |
| Footer (`.subheadline`, secondary) | "Saved views work while zoom is on. If ⌥ with a number types a character you need, choose another shortcut here." |

That makes **66** recorder rows. Restore Defaults also resets the 18 names. Duplicate checks use the Phase 4 `.shortcutValidation` text. Titles come from `ZoomCopy.shortcutTitle(_:)` (new cases) so the Recorder title and the help stay in one place.

**Menu.** No menu items in Phase 8 (Scope). The status menu is unchanged except the Debug submenu (Surface 5).

## Surface 4 — URLs (VIEW-03, D-06)

| URL | Command | Same as |
|---|---|---|
| `transom://view/{n}`, n = 1–9 | Go to view n | ⌥{n} |
| `transom://save-view/{n}`, n = 1–9 | Save view n | ⇧⌥{n} |

**Allow-list (strict, extends Phase 3/4).** Exact scheme (`transom`, or `transom-debug` in a Debug build), lowercase host, no user, password, port, query or fragment. A path is accepted **only** for `view` and `save-view` and **only** as exactly `/` followed by one digit `1`–`9`. Everything else is rejected with no side effects, logged without its contents, no UI: `transom://view`, `transom://view/`, `transom://view/0`, `/10`, `/3/`, `/03`, `/%33`, `/a`, `transom://zoom-out/3`, `transom://VIEW/3`.

**Rate limit.** Once per second per command; each slot is its own command (`view/3` and `view/4` don't limit each other; `view/3` and `save-view/3` don't either). CLI requests share the same limiter (D-07).

**Feedback.** A URL that acts shows its toast (Surface 1). A URL that is refused or can't act does nothing and logs, no beep, no toast, no announcement (Phase 3 rule). The full URL list after Phase 8 is 20 commands: the 18 existing ones plus these two.

## Surface 5 — The `transom` command-line tool (VIEW-05, D-07..D-09)

**Location.** Inside the app bundle at `Transom.app/Contents/Helpers/transom` (see Notes for the planner: `Contents/MacOS/transom` would collide with the `Transom` app binary on a case-insensitive volume). Installed by the README one-liner (below). No install UI (D-09).

**Shape** (Claude's discretion beyond D-09).

| Invocation | Meaning |
|---|---|
| `transom <command>` | Run a parameterless command, for example `transom zoom-out` |
| `transom view 3` · `transom view/3` | Go to view 3 (both forms) |
| `transom save-view 3` · `transom save-view/3` | Save view 3 |
| `transom help` · `transom -h` · `transom --help` · `transom` (no arguments) | Print the help text to stdout, exit 0 |

Before sending, the CLI builds `transom://<command>[/<n>]` and checks it with the same `TransomURL` parser from TransomEngine (D-07). Commands and arguments are case-sensitive and lowercase, like the URLs. Nothing is ever launched (D-08).

**Output rules.** ASCII only (straight quotes, three dots), so output is safe in any terminal, log or script. Errors go to **stderr**, prefixed `transom: `. **Success prints nothing** (Unix convention); the app shows its toast. Help goes to stdout.

**Exit codes.**

| Code | Meaning |
|---|---|
| 0 | Transom accepted the command and ran it (a camera move may still be animating) |
| 1 | Transom refused the command, or didn't answer within **2 s** |
| 2 | Transom is not running (D-08) |
| 64 | Unknown command or bad argument (`EX_USAGE`) |

**Messages (exact text).**

| Situation | stderr | Exit |
|---|---|---|
| Unknown command | `transom: unknown command "foo". Run "transom help" to see every command.` | 64 |
| Slot missing or not 1-9 (`view`, `view 0`, `view 10`, `view x`) | `transom: view needs a slot from 1 to 9, as in "transom view 3".` (`save-view` names itself the same way) | 64 |
| Argument given to a parameterless command | `transom: zoom-out takes no argument.` | 64 |
| Too many arguments | `transom: too many arguments. Run "transom help" to see every command.` | 64 |
| Transom not running (no listener) | `transom: Transom is not running` | 2 |
| Rate limit | `transom: refused (rate limit). Each command runs at most once per second.` | 1 |
| Refused by Transom | `transom: refused: {reason}` where `{reason}` is the exact text VoiceOver would hear for that refusal with curly quotes and "…" made ASCII, for example `transom: refused: No view in slot 3`, `transom: refused: Arranging is paused`, `transom: refused: The focused window isn't in a tab group`, `transom: refused: Zoom is off` | 1 |
| Refused with no announcement text | `transom: refused: zoom-out can't act right now` | 1 |
| No reply within 2 s | `transom: Transom didn't answer` | 1 |

The app treats a CLI request exactly like a URL open (same allow-list, same rate limit, same toasts on success, same silence on screen for refusals); the only difference is that the refusal reason goes back to the CLI. A Debug build's CLI talks to the Debug app (the channel is named from the bundle it ships in).

**Help text (exact, ≤ 72 columns).** The command lines come from one table beside `TransomURL.commands`, and a unit test checks that every allow-listed command has exactly one help line.


## Copywriting Contract

Voice unchanged from Phases 3–7: plain, second person, sentence case for body text, toasts, announcements and Debug lines; title case for Shortcuts rows and section headers; curly quotes around app names in announcements; "…" (U+2026) only for items that need more input, plus the ongoing-wait label "Waiting for {App}…" (user-decided copy, D-13); plurals from explicit branches, never "(s)". No jargon in user-facing copy: never "re-match", "hint", "slot ID", "NodeID" or "desk" outside Debug lines and logs. On screen it is a **"view"** in a **"slot"**. The CLI is the one exception to the typography rules: ASCII only (Surface 5).

The placeholder label follows D-13 literally ("Waiting for Safari…", no quotes around the app name): the app icon right above it already marks the name.

## Accessibility

**Placeholder as an accessibility element.** Role `.staticText`; label "Waiting for {App}…" (same text as the capsule, also when the capsule is hidden by the clearance rule); help "This tile closes if the window doesn't come back." Not pressable (click-through, nothing to act on). The stage and overview drawings of a placeholder are not elements (Phase 4/6 rule).

**Keyboard parity.** Every Phase 8 action is keyboard-first: going and saving are hotkeys, and URL/CLI forms exist for launchers and scripts. The placeholder needs no action (it resolves by itself). Views have no menu items, so a VoiceOver user reaches them by hotkey or CLI; the Shortcuts window's Recorder rows are standard, VoiceOver-labelled controls.

**Reduce Motion.** Going to a view uses the Phase 4 crossfade. Toasts and placeholders only fade (opacity is not motion, Phase 3 rule). macOS's own Space transition follows the system setting.

**Increase Contrast / Differentiate Without Color / Reduce Transparency.** As in Color.

## Notes for the planner

1. **Bundle path.** Put the CLI at `Contents/Helpers/transom`, not `Contents/MacOS/transom`: APFS volumes are case-insensitive by default, so `transom` and the app binary `Transom` would be the same file. The CLI must resolve its own symlink (`/usr/local/bin/transom` → bundle) to find the bundle it belongs to and name the channel from that bundle's ID.
2. **App quit while Transom runs (D-11/D-12 reading).** For "re-match when an app relaunches while Transom keeps running" to have anything to match, an app's docked windows must become placeholders when the app **quits** (today they close through CloseRule's 5 s recheck). **User decision 2026-11-03:** on this path a placeholder expires 30 s after the app quit if it has not relaunched (D-12a). After ⌘Q of an app, its tiles show "Waiting for {App}…" for up to 30 s, then close. A window closed with ⌘W while its app keeps running still closes at once. D-13 deviation: the placeholder is a sibling view sharing AppColor and the fallback-tile layout, not CollapsedBlockView itself (its hover ring and double-click would break click-through).
3. **⌥ fallback detection.** KeyboardShortcuts 3.1.0 does not expose Carbon registration failure (`onRegistrationFailed` is internal), so the fallback is an OS-version rule (Surface 3). If research finds a public signal, the version rule can stay as the default and the signal added on top.
4. **Pitfall 16.** D-01 keeps ⌥1–9 as the default even though ⌥5–9 type brackets on German and similar layouts. This spec mitigates with the Shortcuts footer and README note only; no automatic switch to another default (not decided in CONTEXT).
5. **Toasts and the queue.** The brief class needs a per-item duration in `NoticeQueue` (today one static 6 s) and the "drop behind a crash notice" rule; N13–N16, N18, N19 are brief, N17 is normal.
6. **Joined announcement.** Going to a view must show its toast without announcing and prefix the Phase 4 reveal announcement with "View {n}. ". When nothing moves, the toast announces normally.
