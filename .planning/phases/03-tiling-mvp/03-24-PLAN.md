## Phase Goal

**As a** Mac user, **I want to** drag windows into nested tiles that reflow as windows open and close, **so that** my windows never overlap.

<objective>
Close UAT gap G-03-10 (SAFE-06, CR-03, test 17). If Pane starts while the screen is locked, every saved desk must still be there after the screen is unlocked.

Root cause (binding, from 03-UAT.md G-03-10 and .planning/debug/g-03-10-locked-start.md). Three facts combine:
1. `AXWindowSystem.start()` runs its only initial sweep while the session gate is paused. Every `refresh(pid:)` returns at `guard !paused`, so nothing is observed, yet `initialRefreshComplete` becomes true.
2. On unlock, `sessionDidResume` runs `refreshAll()`, which is a non-initial sweep. `WindowTracker.ingest` holds every first-seen window back for its 250 ms settle delay, so the tracker is still empty when `.sessionPaused(false)` is yielded.
3. ArrangeController feeds that inventory (`awaitsRestore`). It passes the CR-03 guard with no tracked windows, so `reattach` removes every saved window on the shown Space. Hidden-Space windows survive as dormant through the `isAlive` filter. The restore never retries, and 250 ms later the settle refresh admits the removed windows as new floaters at unmoved frames.

The CR-03 test missed this because it hand-blanks an inventory taken from a fake whose initial sweep ran unlocked.

Fix (the debugger's first `missing` item, smallest complete change): the initial sweep counts only if it ran unpaused. Until then `initialRefreshComplete` stays false, and the next unpaused full sweep is the initial one. After a locked start, that is the post-resume `refreshAll`. It tracks every window with no settle hold, before the pause ends. So the existing Arranger guard and the existing ArrangeController feed rule (both wait on `initialRefreshComplete`) wait correctly. FakeWindowSystem mirrors the rule.

Arranger, LayoutRestore, WindowTracker and ArrangeController do not change. A planning-time experiment confirmed the fake half: with only the fake mirror applied, the debug probe passed, and so did the full headless `swift test` (513 tests). The experiment was reverted before this plan was written.

Explicit non-goal (the debugger's live-risk note): if an app's AX reads fail at the first unpaused sweep, its windows are still untracked when the restore runs. This change does not fix that. The same risk already exists at an ordinary unlocked launch. Task 2 records it in deferred-items.md.

Output: AXWindowSystem and FakeWindowSystem changes, one regression test, a deferred-items entry, and a SUMMARY with the RED and GREEN evidence. The orchestrator re-checks the locked start in the Tart VM afterwards (the user must unlock the screen), so this plan has no VM task.
</objective>
