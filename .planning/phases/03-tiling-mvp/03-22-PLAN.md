## Phase Goal

**As a** Mac user, **I want to** drag windows into nested tiles that reflow as windows open and close, **so that** my windows never overlap.

<objective>
Close the docked-overflow part of UAT gap G-03-6: a docked window that can't fit its tile floats to the Desktop instead of overlapping a neighbour (core value).

Root cause (binding, from 03-UAT.md and .planning/debug/g-03-6-fixed-size-window-overlap.md): fit is decided only from learned minimums. `MinimumSizeLearner.recordWrite` counts a refusal only if the read-back moved toward the request, which is the late-applier guard from 7c97838. Reminders' Welcome window opens at its 768x692 minimum, so no write moves it and nothing is learned. No other path compares a docked window's read-back with its tile, and Pane never re-writes a refused tile, because the read-back equals lastApplied. Overflows under the 32 pt refusalMargin are never learned either.

Fix, keeping the late-applier protection as required: one unmoved refusal no longer teaches anything. Arranger re-sends the refused tile once, at least 1 s later. If that write reads back the same clamp, and the usual confirm refresh 1 s after it still sees it, the size is learned. A late applier has had more than a second, then another second, to apply the request, so a single slow write still teaches nothing.

The under-32 pt decision is stated in the truths. Plan 03-21 makes sure the floated window's minimum does not then evict its neighbours.

Output: the learner rule, the Arranger retry, tests including an end-to-end Harness scenario, and a VM re-check of UAT test 15.
</objective>
