## Phase Goal

**As a** Mac user, **I want to** drag windows into nested tiles that reflow as windows open and close, **so that** my windows never overlap.

<objective>
Make the Desktop a real tile in the layout tree (D-24). Every desk starts as the Desktop tile alone; docking beside it shrinks it; floating windows will live inside its rect; hiding it gives its space to the docked tiles. This model change lands first so the persisted format (SAFE-06, plan 07) includes the Desktop tile from its first version.

Purpose: the core promise "windows never overlap" needs a rect that floating windows are confined to. TILE-07 (new windows open floating on the Desktop tile) and TILE-15 (hide and show the Desktop tile) rest on it.
Output: `Node.desktop(hidden:)`, `NodeID.desktop`, Desktop invariants, `setDesktopHidden`, `resolve(... desktopMinimum:)`, `Resolution.desktopRect`, updated JSON fixtures, migrated desk fixtures.
</objective>

Claude's Discretion choices for this phase (record each in the SUMMARY of the plan that applies it):
- The Desktop tile has the reserved ID `NodeID.desktop` (raw 0). `IDSource` starts at 1, so it is never minted, and one desk can hold at most one Desktop tile by construction (this plan).
- Echo recognition: `frameApplied` plus a `windowMoved`/`windowResized` within ±2 pt of the last applied frame is Pane's own write; a user drag needs the press window, ≥ 3 pt of pointer travel and the left button down (plans 06, 10).
- The layout owner is a pure `Arranger` struct in PaneEngine with a thin MainActor `ArrangeController` shell in PaneMac (plan 04).
- A floating window is moved only when its frame overlaps a docked tile; a floating window outside the visible frame but clear of docked tiles is left alone (Restore All handles off-screen windows). Plan 04.
- Dock on a floating window uses the drop target at the window's centre; when that point is in a tile's centre zone (a plain move before Phase 7), the nearest edge band of that same tile is used (plan 04).
- Rotate on a nested split: a nested split cannot take its parent's axis without merging into it, which would stop a second Rotate from undoing the first, so the flip starts at the desk's root split when the target split has a parent (plan 02, D-32).

Deferred and excluded from every plan in this phase: tab grouping from the centre zone (Phase 7), collapsed tiles for windows that don't fit (Phase 4), the hotkey recorder and layout-aware defaults (Phase 4/9), a Secure Input indicator, re-opening new windows in a remembered slot and per-app auto-dock rules (V2-02), CI notarisation and the Homebrew cask (Phase 9), multi-display hardening (Phase 6). There are no default exclusions (D-29).
