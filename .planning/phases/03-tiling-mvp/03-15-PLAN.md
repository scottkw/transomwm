## Phase Goal

**As a** Mac user, **I want to** drag windows into nested tiles that reflow as windows open and close, **so that** my windows never overlap.

<objective>
Quit safely (SAFE-01): before Pane exits, every window it parked or left off-screen goes back to a sensible on-screen frame, with a hard time limit per app. Register `pane://` with its three Phase 3 commands: `restore` (SAFE-03), `toggle-desktop` (TILE-15) and `split-finder` (TILE-17).

Purpose: the last two entry points of success criteria 3 and 4 that need an application delegate.
Output: `AppDelegate`, `AXAppThread.writeForTermination`, `AXWindowSystem.restoreForTermination`, `Recovery.terminationPlan`, `PaneURL`, URL registration, tests.
</objective>

Recovery.terminationPlan (pure): windows that are stranded or parked go to `destination(for:home:display:)`; docked on-screen windows are left alone (D-15: they are already on-screen). AXAppThread.writeForTermination performs the existing frame write on the thread via `CFRunLoopPerformBlock` and waits on a `DispatchSemaphore` until the deadline, returning false on timeout; it never touches the latest-wins queue's state from the waiting thread. AXWindowSystem.restoreForTermination fans the plan out by pid with a DispatchGroup, each with the shared deadline; it runs synchronously on main because the run loop is in modal-panel mode during terminateLater and async MainActor work must not be relied on (Pitfall 14).

AppDelegate: `applicationShouldTerminate` returns `.terminateLater` after scheduling, on the main queue, the sequence restoreForTermination (limit 2 s), then the store write with `cleanExit: true` (moved here from the willTerminate observer of 03-07; keep the freeze-test resume observer, Chesterton's Fence), then `NSApp.reply(toApplicationShouldTerminate: true)`. PaneMacApp sets the delegate before `app.run()` and keeps a static strong reference. SIGTERM: `signal(SIGTERM, SIG_IGN)` and a `DispatchSource.makeSignalSource(signal: SIGTERM, queue: .main)` whose handler calls `NSApp.terminate(nil)`, so `killall Pane` and logout restore too; `kill -9` is the crash path (03-14).

Per SAFE-03, TILE-15, TILE-17 and Pitfall 21. First commit PaneURLTests (RED), then implement (GREEN).

PaneURL.parse uses URLComponents and accepts only the given scheme (exact), a lowercase host in {restore, toggle-desktop, split-finder}, no user, password, port, query or fragment, and a path that is empty or "/". Nothing from the URL is passed anywhere except the chosen Command. AppDelegate.application(_:open:) reads the expected scheme from the bundle's first CFBundleURLSchemes entry, parses each URL, logs a rejection with the url category and no URL contents, rate-limits, and calls `dispatch(command, from: .url)`.

project.yml: add `PANE_URL_SCHEME` to the Debug (`pane-debug`) and Release (`pane`) configurations, and `INFOPLIST_FILE: Pane-Info.plist` alongside `GENERATE_INFOPLIST_FILE: YES` so Xcode merges it; `Pane-Info.plist` holds only `CFBundleURLTypes` with one entry whose `CFBundleURLSchemes` is `$(PANE_URL_SCHEME)` and `CFBundleURLName` `com.eightabyte.pane`. Separate schemes keep LaunchServices from picking the wrong build on a dev Mac (A8). Verify the merge with `plutil -p` on the built app (A17).
