# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 3 is the first usable release. It extends the Phase 2 contract (`02-UI-SPEC.md`) and keeps all of it unless a row below says otherwise. It adds six surfaces:

1. the **drop preview overlay**, shown while a window is dragged
2. the **gap handles** between docked windows
3. the **default hotkeys** on ⌃⌥⌘, routed through the one command dispatcher (TILE-09)
4. the **status menu** regrouped into Arrange, Safety and Exclusions, with conflict lines, pause states, the Gaps submenu, and Debug shown only while ⌥ is held
5. **notices**: a small, click-through toast for "window floated", crash recovery, restore results and similar
6. three **conflict alerts** (Stage Manager, macOS edge tiling, Click Wallpaper to Reveal Desktop)

Not in this phase: the zoom stage, the hotkey recorder, a Settings window, the tab strip, a focus border, and onboarding polish (Phases 4, 7 and 9). The Setup and Tracked Windows windows are unchanged.

**Platform rule (unchanged from Phase 2).** Native macOS only. The shell is AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`, `NSAlert`). SwiftUI is used only inside `NSHostingView` / `NSHostingController`, and here only for the toast content. Overlays are layer-backed AppKit views drawn with Core Animation (`CAShapeLayer`). Every colour is a semantic system colour and every font is a system text style.

**Phase 2 review findings this phase must not repeat** (`02-UI-REVIEW.md`):
- No `.font(.system(size:))` for glyphs. Size glyphs with text styles plus `imageScale`. The only fixed sizes are the ones listed under Spacing ▸ Fixed sizes.
- No `GroupBox` and no padding stacked on top of a system inset. Every padding below is the total padding.
- No duplicated controls. Each action appears once per surface, except the deliberate halves alias described under Hotkeys.
- The menu must not do per-row AppKit lookups on every rebuild. App names and icons come from a per-pid cache that is updated when the inventory changes.
- **Menu header fix (carried into this phase):** the header counts only non-closed windows, using the same rule as the Tracked Windows footer. Before the first sweep finishes it reads "Looking for windows…".

**Clean-room rule.** Every string, default key and visual below was written fresh for Pane. None of TrellisWM's ⌃⌥ hotkey set, copy or icons is used.

**Spelling.** UI strings use US English to match macOS's own en menus ("Center", "Maximize"), because the bundle's development region is `en`. Planning prose may stay British.

## Spacing Scale

All values are in points. The token scale is the Phase 2 set: 4 / 8 / 16 / 24 / 32 / 48 / 64. The Phase 2 exceptions (20pt window inset, 12pt button gap) still apply only where Phase 2 listed them. Phase 3 adds no new spacing exceptions.

| Token | Value | Phase 3 usage |
|-------|-------|---------------|
| xs | 4pt | Glyph-to-text gap inside the overlay label; vertical padding of the overlay label; minimum gap that shows gap handles (TILE-05) |
| sm | 8pt | Horizontal padding of the overlay label; vertical padding of the toast; gap between the toast glyph and text |
| md | 16pt | Horizontal padding of the toast; offset of the toast below the top of the display's `visibleFrame`; minimum clearance the overlay label needs on each side inside a preview rect |
| lg | 24pt | Not used in Phase 3 |
| xl–3xl | 32 / 48 / 64pt | Not used in Phase 3 |

**Gap sizes (user setting, TILE-04):** 0, 4, 8, 12, 16 and 24pt. The default is 8pt. All of them sit on the 4-pt grid. 12pt here is a user-chosen layout gap, not a use of the Phase 2 12pt UI exception.

Exceptions (non-spacing metrics, listed so the checker and auditor can find them):
- **Stroke widths:** 2pt for preview borders, 1pt for the overlay label border. These are line weights, not spacing.
- **Dash pattern:** 8pt on, 4pt off, for the snap-back ghost and the swap-origin border.
- **Corner radii:** 12pt for preview rects and the toast. The overlay label is a capsule (radius = height / 2 = 12pt). Gap-handle strips use radius = gap / 2, capped at 4pt.
- **Fixed sizes:** the toast is at most 360pt wide (it wraps beyond that). The status-item glyph stays 16pt (Phase 2).
- **The preview rect has no inset.** It is exactly the frame the window will get (CONTEXT A), and the stroke is drawn inside it.
- **System metrics:** menu, section-header and alert metrics are system-drawn. Never override them.

## Color

Semantic system colours only, with **no hex literals in code**. The hex values are references resolved on macOS 27.0.1 with the default appearance. Phase 3 is the first phase where Pane applies colour itself, in the overlays. Because `CGColor` does not follow appearance changes, overlay layers must re-resolve their colours inside `effectiveAppearance.performAsCurrentDrawingAppearance { … }` from `viewDidChangeEffectiveAppearance()` and on `NSColor.systemColorsDidChangeNotification` (the user changed the accent colour).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Transparent: the user's own windows and wallpaper | The overlays are tints over existing content. Pane draws no opaque surface larger than a label |
| Secondary (30%) | `NSVisualEffectView.Material.hudWindow` (toast), `windowBackgroundColor` (overlay label fill, ref light `#FFFFFF`, dark `#1E1E1E`), system menu material, `labelColor` tints (snap-back ghost) | Toast background, overlay label, status menu, neutral ghost |
| Accent (10%) | `NSColor.controlAccentColor` (user's accent; ref default blue `#0088FF` light, `#0091FF` dark) | Only the elements listed below |
| Destructive / refusal | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | Phase 2's two uses, plus the **blocked** drop preview (fill, border, `nosign` glyph). Red means "this will not happen", never decoration |
| Warning | `NSColor.systemOrange` (ref `#FF8D28` light, `#FF9230` dark) | The semantic warning colour, as in Phase 2. In Phase 3 it is used only for the `exclamationmark.triangle.fill` glyph of toast N7 ("Couldn't turn off {Feature}…"). It is never used for text, fills or overlays. The conflict menu items use a template (uncoloured) triangle |

Accent reserved for exactly these elements (it extends Phase 2's list, which stays valid):
1. Drop preview fill and border, for both the dock and the swap states
2. The swap-origin dashed border
3. A gap-handle strip while hovered and while dragged
4. Phase 2's system-drawn uses (default button, selection, focus ring), plus the default "Turn Off" button of the conflict alerts (system-drawn)

The accent is **not** used for the snap-back ghost, the toast, the overlay label, menu items or the status glyph.

**Overlay colour recipe** (alpha is applied to the semantic colour):

| Overlay state | Fill | Border (2pt) | Label |
|---|---|---|---|
| Dock (accepted target) | `controlAccentColor` 20% | `controlAccentColor` 85%, solid | none |
| Swap: target tile | `controlAccentColor` 20% | `controlAccentColor` 85%, solid | `arrow.left.arrow.right` + "Swap" |
| Swap: origin tile | `controlAccentColor` 10% | `controlAccentColor` 85%, dashed 8/4 | none |
| Blocked | `systemRed` 12% | `systemRed` 85%, solid | `nosign` (systemRed) + "Not enough room" |
| Snap-back / clamp ghost | `labelColor` 8% | `labelColor` 50%, dashed 8/4 | none (or "Show the Desktop Tile to float windows", see Surface 2) |
| Gap handle, hover | `controlAccentColor` 50% | none | none |
| Gap handle, dragging | `controlAccentColor` 85% | none | none |

**Increase Contrast** (`NSWorkspace.shared.accessibilityDisplayShouldIncreaseContrast`): every fill alpha is multiplied by 1.5 (20→30, 12→18, 10→15, 8→12, 50→75), and every border and gap-handle alpha becomes 100%. **Differentiate Without Color** needs no extra handling, because swap, blocked and ghost already differ by glyph, label or dash, not by colour alone. **Reduce Transparency**: overlays use tints, not materials, so they are unchanged. The toast's `NSVisualEffectView` turns opaque by itself (system).

**Status-item glyph** (extends the Phase 2 table). It is still a template image and is never tinted.

| App state | Glyph | Treatment | `accessibilityDescription` / tooltip |
|---|---|---|---|
| ready, arranging | `rectangle.split.2x1` | normal | "Pane" (tooltip: bundle name) |

| not ready (Phase 2) | `exclamationmark.triangle` | normal | "Pane: Accessibility access needed" |

**The halves alias is the one deliberate duplicate.** ⇧-arrows appear on both Move Window ▸ Left and Snap Floating Window ▸ Left Half. Both route to the single dispatcher command `moveOrSnap(.left)`, and exactly one of the pair is enabled for any focused window (docked → Move, floating → Snap). NSMenu skips disabled items when matching key equivalents, so a key press can only ever hit the enabled one.

**Disabled-state rules:**
- No focused trackable window, an excluded frontmost app, or a never-dock window: every window-scoped Arrange item is disabled. Arrange All, Float All, Hide/Show Desktop and Gaps stay enabled.
- Paused (any reason): items 7–17 are disabled. Gaps, Safety and Exclusions stay enabled.
- Not ready (no Accessibility, Phase 2 header shown): Arrange and Safety items are disabled. Exclusions and Quit stay enabled (Phase 2).
- A disabled item keeps its normal title. Unlike the Phase 2 Debug items, it gets no "(reason)" suffix, because the pause line or header already explains why.

**Pause states.** Pause has a set of reasons, and arranging runs only while the set is empty. "Pause Arranging" adds `user`. "Resume Arranging" clears `user` and `crashLoop`. `stageManager` clears itself when Stage Manager turns off. The title is "Resume Arranging" whenever any reason is present. It is **disabled** when `stageManager` is the only reason, because the conflict item is the way out.

| Reason (priority high → low) | Pause line (item 2) |
|---|---|
| `stageManager` | "Arranging paused: Stage Manager is on" |
| `crashLoop` (second crash within about 60 s, CONTEXT C) | "Arranging paused after Pane quit unexpectedly" |
| `user` | "Arranging paused" |

While paused, Pane keeps tracking, moves nothing, shows no drop preview or gap handles, and ignores drags (CONTEXT C). Resume re-applies the layout.

**Conflict lines (SAFE-04).** These are items with a template `exclamationmark.triangle` image (`accessibilityDescription` "Conflict"). Clicking one turns the feature off immediately. There is no ellipsis and no alert, because the click is the explicit choice, and it is reversible through item 22.

| Conflict | Item title | Tooltip |
|---|---|---|
| Stage Manager on | "Turn Off Stage Manager" | "Stage Manager moves windows by itself, so Pane has paused arranging." |
| Edge tiling on (macOS 15+) | "Turn Off macOS Edge Tiling" | "macOS tiles windows dragged to screen edges, which competes with Pane's docking." |
| Click wallpaper set to Always | "Turn Off Click Wallpaper to Reveal Desktop" | "Clicking the wallpaper or a gap between windows moves every window off screen." |

## Surface 2 — Drop preview overlay (TILE-01, 02, 11)

**What it shows.** The overlay always shows **where the window will end up when that isn't simply where you let go**. If nothing is shown, the window stays where you release it. This rule drives every state below. It is **WYSIWYG**: a release docks only into the preview that is on screen. If no preview is visible at release time, including during the 150 ms before one appears, the miss rules apply.

**Panel.** There is one `NSPanel` per display. Each is created at launch and when displays change, never per drag, and covers that display's full `frame`. Preview rects are `CAShapeLayer`s inside it, positioned through the Phase 2 coordinate boundary (`Coordinates.swift`, AX top-left to AppKit bottom-left). The panel is ordered front when a drag starts and ordered out when it ends.

| Property | Value | Why |
|---|---|---|
| `styleMask` | `[.borderless, .nonactivatingPanel]` | Never activates Pane or takes focus from the dragging app |
| `ignoresMouseEvents` | `true` | Click-through: the drag continues underneath it (Pitfall 18) |
| `canBecomeKey` / `canBecomeMain` | `false` (subclass override) | Never key, never main |
| `level` | `.floating` | Above normal app windows, including the dragged window, and below the Dock and menu bar. Previews are confined to `visibleFrame`, so they never sit under the menu bar or Dock |
| `collectionBehavior` | `[.canJoinAllSpaces, .stationary, .ignoresCycle]` | Present on whichever Space the drag happens on; not moved by Exposé; not in ⌘` cycling. No `.fullScreenAuxiliary`: fullscreen Spaces have no layout and fullscreen windows can't be dragged |
| `sharingType` | `.none` | Never appears in screenshots, screen sharing or later Pane snapshots (Pitfall 18) |
| `isOpaque` / `backgroundColor` / `hasShadow` | `false` / `.clear` / `false` | The layer draws everything |
| `animationBehavior` | `.none` | No system window animation on order-in/out |
| `hidesOnDeactivate` | `false` | Pane is never active during a drag |
| Accessibility | `setAccessibilityElement(false)` on the panel and its views | Pointer feedback only. Refusals are announced instead (see Accessibility) |

**Timing.** The dwell starts when the hovered target changes, **or a modifier changes**, and lasts 150 ms of no further change (CONTEXT A). The dry run (`applyDrop` + `resolve`, PaneModel) runs once per target change, never per mouse move. If it has not returned when the dwell ends, nothing is shown; a stale frame is never shown.

**State matrix** (pointer over a zone from `DropZones.target`; modifiers are read live during the drag, not at mouse-down):

| Dragged window | Pointer over | Modifier | Overlay after dwell | On release |
|---|---|---|---|---|
| docked or floating | a tile edge band, a layout edge band (24pt) or an empty layout, and the dry run fits | none | **Dock**: the exact resolved frame | Docks there |
| docked or floating | same, but the dry run leaves any window without room (`unfit` non-empty) | none | **Blocked**: the frame the window would get if minimum sizes were ignored, plus the "Not enough room" label | Refused, then the miss rules apply |
| docked | any part of another **docked** tile | ⌘ | **Swap**: target tile rect with the "Swap" label, plus the origin tile rect dashed | The two windows swap tiles (TILE-11) |
| floating | a docked tile | ⌘ | ⌘ is ignored; the row for no modifier applies | as with no modifier |
| docked | its own tile, a tile centre (before Phase 7), a gap, or outside every zone | none | **Snap-back ghost** on its origin tile | Snaps back to its tile (CONTEXT A) |
| floating | a tile centre, a gap, or outside every zone; the release frame stays inside the Desktop tile | none | nothing | Plain move |
| floating | same, but the release frame would cross into docked tiles | none | **Clamp ghost** at the frame clamped inside the Desktop tile | Moves to the clamped frame. Nothing overlaps |
| any | anywhere | ⇧ (bypass, TILE-02) | nothing. Shows a **clamp ghost** only if the release frame would cross docked tiles | A docked window undocks and floats at the release frame, clamped inside the Desktop tile |
| any | anywhere | ⇧, while the Desktop tile is **hidden** | Snap-back ghost on the origin, with the label "Show the Desktop Tile to float windows" | A docked window snaps back; a floating window can't exist in this state |
| any | a window that can't fit inside the Desktop tile even at its minimum size | ⇧ | **Blocked** over the Desktop tile rect, with "Not enough room" | Refused, then the miss rules apply |

Over the **Desktop tile** (a real leaf, CONTEXT D), the same rules apply: its edge bands dock beside it, and its centre is a plain floating move. A fullscreen window's reserved tile (WIN-07) is an ordinary drop target and shows the wallpaper. Phase 3 draws no placeholder there. Excluded apps, never-dock windows, and every drag while paused get no overlay at all.

**Overlay label.** A capsule centred in the preview rect, containing a glyph, 4pt, then the text. Padding is 8pt horizontal and 4pt vertical. Fill `windowBackgroundColor` at 100%, a 1pt `separatorColor` border, and text in `labelColor` using the Heading style. The swap glyph is `labelColor`; the blocked glyph is `systemRed`. The label is hidden when the rect is narrower or shorter than the label plus 16pt clearance on each side. The rect alone then carries the state, and the colour + dash difference is backed by the VoiceOver announcement.

**Animation.**

| Event | Default | Reduce Motion (`accessibilityDisplayShouldReduceMotion`, observed live) |
|---|---|---|
| Preview appears (after dwell) | Opacity 0→1, 120 ms, ease-out | Same fade (opacity is not motion) |
| Target changes while a preview is shown | Frame morphs from the old rect to the new one, 120 ms, ease-in-out (`CABasicAnimation` on `path`/`position`) | **No morph.** The old rect is removed and the new rect fades in, 120 ms |
| State changes in place (e.g. ⌘ pressed: dock → swap) | Cross-fade, 80 ms | Same |
| Target lost or modifier makes it a miss | Opacity 1→0, 80 ms | Same |
| Release accepted | Fade out 120 ms, starting when the frame write is sent | Same |
| Release refused (blocked) | Fade out 120 ms. No shake, bounce or scale, in any mode | Same |

**Keyboard parity.** When a keyboard command (Dock Window, Move Window, Arrange All) is refused for lack of room, the **blocked** preview flashes at the would-be frame for 600 ms (fade in 120 ms, hold, fade out 120 ms), and a VoiceOver announcement is posted. A command that succeeds shows no preview, because the window moving is the feedback.

## Surface 3 — Gap handles (TILE-05)

**When they exist.** Only when the gap setting is at least 4pt (so not with None), Pane is not paused, and no window drag is in progress. They are hidden during a Space change and re-shown after the new Space's layout resolves. At 0pt, resizing uses each window's own edge (`resizeBoundary`).

**Geometry.** There is one handle per boundary between adjacent siblings of a split. It covers **exactly** the gap strip along their shared edge, for the full length of that edge, and extends no further into either window, so no click is taken from an app. Outer gaps between tiles and the screen edge get no handle, because they are not a boundary. Where nested boundaries meet (a T-junction), the parent split's handle runs through, and the child handle stops at its edge.

**Panel.** There is one `NSPanel` per handle, recycled through a pool, with `[.borderless, .nonactivatingPanel]`, `canBecomeKey = false` and `level = .floating`. Collection behaviour is `[.canJoinAllSpaces, .stationary, .ignoresCycle]` with no `.fullScreenAuxiliary`, `sharingType = .none`, and `ignoresMouseEvents = false`. A handle panel only covers bare wallpaper, so taking mouse events there steals nothing. It never activates Pane: clicking or dragging it leaves the frontmost app frontmost. The tracking area uses `[.mouseEnteredAndExited, .cursorUpdate, .activeAlways]` so that hover and cursor work while Pane is inactive.

| State | Visual | Cursor |
|---|---|---|
| Rest | Invisible (the gap shows the wallpaper as before) | system default |

## Surface 4 — Notices (toast)

These are non-blocking, click-through, short-lived messages. Phase 3 does **not** use `UNUserNotificationCenter`, because that would add another permission prompt.

**Panel.** `NSPanel` with `[.borderless, .nonactivatingPanel]`, `ignoresMouseEvents = true`, `level = .floating`, `collectionBehavior = [.canJoinAllSpaces, .stationary, .ignoresCycle]`, `sharingType = .none`, and `hasShadow = true`. Content is `NSVisualEffectView` (material `.hudWindow`, `state = .active`, corner radius 12pt) holding an `NSHostingView` with an HStack: glyph (`.font(.body)`, `.imageScale(.large)`, `secondaryLabelColor` unless the table says otherwise, hidden from VoiceOver), 8pt, then text (`.body`, `labelColor`, wraps up to 3 lines, max width 360pt). Padding is 16pt horizontal and 8pt vertical. The toast is centred horizontally at the top of the **affected display's** `visibleFrame`, 16pt below its top edge. For notices with no affected display, that is the display with the menu bar.

**Timing.** Fades in over 160 ms and out over 240 ms (opacity only, and the same under Reduce Motion). It stays visible 6 s, or 10 s for N2/N3. Only one toast shows at a time. A new toast replaces the current one, except that crash notices (N2/N3) are never replaced. Others wait behind them in a queue of up to 3, and older queued items are dropped. Toasts of the same kind that arrive while one is showing are merged into one count, e.g. two "floated" notices become "2 windows…".

Each toast also posts a VoiceOver announcement with the same text (see Accessibility).

| ID | When | Glyph | Copy |
|---|---|---|---|
| N1 | A window loses its room later (larger learned minimum, smaller display) and floats (CONTEXT D) | `macwindow` | 1: "A “{App}” window no longer fits its tile, so it's floating on the Desktop." · n: "{n} windows no longer fit their tiles, so they're floating on the Desktop." |

## Surface 5 — Conflict alerts (SAFE-04)

**When.** Pane checks at launch and whenever the relevant `com.apple.WindowManager` values change. Each feature gets **one** alert per "on" episode, meaning the first time Pane sees it on after it was off, or the first launch that finds it on. Not Now is remembered across relaunches while the feature stays on. If Pane itself turns a feature back on through Restore macOS Window Settings, no alert is shown. The menu conflict item stays visible while the conflict remains. Only one alert is up at a time; others queue. An alert is never shown during a drag, and is deferred until mouse-up.

**Non-blocking contract.** Tracking, the event tap, drops and hotkeys keep working while an alert is up, and no feature waits for the answer. Closing the alert is the same as Not Now. If `runModal()` is used, the planner must verify that docking still works with the alert open (backstop below). Otherwise the alert's window is shown modelessly.

**Form.** `NSAlert`, `alertStyle = .informational` (app icon), shown after `NSApp.activate()`. Buttons: **"Turn Off"** (first, rightmost, default, Return) and **"Not Now"** (Esc). Neither is destructive, because the change is reversible from the menu. The labels "Turn Off" / "Not Now" are fixed by CONTEXT. The message text names the feature and asks the question, so the bare "Turn Off" can't be read as anything else (the Phase 2 checker's bare-label concern).

| Feature | `messageText` | `informativeText` | What "Turn Off" changes (originals recorded once, then read back) |
|---|---|---|---|
| Stage Manager | "Turn off Stage Manager?" | "Stage Manager moves and groups windows by itself, so Pane has paused arranging. Turning it off lets Pane arrange your windows again. You can turn it back on with Restore macOS Window Settings in the Pane menu." | Stage Manager off. Pause reason `stageManager` clears once the read-back confirms |
| macOS edge tiling (macOS 15+ only; never shown on 14) | "Turn off macOS edge tiling?" | "macOS also tiles a window when you drag it to a screen edge or the menu bar, so a drag meant for Pane can be tiled by macOS instead. Pane keeps working either way. You can turn macOS tiling back on with Restore macOS Window Settings in the Pane menu." | "Drag windows to screen edges to tile" and "Drag windows to menu bar to fill screen" off. "Hold ⌥ key while dragging windows to tile" is left as the user set it (CONTEXT A leaves ⌥-drag alone) |
| Click Wallpaper to Reveal Desktop | "Turn off Click Wallpaper to Reveal Desktop?" | "With this on, clicking the wallpaper, including a gap between docked windows, moves every window off screen. Turning it off sets it to Only in Stage Manager. You can change it back with Restore macOS Window Settings in the Pane menu." | "Click wallpaper to reveal desktop" set to "Only in Stage Manager" |

If the read-back fails, Pane opens Desktop & Dock and shows N7. The setting key names are LOW confidence (Pitfall 15), so the read-back is mandatory.

## Surface 6 — Default hotkeys (TILE-09, 11–18, SAFE-03, undo, pause)

Every hotkey is on the **⌃⌥⌘** base (CONTEXT B). They are registered through KeyboardShortcuts 3.1.0 with `KeyboardShortcuts.Name("<name>", initial: …)`, so the stable names below are what the Phase 4 recorder rebinds. KeyboardShortcuts registers by key code, so on non-US layouts the physical key stays the same and the menu shows that layout's character (layout-aware defaults are deferred, Pitfall 16). There is no rebinding in Phase 3.

**Consistency rules:** arrows are directions; ⇧ on an arrow means *move*; ⇧ on a letter widens a command to *all windows* (D→⇧D, F→⇧F). Every chord runs one dispatcher command, and the menu item runs the same command. A hotkey that can't act (no target, wrong window kind, paused, nothing to undo, at a size limit) plays `NSSound.beep()`. Refusals for lack of room also flash the blocked preview (Surface 2). ## Accessibility

**Status menu (VoiceOver).**
- Section headers (`NSMenuItem.sectionHeader`) are announced as headings. Disabled info lines (header, pause line, degraded line) are read as dimmed text, so the reason for a disabled command is always reachable.
- Each item's key equivalent is set through `setShortcut(for:)`, so VoiceOver reads it ("Dock Window, Control-Option-Command-D").
- Conflict item images carry `accessibilityDescription` "Conflict", so they read as "Conflict, Turn Off Stage Manager".
- The status button's `accessibilityDescription` follows the glyph table ("Pane: arranging paused" when paused).
- Every command is in the menu, so a user who can't use the hotkeys or drag loses nothing. Drags have keyboard equivalents: Dock / Move Window for docking, Swap for ⌘-drag, Grow / Shrink for the gap handles.

**Alerts (VoiceOver).** `NSAlert` is accessible by default. `NSApp.activate()` runs before the alert shows, so VoiceOver focus lands on it. The message text is the question and is read first. The default button ("Turn Off") and Esc → "Not Now" are standard.

**Overlays and toasts.**
- The drop preview, gap handles and toast panels are not accessibility elements.
- Each toast posts `NSAccessibility.post(element: NSApp, notification: .announcementRequested, userInfo: [.announcement: text, .priority: NSAccessibilityPriorityLevel.high])` with its exact text.
- A refused drop or refused command announces "Not enough room to dock here". A swap on release announces "Swapped". The bypass-with-hidden-Desktop refusal announces "Show the Desktop Tile to float windows".

**VoiceOver and the ⌃⌥⌘ chords.** Phase 3 keeps the hotkeys registered while VoiceOver runs. **If UAT shows a Pane hotkey swallowing a VoiceOver command** (test: with VoiceOver on in Safari, VO-⌘-H still moves to the next heading), the fallback is fixed now: while `NSWorkspace.shared.isVoiceOverEnabled` is true (key-value observed), Pane disables every hotkey whose key is a letter, digit or Return, keeps the arrow chords, and shows the info line "Hotkeys off while VoiceOver is running". The Phase 4 recorder will let users bind them back.

**Reduce Motion.** The drop preview never morphs between targets: the old rect is removed and the new one fades in. Opacity fades stay, at the durations in Surface 2. Pane draws no slide, scale, shake or bounce in any mode. Toast and gap-handle fades are opacity only and don't change. The setting is observed live through `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification`.

**Increase Contrast / Differentiate Without Color / Reduce Transparency.** As in the Color section: stronger alphas, states that never depend on colour alone, and system-handled materials.
