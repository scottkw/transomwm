# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 9 **extends** `02-`, `03-`, `04-`, `06-`, `08-`, `08.1-` and `08.1.1-UI-SPEC.md`. Every token, timing, panel property, colour recipe, copy rule and announcement pattern in them still applies unless this spec changes it.

Phase 9 has eight surfaces:

1. **Settings window**: one window, seven toolbar tabs (SHIP-01, D-01..D-04)
2. **Onboarding**: the Set Up Transom window becomes a short step-by-step setup (SHIP-02, SHIP-03, D-05..D-08)
3. **Updates**: the Updates tab, the menu-bar dot and the update menu items (SHIP-04, SHIP-07, D-09, D-10)
4. **Menu-bar view controls**: optional Back, Forward and saved-view items (SHIP-06, D-13, D-14)
5. **Status menu changes**: Settings…, Report a Problem…, the update items, and what moves out of the menu (SHIP-07, D-15)
6. **`transom://settings` and `transom settings`** (SHIP-08, D-04)
7. **Collapsed-block label** (D-16)
8. **Brand assets and release artefacts**: the app icon, menu-bar template glyphs, the DMG window and README copy (SHIP-05, D-11, D-12)

D-11 (release script), D-12 (tap and cask), D-17 (flaky tests) and D-18 (name check and beta checklist) have no UI of their own beyond Surface 8.

**Guiding rule (user, since 8.1.1).** Use plain macOS behaviour and keep the UX simple. Settings follows Apple's HIG for a Settings window. When this spec had to choose, it picked the option that adds the fewest concepts, strings and controls. New menu-bar controls are off by default.

**Platform rule (unchanged).** Native macOS only. The shell is AppKit (`NSStatusItem`, `NSMenu`, `NSWindow`, `NSPanel`, `NSAlert`). SwiftUI is used only inside `NSHostingController`, never as a SwiftUI `Settings` scene or `App`. Overlays are layer-backed AppKit views. Every colour is a semantic system colour. The one exception is the user's own highlight override (Surface 1, General). Every font is a system text style.

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom.

**Spelling.** UI strings use US English ("Color", "Center"). Planning prose may stay British.

## Spacing Scale

All values are in points. The token scale is unchanged: 4 / 8 / 16 / 24 / 32 / 48 / 64.

| Token | Value | Phase 9 usage |
|-------|-------|---------------|
| xs | 4pt | Collapsed-label card vertical padding (Surface 7); gap between a status glyph and its text in Settings rows |
| sm | 8pt | Gap between the icon and the label card on a collapsed block; card horizontal padding; gap between buttons in an onboarding row's trailing controls; onboarding step list spacing (existing) |
| md | 16pt | Onboarding vertical stack spacing (existing); collapsed-label clearance from the block edge (`TileLayer.clearance`) |
| lg | 24pt | Gap above the onboarding button row (existing: 16 stack + 8 padding) |
| xl–3xl | 32 / 48 / 64pt | Not used |

Exceptions (non-spacing metrics, listed so the checker and auditor can find them):
- **Onboarding window**: content width 440pt, outer padding 20pt, inner text stack 12pt. All three are unchanged Phase 2 metrics (02-UI-SPEC), kept so the window doesn't change width between steps.
- **Settings window**: content width **560pt** for every tab. The height fits each tab's content and is capped at 640pt. Shortcuts and Exclusions use a fixed 560pt height and scroll inside their `Form`. Grouped `Form` insets, row heights, toolbar tab metrics and `Recorder` rows are system-drawn. Never override them.
- **Hero glyphs**: 48pt SF Symbol on each onboarding step (existing Phase 2 size; it sizes a glyph, not text). The Welcome step shows the app icon at 64pt.
- **Collapsed-label card**: corner radius 8pt (two lines) or height / 2 (one line, the `TileLayer` capsule rule). Border 1pt.
- **Menu-bar update dot**: 6pt diameter, centred at (15, 3) on the 18 × 18pt glyph canvas, with a 1pt transparent knock-out ring cut from the glyph around it (Surface 3).
- **DMG window**: 540 × 380pt, icon size 128pt, app at (140, 180), Applications link at (400, 180) (Surface 8).

## Color

Semantic system colours only, with no hex literals in code. The single exception is the user's highlight override, stored as `#RRGGBB`. Hex values below are references resolved on macOS 27 with the default appearance.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `windowBackgroundColor` (system) | Settings and Set Up Transom window backgrounds. The user's windows and wallpaper everywhere else |
| Secondary (30%) | System grouped-form section fill; `GroupBox` fill; `windowBackgroundColor` + 1pt `separatorColor` for the collapsed-label card (Phase 4 capsule recipe) | Settings sections, onboarding callouts, collapsed-label card |
| Accent (10%) | **Highlight color** = `NSColor.controlAccentColor` (ref default `#0088FF` light, `#0091FF` dark), or the user's override from Settings ▸ General (D-03) | Only the elements listed below |
| Destructive | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | The `xmark.octagon.fill` glyph on the update verification failure and on the existing reset failure (callout E). Plus the existing Blocked preview. The destructive alert buttons are system-drawn (`hasDestructiveAction`) |
| Success | `NSColor.systemGreen` | `checkmark.circle.fill` for a granted permission or a feature turned off in onboarding and Settings, and the Done step hero (existing Phase 2 ready glyph) |
| Warning | `NSColor.systemOrange` | The existing stale-grant hero. Plus `exclamationmark.triangle.fill` beside "Needs your OK in System Settings" (login item `requiresApproval`) |

**Highlight color (D-03).** One resolver, `HighlightColor.current`, returns the override when one is set and `controlAccentColor` otherwise. It is re-resolved on every draw, as `CollapsedBlockView.updateLayer` already does, so appearance and accent changes apply at once. **Every Transom-drawn accent use goes through it**: drop previews, swap origin, gap handles, rect-zoom target preview, pick-mode ring, collapsed-block hover ring, overview selection ring, Group drop preview and fourth/half/third result previews, plus the Increase Contrast alpha rules from Phase 3/4. System-drawn controls (default buttons, toggles, focus rings, the selected toolbar tab, the `Recorder`'s recording state) keep the **macOS** accent. Transom never tints AppKit controls.

Accent (highlight) reserved for exactly:
1. Every Phase 3–8.1.1 Transom-drawn use listed above, now through `HighlightColor.current`
2. Nothing new. The Settings window, onboarding, menu-bar view controls, the update dot and the collapsed label add **no** highlight use. The view controls and the dot are template images (monochrome, tinted by macOS). Filled versus outlined marks the current view, not colour.

## Surface 1 — Settings window (SHIP-01, SHIP-08, D-01..D-04)

**Window.** One `KeyClosableWindow` owned by a new `SettingsWindowController`, with `styleMask [.titled, .closable]`, `isReleasedWhenClosed = false` and frame autosave name `"Settings"`. On first show it is centred on the menu-bar screen. Its content is an `NSTabViewController` with `tabStyle = .toolbar`. The window has the system Settings look: toolbar tabs with an icon over a label, and the window title equal to the selected tab's label. Each tab is an `NSHostingController` holding a SwiftUI `Form { … }.formStyle(.grouped)` at 560pt wide. Opening it calls `NSApp.activate()` then `makeKeyAndOrderFront`. Esc and ⌘W close it (`KeyClosableWindow`). Only one window exists; opening again brings it forward on the requested tab. Without a requested tab it reopens on the **last tab shown** (UserDefaults `settings.lastPane`). The tab change resizes the window height with the system animation, and with no animation when Reduce Motion is on.

**Tabs (D-01), in toolbar order.**

| # | Label | SF Symbol | `pane=` value |
|---|---|---|---|
| 1 | General | `gearshape` | `general` |
| 2 | Arranging | `rectangle.split.3x1` | `arranging` |
| 3 | Zoom & Gestures | `plus.magnifyingglass` | `zoom` |
| 4 | Shortcuts | `keyboard` | `shortcuts` |
| 5 | Exclusions | `hand.raised` | `exclusions` |
| 6 | Menu Bar | `menubar.rectangle` | `menubar` |
| 7 | Updates | `arrow.down.circle` | `updates` |

**One source of truth (D-02).** Every control reads and writes the same preference object the menu uses (`GapPreference`, `NewWindowsPreference`, `DragToDockPreference`, `ExclusionStore`, `MissionControlTakeover`, the zoom key, `CloseGroupConfirmation`). Each exposes its value to SwiftUI as observable, so a change made in the menu while Settings is open shows at once, and a Settings change shows the next time the menu opens. No control keeps a copy.

## Surface 2 — Onboarding (SHIP-02, SHIP-03, D-05..D-08)

**Window.** The existing "Set Up Transom" window (`SetupWindowController`): `[.titled, .closable]`, 440pt content plus 20pt padding, height following `preferredContentSize`, centred on the menu-bar screen on first show. `SetupView` becomes a step container. The heading, body, steps, callouts and button row keep the Phase 2 layout and copy. Steps swap instantly with no slide, and the window height follows the content.

**Step order (D-05).** Only applicable steps are shown and counted.

| # | Step | Shown when | Hero |
|---|---|---|---|
| 0 | Move to Applications (D-08) | The app runs translocated (`/AppTranslocation/` in the bundle path), from `/Volumes/`, or from `~/Downloads`. Checked **before** any permission request | `folder` 48pt, secondary |
| 1 | Welcome | Always on the first run | App icon 64pt |
| 2 | Accessibility (required) | Always. It shows already granted and advances by itself when access is ready | `accessibility` 48pt, secondary; Phase 2 state heroes otherwise |
| 3 | Screen Recording (optional) | Always on the first run | `rectangle.dashed.badge.record` 48pt, secondary |
| 4 | macOS window features | At least one `Conflict` is active | `macwindow.on.rectangle` 48pt, secondary |
| 5 | Launch at login | Always on the first run | `power` 48pt, secondary |
| 6 | Done | Always on the first run | `checkmark.circle.fill` 48pt, `systemGreen` |

**Caption.** Above the heading, steps 1–5 show "Step {n} of {total}" in Label style (11pt, `secondaryLabelColor`), where total counts only the steps that will show. Steps 0 and 6 have no caption.

**When it opens.**
- **First run** (UserDefaults `onboarding.completed` absent): it opens at launch at step 0 or 1, even when Accessibility is already granted (existing users who update to 0.9.0 see it once and step 2 passes by itself).
- **Progress survives a relaunch.** `onboarding.step` stores the last step reached. If macOS's "Quit & Reopen" prompt for Screen Recording relaunches Transom, setup resumes at the step after Screen Recording.
- **After completion** (`onboarding.completed = true`, set by Done or by closing the window from step 3 onward): later launches keep Phase 2's rule. The window opens by itself only when access isn't ready, showing **only** the Accessibility step with no caption. Its Done button reads "Done" on ready. Menu ▸ Grant/Fix Accessibility Access… opens that same single step.
- Closing the window during steps 0–2 quits nothing. It leaves access not ready, the menu's Grant item reopens it, and the first-run flag stays absent.

**No prompt loops (D-06).** Each permission is requested **at most once per click**: Accessibility through Open System Settings (existing), Screen Recording through one `CGRequestScreenCaptureAccess()` call. After that Transom only polls (Accessibility: the existing 1 s probe; Screen Recording: `CGPreflightScreenCaptureAccess()` every 1 s while step 3 shows). A stale grant shows the existing Reset Permission callout B. Nothing re-prompts by itself.

**Step copy and buttons.** In the button row, the default button is on the right (`.borderedProminent`, Return), the secondary buttons sit to its left, and "Back" is leftmost on steps 3–5. "Quit Transom" appears only on steps 0–2.

| Step | Heading (Display) | Body | Buttons, left to right |
|---|---|---|---|
| 0 Move | "Move Transom to Applications" | "Transom is running from {place}. macOS can forget the permissions you give it there, so move it to the Applications folder first." `{place}` is "a disk image", "your Downloads folder" or "a temporary folder" (translocated) | **Quit** · **Move to Applications** (default) |
| 1 Welcome | "Welcome to Transom" | "Transom docks your windows into tiles that never overlap, and lets you zoom out to see them all. Setup takes about a minute: one permission is required, the rest is optional." | Quit Transom · **Continue** (default) |
| 2 Accessibility | Phase 2 copy unchanged ("Let Transom arrange your windows" and every state) | Phase 2 copy and numbered steps unchanged | Phase 2 buttons unchanged. On `.ready` the step advances to the next one by itself, with no "Transom is ready" stop in the middle |
| 3 Screen Recording | "Show window previews (optional)" | "When you zoom out, Transom can show live pictures of your windows. That needs Screen Recording access. Without it, zoomed-out views show each app's icon. Transom never records or saves your screen." Then a secondary line: "On macOS 15 and later, macOS asks you to confirm this about once a month. Choose Allow to keep previews." | Back · **Skip** · **Allow Screen Recording** (default) |
| 3, after Allow | same | Status row (spinner + Label): "Waiting for Screen Recording…" and the text "Turn on “Transom” in System Settings ▸ Privacy & Security ▸ Screen & System Audio Recording. You can also turn it on later in Settings ▸ Zoom & Gestures." | Back · **Continue** (default; never blocked) |
| 3, granted | same | Green check + "Screen Recording is on." | Back · **Continue** (default) |
| 4 Features | "Turn off macOS features that move windows" | "These move windows by themselves and fight with Transom. You can turn them back on any time with Restore macOS Window Settings in the Transom menu." Then one row per `Conflict` (all three shown, active or not): name (Heading style), `ConflictCopy.tooltip` (secondary), and trailing **"Turn Off"** or a green check + "Off". Under each active row sits a `.link` button **"Open Desktop & Dock Settings"** that opens `x-apple.systempreferences:com.apple.Desktop-Settings.extension` | Back · **Continue** (default) |
| 5 Launch at login | "Open Transom when you log in" | `Toggle` **"Open Transom at login"**, on by default (D-07). Under it: "Transom arranges windows only while it's running. You can change this in Settings ▸ General." | Back · **Continue** (default). Continue calls `register()` only when the toggle is on. On an error or `.requiresApproval`, the step stays and shows the General tab's message and button. Continue then moves on |
| 6 Done | "Transom is ready" | "Transom lives in the menu bar. Drag a window to a screen edge to dock it, or click the Transom icon for every command and Settings." | **Open Settings** · **Done** (default) |

**Move to Applications (D-08) behaviour.** The step copies the bundle to `/Applications/Transom.app`, opens the copy, and quits this one. If `/Applications/Transom.app` already exists, an `NSAlert` asks first (see Copywriting, destructive). Replacing moves the old copy to the Trash, never deletes it. A failed copy (no permission, disk full) keeps the step and adds callout E styling: "Couldn't move Transom. Drag it to the Applications folder yourself, then open it from there." The buttons stay.

**First-zoom previews alert (08.1 deferred finding).** Reaching step 3 sets `zoomPreviewExplainerShown = true`, so the Phase 4 "Show window previews while zooming?" alert never appears for a user who has already answered here.

**Conflicting features (Claude's discretion 6).** The step shows the three existing `Conflict` cases. If the phase research finds another macOS feature that moves windows by itself, it gets a row with this same recipe, a `ConflictCopy` entry and a `Conflict` case. No other UI changes.

## Surface 7 — Collapsed-block label (D-16)

**Problem.** At rest, a collapsed block is an app-colour rectangle with the app icon (Phase 4 Surface 3). In 08.1 UAT the user read it as a minimised window.

**Layout and fit** (top to bottom, centred as one group, as the Phase 4 fallback tile does):
1. Icon at `min(32, shorter side − 8)`, hidden below 16pt (unchanged).

4. **Line 1 only**: when the full card doesn't fit but a one-line capsule does, by the same rule.
5. **Icon only**: otherwise, as today.

The card width is the wider line plus 16pt, capped at block width − 32. Lines that don't fit are truncated with "…".

**Unchanged:** the app-colour fill, the radius `min(12, shorter / 2)`, the 1pt separator border, the hover ring (highlight colour), the pointing hand, double-click to zoom in, the help "Double-click to zoom in", and the accessibility label (`CollapsedBlockView.label` / `TabCopy.collapsedGroupLabel`, which already says "collapsed"). ## Accessibility

**Native controls (8.1.1 D-19).** Settings, onboarding, the Exclusions list, the update UI and the menu items are system controls. VoiceOver reads their labels, values and states with no custom work. Required details:
- Toolbar tabs read their labels. Each tab's `Form` sections read as groups with their headers.
- Status glyphs beside text (`checkmark.circle.fill`, `xmark.octagon.fill`, the warning triangle) are `accessibilityHidden(true)` when the text already says the state ("On", the error text). The error glyph keeps the label "Error" (existing callout E pattern).
- Onboarding: the step heading has `.isHeader`. On every step change, VoiceOver focus moves to the heading (`AccessibilityFocusState`), so the new step is read. The hero image is hidden from accessibility.
- Updates: the status line is a live region, so each state change is spoken (`.accessibilityAddTraits(.updatesFrequently)` on the text). The progress bar exposes its percentage.
- Menu Bar tab reorder: "Move Up" / "Move Down" VoiceOver custom actions and the right-click menu give a non-drag way to reorder.
- Exclusions `+` / `−`: accessibility labels "Add App" / "Remove App".
- Menu-bar view controls: each `NSStatusItem` button has its accessibility description (Surface 4), which VoiceOver reads in the menu-bar extras.

**Keyboard.** Settings: Tab moves between controls (system full keyboard access), and Esc / ⌘W close. Onboarding: Return triggers the default button and Esc closes the window (`KeyClosableWindow`, blocked while a reset runs, as today).

**Overlays.** The collapsed-label card is drawn inside the existing block panel, whose accessibility label already says "collapsed". No new announcement.

**Reduce Motion / Increase Contrast / Differentiate Without Color / Reduce Transparency.** Settings tab resize: no animation with Reduce Motion. Collapsed card: Increase Contrast gives a 100% `labelColor` border; it is opaque, so Reduce Transparency needs nothing. View controls: current versus other is filled versus outlined, never colour. Update dot: a shape, not a colour.

4. **Settings reopens on its last tab;** an unknown `pane=` opens General (D-04). This is plain macOS behaviour.
5. **Onboarding shows once for everyone, including existing users,** so they also get the launch-at-login choice. The Accessibility step passes by itself when access is granted. After that, only the single Accessibility step ever opens by itself.
6. **Conflicting features: the three existing `Conflict` cases** with Turn Off, plus the D-05 System Settings button as a link under each active row. All three live in Desktop & Dock. Research may add a row with the same recipe.
7. **"Update to Transom {v}…" opens Settings ▸ Updates and starts the download there,** so progress and errors have one home. Homebrew installs get an info line and a copy-command item instead (D-10).
8. **No "skip this version"** and no reminder cadence: the dot stays until you update. One concept fewer.
9. **View controls are one status item per control and per saved slot.** Each is a native button with its own accessibility label, and they are hidden while zoom is off, because they do nothing then. Only saved slots get a badge.
10. **Collapsed label = icon + a title card with "Collapsed".** The second line says what happened, and the existing tooltip says how to get the window back (double-click). The card reuses the Phase 4 title-capsule recipe, so there are no new colours, sizes or weights.
11. **Brand assets wired in this phase.** The app icon and the `TransomTemplate` glyphs exist in `design-template/icons/`, and a shipped DMG needs an app icon. The update dot is composited onto the template glyph, so it stays monochrome and HIG-correct.
12. **Report a Problem has no confirmation or toast.** The browser opening is the feedback, and the tooltip says the details are also copied.

## Notes for the planner

1. **`SettingsWindowController`** replaces `ShortcutsWindowController` (keep `ShortcutsView` and `confirmRestoreDefaults`). It takes an optional pane and is the one entry for the menu, URL, CLI, onboarding Done, and the Updates menu item.
2. **Preference objects need SwiftUI observation.** `GapPreference`, `NewWindowsPreference` and `DragToDockPreference` have `onChange` closures today. Wrap them (or make them `ObservableObject`) without adding a second store (D-02). `ExclusionStore` is already `ObservableObject`.
3. **`HighlightColor.current`** must replace every direct `NSColor.controlAccentColor` in Transom-drawn layers (grep `controlAccentColor` in `Overlay/`, `Zoom/`, `Overview/`, `TabStripPanels`). Each overlay redraws on change by observing `appearance.highlight` (KVO or `UserDefaults.didChangeNotification`).
4. **Gesture toggles** gate `GestureTapRules` / the multitouch path: `gestures.option` off drops the ⌥ pinch and pan, `gestures.wallpaper` off drops the bare-wallpaper gestures. Both off means the gesture tap is not created (as when zoom is off).
5. **Onboarding gating** lives in `SetupWindowController.decideAtLaunch` (keys `onboarding.completed`, `onboarding.step`). The Phase 2 "trusted launch never flashes the window" rule still applies after completion.
6. **Status item ordering.** Newly created `NSStatusItem`s appear to the left of existing ones. Recreate the view-control items right-to-left from the Settings order on every change. Don't set `autosaveName` on them, so a user's ⌘-drag can't fight the Settings order.
7. **The update dot** is drawn into a new `NSImage` (template) from the current template glyph each time `updateGlyph()` runs: clear a 8pt circle at (15, 3), then fill a 6pt circle there.
8. **`TransomURL`** gains the `settings` entry with an optional `pane` query item, keeping the strict whitelist. `CLICommandLine` maps `transom settings [pane]` to it.
9. **The cask** can add `binary "#{appdir}/Transom.app/Contents/Helpers/transom"` so Homebrew users get the CLI (General then shows "Installed").
10. **Test count changes:** `ShortcutsModelTests` (Mouse section gone from the view, rows unchanged), `CLICopyTests` (App section), URL tests (`settings` cases), new `SettingsCopy`, `OnboardingCopy`, `UpdateCopy`, Report body privacy test, `CollapsedBlockView` label fit tests (full / one line / icon only).
