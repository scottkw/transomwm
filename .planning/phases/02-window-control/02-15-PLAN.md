Discretion choices made here (record them in the SUMMARY):
- `refusalMargin = 32` pt. A text-grid app rounds a size up by less than one cell, which is under 32 pt for any common terminal font. A real minimum that is 2-32 pt above a tile is not learned from that write. Phase 3 still gets the read-back frame, and a smaller tile later teaches it. Both sides of this blind spot go in the SUMMARY's "Known limits". The other side is that cells larger than 32 pt are not protected.
- `confirmDelay = 1 s`, which is 4 × the 250 ms settle delay. An app that applies a size late (an animation or a busy main thread) has caught up by then, and a clamped window has not moved.
- In-session hints live in the tracker. When a window learns, the tracker raises its own per-bundle hint (max per axis), so later windows of that bundle start from it. This is pure engine code, testable without AppKit, and no round trip through MinimumHintsStore is needed. PaneMacApp keeps persisting through onLearnedMinimum, as today. This is how REVIEW IN-04 is closed.
