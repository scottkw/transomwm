## Phase Goal

**As a** Mac user, **I want to** grant Pane access and have it track and move every window, **so that** no slow app or lock screen can freeze or lose them.

<objective>
Honour the Phase 1 model contract from the engine side: OS lifecycle facts reach the layout model only through `World.apply`, and every window an undo brings back is re-queried from the window system and reported with its real state.

Purpose: D-10 and D-11 (the obligation recorded in STATE.md from Phase 1 commit c403f45); the model half of WIN-09 (a window leaves the model only as `.closed`, which the window system emits only after two-source confirmation, Plan 09). Phase 3 drives its World through this type.
Output: `LifecycleSync` with tests against a real `World` and the `FakeWindowSystem`.
</objective>

<interfaces>
From PaneModel (exists, do not change): `World.apply(_ state: WindowState, for: WindowRef, on: DeskKey, history: inout UndoHistory) throws(LayoutError)` (key ignored for `.closed`); `World.undo(_ key: DeskKey, history: inout UndoHistory) throws(LayoutError) -> [WindowRef]?` (returns windows no desk held before the undo); `World.desks: [DeskKey: Desk]` (read-only); `Desk.contains(_:)`; `UndoHistory.depth(for:)`.
From 02-01: `WindowEvent`, `WindowInfo.state`, `WindowSystem.windowInfo(_:) async -> WindowInfo?` (nil only for a window never seen or confirmed closed by two sources), `FakeWindowSystem` (`addApp`, `open`, `update`, `refreshAll`, `windowInfo`).

Created here (PaneEngine, Foundation-free):
- `public struct RevivedWindows: Equatable, Sendable { public let key: DeskKey; public let windows: [WindowRef] }`
- `public enum LifecycleSync` with
  - `public static func handle(_ event: WindowEvent, world: inout World, history: inout UndoHistory) throws(LayoutError) -> Bool` (true when the World changed)
  - `public static func undo(_ key: DeskKey, world: inout World, history: inout UndoHistory) throws(LayoutError) -> RevivedWindows?`
  - `public static func requery(_ revived: RevivedWindows, using system: any WindowSystem) async -> [(WindowRef, WindowState)]` (order preserved)
  - `public static func applyRequeried(_ states: [(WindowRef, WindowState)], on key: DeskKey, world: inout World, history: inout UndoHistory) throws(LayoutError)`
  The undo path is split into sync → async → sync steps so callers that keep the World in an actor never pass actor state inout across an await.
</interfaces>

    - windowStateChanged(A, .absent) for A docked on desk K → World state of A is .absent, handle returns true, history.depth(for: K) unchanged

    - windowDestroyed(A) for docked A → A on no desk; a prior undo snapshot that contained A no longer restores it
    - windowDestroyed(B) for B on no desk but present in an undo snapshot → no throw, returns true, and undo no longer revives B

    - windowStateChanged(A, .closed) behaves exactly like windowDestroyed(A)

  </behavior>
  <action>
Per D-10. Tests first (RED), then implementation (GREEN). `handle` finds the desk holding the window by scanning `world.desks` in sorted key order. For `.windowStateChanged(ref, s)` with s != .closed: if a desk holds ref, `try world.apply(s, for: ref, on: holderKey, history: &history)` and return true; otherwise return false. For `.windowDestroyed(ref)` and `.windowStateChanged(ref, .closed)`: call `world.apply(.closed, ...)` with the holder's key, or with the smallest existing desk key, or with `DeskKey(displayUUID: "", spaceID: nil)` when the World has no desks (World ignores the key for `.closed`; document this at the call), and return true. Every other case returns false without touching the World. Never call `World.edit`. Typed throws propagate LayoutError unchanged; error and doc text names identities only, never titles.
