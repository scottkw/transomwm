# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 2's UI is small and mostly for the developer. It has four surfaces:

1. the menu-bar status item and its menu
2. the "Set Up Pane" permission window (Accessibility onboarding, stale-grant detection, Reset Permission)
3. the "Tracked Windows" debug window, a live list of tracked windows
4. two system alerts: the Freeze-test confirmation and the Reset Permission failure fallback

There is no tiling, drop preview, zoom overlay, or Settings window in this phase (Phase 3+ and Phase 9). Polish of the onboarding (Screen Recording, conflicting features) belongs to Phase 9 (SHIP-02). This contract only fixes what Phase 2 ships.

**Platform rule.** Native macOS only. Use AppKit for the shell (`NSApplication`, `NSStatusItem`, `NSMenu`, `NSWindow`, `NSAlert`). Use SwiftUI views hosted in `NSHostingController` for the two windows' content. Do not use the SwiftUI `App`, `Settings` or `MenuBarExtra` lifecycle (STACK.md, RESEARCH.md Project Constraints). Use system fonts, semantic system colours and system controls only. Phase 2 has no custom drawing, custom colours, custom fonts or custom animation.

**Clean-room rule.** Do not copy any TrellisWM text, icon or `MenuBarIcon.svg` (PLAN.md). Every string below was written fresh for Pane, and the status-item glyph is an SF Symbol.

## Spacing Scale

All values are points (pt). The token scale is the standard 4 / 8 / 16 / 24 / 32 / 48 / 64 set. The only off-scale values are the two macOS HIG metrics in Exceptions below, and they may be used only where listed.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-text gap inside a table cell (app icon → app name); gap between a badge and its neighbour |
| sm | 8pt | Gap between a status icon and its caption (spinner + "Waiting for access…"); vertical gap between numbered steps; inner padding of table badges (horizontal 8, vertical 4 → see exceptions) |
| md | 16pt | Gap between content blocks in the setup window (hero → steps → status row → callout) |
| lg | 24pt | Gap above the bottom button row in the setup window |
| xl | 32pt | Not used in Phase 2 (reserved) |
| 2xl | 48pt | Not used in Phase 2 (reserved) |
| 3xl | 64pt | Not used in Phase 2 (reserved) |

Exceptions:
- **20pt: macOS window content margin (HIG standard).** It is allowed only as the setup window's content inset on all four edges. It is not used anywhere else, and Tracked Windows uses system table insets.
- **12pt: macOS push-button gap (HIG standard).** It is allowed only in these four places:
  - between push buttons in a button row (setup window)
  - as the inner padding of a `GroupBox` callout
  - as the gap between a heading and its body in the setup window and callouts
  - as the horizontal inset of the Tracked Windows footer bar

  It is never used as a general gap.
- **Badges** ("Excluded", "Not responding") use 8pt horizontal and 4pt vertical padding with a 4pt corner radius. That is still on the 4-pt grid and is listed here only because it is the one custom-styled element.
- **Fixed sizes.** The status-item glyph is a 16pt SF Symbol, regular weight. The setup-window hero symbol is 48pt. App icons in table rows are 16×16pt. These are glyph sizes, not spacing.
- **System metrics.** Table row height, menu item height, control heights and title-bar height are system-drawn. Never override them.

## Typography

Use SwiftUI semantic styles (`.font(.title)`, `.font(.body)`, `.font(.caption)`) and AppKit `NSFont.preferredFont(forTextStyle:)`. Never call `.system(size:)` with a hard-coded size, and never set `lineSpacing`. Line heights are the system's built-in leading for each style. The ratio column records those values for the checker and auditor.

| Role | Size | Weight | Line Height | Style / where |
|------|------|--------|-------------|---------------|
| Body | 13pt | Regular (400) | 16pt (≈1.23, system leading) | `.body`: setup-window explanations and steps, table cells, menu items (menus are system-drawn at 13pt) |
| Label | 11pt | Regular (400) | 13pt (≈1.18, system leading) | `.caption`: status row captions ("Waiting for access…"), the Tracked Windows footer summary, badge text, the column header text the system draws |
| Heading | 13pt | Semibold (600) | 16pt (≈1.23, system leading) | `.headline`: callout titles inside `GroupBox` ("Already turned on?", "Couldn't reset the permission") and the empty-state heading in Tracked Windows |
| Display | 22pt | Semibold (600) | 26pt (≈1.18, system leading) | `.title` with `.fontWeight(.semibold)`: the single heading at the top of each setup-window state |

So there are 3 distinct sizes (11, 13, 22) and 2 weights (400, 600). Text colour is `labelColor` for primary text and `secondaryLabelColor` for explanations, captions and the "Untitled" placeholder. The setup window body text is left-aligned, wraps, and is never truncated (`.fixedSize(horizontal: false, vertical: true)`).

## Color

Semantic system colours only. The hex values are **reference only**: they were resolved on macOS 27.0.1 with the default appearance, and they change with appearance, Increase Contrast and macOS version. Code uses the semantic names and **never** a hex literal. Phase 2 ships no `AccentColor` asset, so the accent is the user's System Settings choice.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `NSColor.windowBackgroundColor` (ref light `#FFFFFF`, dark `#1E1E1E`) | Background of both windows; SwiftUI views leave the background unset and inherit it |
| Secondary (30%) | `NSColor.controlBackgroundColor` (ref light `#FFFFFF`, dark `#1E1E1E`) plus the system `GroupBox` fill, and the system menu material for the status menu | Tracked Windows table body; the stale-grant / reset-error callouts in the setup window (`GroupBox`, system-drawn); the status menu (system-drawn) |
| Accent (10%) | `NSColor.controlAccentColor` / SwiftUI `Color.accentColor` (user's system accent; ref default blue `#0088FF` light, `#0091FF` dark) | System-drawn only. Pane code never applies accent manually in Phase 2 |
| Destructive | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | Only on (a) the "Freeze" button of the Freeze-test alert, via `NSAlert.hasDestructiveAction` + `NSButton.hasDestructiveAction`, and (b) the `xmark.octagon.fill` icon in the reset-failed callout |

Accent reserved for exactly these elements:
1. The single default push button of each setup-window state (`.keyboardShortcut(.defaultAction)` / `.borderedProminent`): "Open System Settings", "Reset Permission" (stale form A only) or "Done"
2. Table row selection highlight in Tracked Windows (system)
3. Keyboard focus rings (system)

The accent is **not** used for icons, links, headings, badges, the status-item glyph or the progress spinner. The spinner is the system grey `ProgressView().controlSize(.small)`.

Status colours (semantic, icon or badge only, never for body text):

| Colour | Where |
|--------|-------|
| `systemGreen` (ref `#34C759` / `#30D158`) | `checkmark.circle.fill` hero icon in the Ready state only |
| `systemOrange` (ref `#FF8D28` / `#FF9230`) | `exclamationmark.triangle.fill` hero icon in stale form A; the "Not responding" badge text, on a `systemOrange` 15%-opacity fill |
| `secondaryLabelColor` | The `rectangle.split.2x1` hero icon in the not-trusted, waiting and probing states; the "Excluded" badge text, on a `quaternaryLabelColor` fill |

The status-item glyph is always a **template image** (`isTemplate = true`). It is never tinted, so the menu bar draws it correctly in light, dark, tinted and Increase Contrast modes.

## Surface 1 — Status item and menu

**Status item:** `NSStatusBar.system.statusItem(withLength: NSStatusItem.squareLength)`. The glyph is an SF Symbol template at `NSImage.SymbolConfiguration(pointSize: 16, weight: .regular)`.

| App state (from `PermissionReducer`) | Glyph | `accessibilityDescription` / tooltip |
|---|---|---|
| ready | `rectangle.split.2x1` | "Pane" (tooltip = bundle display name, so Debug shows "Pane Debug") |
| notTrusted / waitingForGrant / probing / either stale form | `exclamationmark.triangle` | "Pane: Accessibility access needed" |

A click opens the menu. There is no left/right-click split and no popover. The menu is rebuilt in `menuNeedsUpdate(_:)` / `menuWillOpen(_:)`. The frontmost app is captured at that moment from `NSWorkspace.shared.frontmostApplication`, which is still the user's app because opening a status menu does not activate Pane.

**Menu structure (top to bottom), ready state:**

| # | Item | Type | Behaviour |
|---|------|------|-----------|
| 1 | Status header, e.g. "Tracking 12 windows in 5 apps" | disabled item | Live summary; plural-correct (see Copywriting) |
| 2 | "2 apps not responding" | disabled item | Shown only when the degraded count is > 0 |
| — | separator | | |
| 3 | "Show Tracked Windows" | item | Opens or focuses the Tracked Windows window (`NSApp.activate()` then `makeKeyAndOrderFront`) |
| — | separator | | |
| 4 | "Don't Arrange “Safari”" | toggle item | `state = .on` (checkmark) when the frontmost app's bundle ID is excluded; a click toggles it in UserDefaults. App name is `localizedName`, truncated to 32 characters with "…" |
| 5 | "Never Arrange" | submenu | One item per excluded bundle ID (app name if resolvable via `NSWorkspace.urlForApplication(withBundleIdentifier:)`, else the bundle ID), each with `state = .on`; a click removes it. Empty: a single disabled item "No apps excluded" |
| — | separator | | |
| 6 | "Debug" | submenu | See below |
| — | separator | | |
| 7 | "Quit Pane" | item, key equivalent ⌘Q | `NSApp.terminate(nil)`; no confirmation |

Item 4 when the frontmost app is Pane itself, has no bundle ID, or is not `.regular` activation policy: the title is "Don't Arrange Frontmost App" and the item is disabled.

**Menu when not ready.** Item 1 shows the permission header (see Copywriting). It is followed by "Grant Accessibility Access…" in the not-trusted, waiting and probing states, or "Fix Accessibility Access…" in either stale form. That item opens and focuses the setup window. Items 3–7 stay present and enabled, because exclusions are plain UserDefaults and the Tracked Windows window shows its no-permission state.

**Debug submenu:**

| Item | Builds | Behaviour |
|------|--------|-----------|
| "Nudge Focused Window" | all | Applies `setFrame` to the frontmost app's focused tracked window. The first press moves it to (x+32, y+32) and shrinks it by 64×64pt. The next press restores the frame it had before the first press. The result is visible on the window itself and in the Tracked Windows row (frame and learned minimum). Disabled, with title "Nudge Focused Window (app excluded)", when the app is excluded. Disabled, with title "Nudge Focused Window (no window)", when there is no tracked dockable focused window |
| "Freeze “Safari” for 10 Seconds…" | Debug only (`#if DEBUG`) | Opens the Freeze confirmation alert (Surface 4). Disabled, with title "Freeze Frontmost App (not allowed)", for Pane's own pid, `com.apple.loginwindow`, Finder, Dock and SystemUIServer |
| "Resume “Safari” Now" | Debug only | Replaces the Freeze item while an app is frozen; sends `SIGCONT` immediately |
| — separator — | | |
| "Window ID lookup: available" / "Window ID lookup: off, matching by frame" | all | Disabled info item from the capability registry (SAFE-05 visibility) |

## Surface 2 — "Set Up Pane" window (WIN-01)

**Window.** `NSWindow` with `[.titled, .closable]`, title "Set Up Pane", not resizable and not miniaturizable. Content is `NSHostingController(rootView: SetupView)`. The width is fixed at 480pt and the height fits the content, so each state resizes the window to fit with no custom animation. The window is centred on the screen with the menu bar on first show. Phase 2 does not persist its position. It is shown with `NSApp.activate()` + `makeKeyAndOrderFront(nil)`.

**When it appears.** At launch, it appears only if the reducer state is not `ready`. If the user closes it, Pane never reopens it automatically. The status item stays in its attention state and "Grant Accessibility Access…" reopens it. This is the "no looping prompts" contract. When the state becomes `ready` while the window exists, the window is brought forward once (`NSApp.activate()` + `orderFrontRegardless()`) so the user sees the confirmation after returning from System Settings.

**Layout (every state).** The content inset is 20pt. A vertical stack, leading-aligned, with 16pt between blocks:

1. Hero symbol, 48pt (`.font(.system(size: 48))` is the one allowed fixed size, because it sizes a glyph), with hierarchical rendering and the colour from the state table
2. Display heading (22pt semibold)
3. Body (13pt regular, `secondaryLabelColor`), wrapping
4. Optional numbered steps (13pt regular, `labelColor`), 8pt apart, numbers rendered "1." "2." "3."
5. Optional status row: small spinner + caption (11pt, `secondaryLabelColor`), 8pt gap
6. Optional `GroupBox` callout (12pt inner padding): headline title + body + its own button
7. Button row, 24pt above it: trailing-aligned with 12pt between buttons. The default (accent) button is rightmost, secondary buttons sit to its left, and "Quit Pane" is leftmost-in-row when present

**Keyboard.** Return triggers the default button. ⌘W and Esc close the window, except while a Reset is running. Tab moves between buttons, and the focus ring is system-drawn.

**State matrix** (states come from RESEARCH.md Pattern 7's `PermissionReducer`; the copy is in the Copywriting Contract):

| State | Hero | Heading | Steps / status row / callout | Buttons (left → right; **bold** = default) |
|---|---|---|---|---|
| notTrusted (first view) | `rectangle.split.2x1`, secondary | S1 heading | Steps S1.1–S1.3 | "Quit Pane", **"Open System Settings"** |
| waitingForGrant | same | S1 heading | Steps S1.1–S1.3 + status row "Waiting for access…" (spinner) | "Quit Pane", **"Open System Settings"** (re-opens the pane) |
| waitingForGrant, 15 s after the Settings visit with no trust (stale form B) | same | S1 heading | Steps + status row + callout B with "Reset Permission" (regular button inside the callout) | "Quit Pane", **"Open System Settings"** |
| probing | same | S2 heading | Status row "Checking that Pane can reach your windows…" (spinner) | "Quit Pane" (no default button) |
| staleTrustedButFailing (form A) | `exclamationmark.triangle.fill`, systemOrange | S3 heading | Body S3 only | "Quit Pane", "Open System Settings", **"Reset Permission"** |
| resetting | same as preceding state | unchanged | Status row "Resetting permission…" (spinner); all buttons disabled | — |
| after a successful reset → waitingForGrant | `rectangle.split.2x1`, secondary | S4 heading | Body S4 + status row "Waiting for access…" | "Quit Pane", **"Open System Settings"** |
| reset failed (tccutil exit ≠ 0) | unchanged | unchanged | Callout E (`xmark.octagon.fill`, systemRed, 16pt, inline with the callout title) | "Quit Pane", **"Open System Settings"** |
| ready | `checkmark.circle.fill`, systemGreen | S5 heading | Body S5 | **"Done"** (closes the window) |

**Interaction rules:**
- "Open System Settings" opens `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` via `NSWorkspace.shared.open`. On the first click of each grant cycle (first run, or after a reset), it first calls `AXIsProcessTrustedWithOptions(["AXTrustedCheckOptionPrompt": true])` so that Pane is listed. It enters `waitingForGrant` and starts the 1 s `AXIsProcessTrusted()` poll. Pane never calls the prompting API at launch or on later clicks.
- The 15 s stale-form-B timer starts at the first "Open System Settings" click of the cycle and does not restart on later clicks.
- "Reset Permission" runs `/usr/bin/tccutil reset Accessibility <Bundle.main.bundleIdentifier>` through `Process` with a fixed argv. It shows `resetting` while running, then shows S4 on exit 0 or callout E on any other exit code. No confirmation dialog: in both stale forms Pane already can't control windows, so a reset loses nothing and the user re-grants in one step.
- Probing must resolve in at most about 5 s: 3 retries plus the frontmost-app fallback with a 1 s AX timeout. An inconclusive probe never leaves the spinner up indefinitely. `-25211` → form A; success → ready. If both probe targets time out, the probe resolves to ready and logs the inconclusive result. The UI never blocks on one slow app.
- The app display name in copy is `Bundle.main` `CFBundleName` ("Pane" or "Pane Debug"). Steps must name the exact entry the user will see in System Settings.

## Surface 3 — "Tracked Windows" window (WIN-02, 05, 06, 08, 09; SAFE-05)

**Window.** `NSWindow` with `[.titled, .closable, .miniaturizable, .resizable]`, title "Tracked Windows". Default content size 960×480pt, minimum 720×320pt. Frame autosave name `"TrackedWindows"`. Content is `NSHostingController` with a SwiftUI `Table` (macOS 12+) above a footer bar. ⌘W closes it. Closing it releases nothing and stops nothing, because tracking continues.

**Table.** Single selection is allowed and has no actions. Columns are not sortable in Phase 2. Fixed order: app `localizedName` ascending (case- and diacritic-insensitive), then window ID ascending. The order is stable across live updates, so rows don't jump when frames change. Rows update in place as `WindowEvent`s arrive, with no row animation (`.animation(nil)` / transaction disabled). Table body background is `controlBackgroundColor` with system alternating rows.

| Column | Min width | Content | Alignment |
|---|---|---|---|
| App | 160pt | 16×16pt app icon (`NSRunningApplication.icon`) + 4pt + app name, tail-truncated | leading |
| Title | 180pt (flexible) | AX title, middle-truncated, full title in `.help()` tooltip; empty or nil → "Untitled" in `secondaryLabelColor`. Titles are shown on screen only and are never logged (V7) | leading |
| ID | 72pt | CG window ID, `.monospacedDigit()`; synthetic fallback IDs show "by frame" in `secondaryLabelColor` with tooltip "Matched by frame because window ID lookup is unavailable" | trailing |
| Kind | 160pt | "Dockable", or "Never dock · <reason>" (reason vocabulary below) | leading |
| State | 88pt | "Present", "Absent", "Fullscreen" (the model's `WindowState`; `.closed` rows are removed) | leading |
| Tabs | 56pt | "3 tabs" when `tabCount ≥ 2`, else empty | trailing |
| Frame | 168pt | Top-left global points "x, y  w × h", integers, `.monospacedDigit()` | trailing |
| Display | 140pt | `NSScreen.localizedName` of the display with the largest intersection; none → "—" | leading |
| Min Size | 96pt | Learned minimum "w × h", empty if none learned | trailing |
| Status | 120pt | Badges, 4pt apart: "Excluded" (`quaternaryLabelColor` fill, `secondaryLabelColor` text), "Not responding" (`systemOrange` 15% fill, `systemOrange` text) | leading |

Never-dock reason vocabulary (maps classifier reasons from RESEARCH.md Pattern 2):

| Classifier reason | Displayed |
|---|---|
| `.floatingLevel` | "Floating" |
| `.subrole` | "Dialog or panel" |
| `.modal` | "Modal" |
| `.noCloseButton` | "No close button" |
| `.noFullscreenButton` | "No full-screen button" |

`.notAWindow` entries (such as the Finder desktop) are never rows.

**Footer bar.** 28pt tall, separated from the table by a system divider, with a 12pt horizontal inset. Leading: summary caption, e.g. "14 windows · 6 apps · 3 never dock · 1 excluded · 1 not responding". Zero-count segments after "apps" are omitted. Trailing: the capability caption, "Window ID lookup: available" or "Window ID lookup: off, matching by frame". Both use 11pt `secondaryLabelColor`.

**States** (centred in the table area as a SwiftUI `ContentUnavailableView` on macOS 14+, symbol + heading + body + optional button):

| State | Symbol | Heading | Body / action |
|---|---|---|---|
| No permission (any non-ready reducer state) | `lock.shield` | T1 heading | T1 body + button "Grant Accessibility Access…" (or "Fix Accessibility Access…" when stale), which opens Surface 2 |
| Loading (ready, first full refresh not complete, cache empty) | none; small spinner | "Looking for windows…" | — |
| Empty (ready, refresh complete, zero windows) | `macwindow` | T2 heading | T2 body |
| Populated | — | table | footer |
| Refreshing after wake/unlock (session gate) | — | table stays visible with last-known rows | footer prepends "Refreshing after wake · " until the post-resume refresh completes |

## Surface 4 — Alerts

**Freeze-test confirmation** (Debug builds only). This is the phase's one destructive action, because it `SIGSTOP`s another app.
- `NSAlert`, style `.warning`, `messageText` and `informativeText` as in the Copywriting Contract.
- Buttons: "Freeze" (rightmost, `hasDestructiveAction = true`, red, key equivalent cleared) and "Cancel" (key equivalent Return; Esc also cancels). `NSAlert.hasDestructiveAction = true`. Return never freezes.
- After confirming, the Debug submenu shows "Resume “<App>” Now" until it auto-resumes after 10 s. The frozen pid is written to UserDefaults before `SIGSTOP` and resumed at the next launch (RESEARCH.md Pitfall 8).

**No other alerts in Phase 2.** Reset Permission failure is shown inline (callout E), not as an alert. Quit, exclusion toggles and un-excluding have no confirmation, because they are instantly reversible.

## Accessibility (Pane's own UI)

- The status item button has `accessibilityDescription` per state (Surface 1 table). Every hero and status SF Symbol has an accessibility label equal to its meaning ("Ready", "Warning", "Error"), or is hidden from VoiceOver (`.accessibilityHidden(true)`) when the heading already says it. The hero symbol is hidden, and the callout E icon is labelled "Error".
- Table badges are text, not colour alone ("Excluded", "Not responding"). The colour only reinforces the text.
- All colours are semantic, so Increase Contrast, Reduce Transparency and dark mode are handled by the system. There is no custom animation, so Reduce Motion needs no handling.
- Everything is keyboard-reachable: setup-window buttons are reachable by Tab, the table supports arrow-key row navigation (system), and the status menu supports system keyboard navigation.
