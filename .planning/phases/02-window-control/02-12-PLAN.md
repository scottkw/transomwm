## Phase Goal

**As a** Mac user, **I want to** grant Pane access and have it track and move every window, **so that** no slow app or lock screen can freeze or lose them.

<objective>
Let Pane move and resize windows reliably: a coalescing, latest-wins write pipeline on each app's thread writes size → position → size with enhanced-UI mode off, reads every write back, and learns an app's real minimum size when it refuses a smaller one; a frozen app only holds its own frames.

Purpose: WIN-04 (ROADMAP SC3, movement and learning), D-16 latest-wins, D-17 write order and read-back, the in-memory half of D-13, and WIN-03 for writes.
Output: MinimumSizeLearner (+ tests), FrameWriter, frame slots in AXAppThread, AXWindowSystem.perform, the fake's refusing-size simulation, integration tests.
</objective>

  <action>
Per D-16 and D-17.

FrameWriter.write (runs only on an app thread): read the app element's `AXEnhancedUserInterface`; if true set it false; set `kAXSizeAttribute` (AXValueCreate `.cgSize`), check `isCancelled`, set `kAXPositionAttribute` (`.cgPoint`), check, set size again; read position and size back (top-left global points, no conversion); if enhanced UI was on and `reenableEnhancedUI` is true, set it back. Map AX errors with `AXFailure(code:)`; the first failure stops the sequence and is returned with whatever read-back succeeded.

AXAppThread: a `[UInt32: (rect: Rect, ref: WindowRef)]` slot dictionary plus `drainScheduled` and `drainEnabled` flags under one `OSAllocatedUnfairLock`. `enqueueFrame` overwrites the slot and, if enabled and no drain is scheduled, schedules one `CFRunLoopPerformBlock` drain and wakes the loop. The drain swaps out all slots, writes each with FrameWriter against the cached element for that id (an id with no cached element yields a `.invalidElement` result), checks the job token between writes, and yields each FrameWriteResult on `frameResults`. Setting `drainEnabled` back to true schedules a drain if slots are waiting. `reenableEnhancedUI` defaults true per bundle (a `[String: Bool]` override table, empty for now; Rectangle disabled it for Chrome, RESEARCH Pattern 5).

AXWindowSystem.perform: for `.setFrame(ref, rect)` drop and log (by `ref.description`) rects that fail `isValidGeometry`, are non-finite or exceed `Geometry.maxCoordinate`; otherwise look up the tracked info, address `visibleMemberID ?? windowID` and call `thread.enqueueFrame`. Consume each thread's `frameResults` on MainActor through `tracker.applyFrameResult` and yield the events; a `.cannotComplete` result is recorded with the ResponsivenessTracker. Keep `drainEnabled` false while a pid is degraded and true otherwise (recovery flushes the held latest frames). Other commands (park, focus, raise, setHidden) keep the 02-01 behaviour: logged and dropped, with a doc comment that Phase 3 implements them.

FrameWriteIntegrationTests (`.serialized`, `.enabled(if: IntegrationEnv.trusted, ...)`, `@MainActor`, `.timeLimit(.minutes(1))`): (a) standard fixture window, `setFrame` to (200, 200, 400, 300) → frameApplied within 1 s with actual within 1 pt of the request, and the fixture's `list` reports the same frame (independent oracle); (b) `--window minsize:250x150`, setFrame to (100, 120, 100, 80) → actual size 250×150 ± 1 and `learnedMinimum` 250×150 ± 1; (c) ten setFrames in one `perform` call to x = 100, 110, …, 190 → the fixture ends at x = 190 and at most 10 frameApplied events arrive; (d) two fixtures, A stopped with SIGSTOP, setFrame on B → B's frameApplied within 1 s; then resume A; (e) when `NSScreen.screens.count > 1`, setFrame a window onto the second display's visibleFrame and expect its displayUUID to change to that display; with one display, record that the case was not exercised (the manual UAT in 02-13 covers it).
