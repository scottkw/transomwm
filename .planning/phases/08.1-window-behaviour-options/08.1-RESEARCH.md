## Summary

**The ⌥ conflict is real, and neither the toast, nor a settings write, nor another key is the best answer.** On a default Mac, macOS 15.7.7 and 27.2 show their own tile guide about 20 ms after ⌥ goes down during a title-bar drag, and tile the window on release. Transom's tap still sees everything, so both systems act. A docked window flies to macOS's tile and then back to Transom's about a second later. A floating window released where Transom would leave it is tiled by macOS, and macOS wins. That makes UI-SPEC N20 (toast only) a warning about a broken mode.

**A better fix was measured: Transom's active tap removes `.maskAlternate` from the events it passes while a Hold ⌥ title-bar move is live.** With that, macOS draws no guide and does not tile on either OS, the window keeps following the pointer, and Transom has already read ⌥ for itself. This writes no user setting, keeps D-07's ⌥, and needs no dialog. It held for events posted to the HID tap on both OSes, and for input through the VM's virtual HID devices on 27.2. Recommend it and drop N20. If the host UAT disagrees, fall back to writing `EnableTilingOptionAccelerator` false, which also measured clean and takes effect without a restart.

**The rest is small and fits existing paths.** ⌃ and ⌃⌘ reach the tap unchanged and do not disturb the drag. A new `DropTarget.fourth` case carries fourths through the existing hover, dwell, dry run, preview, `commitDock`, undo and collapse paths. `insertLeaf` and `setWeights` do the tree edits. Auto-tiling belongs in the `.windowCreated` branch after `fillPlaceholders` and before `admit`. It also needs one new fact from the tracker, because `.windowCreated` alone does not mean new: it fires for the launch sweep and for old windows first seen after a Space switch.

**Primary recommendation:** Strip ⌥ in the tap during Hold ⌥ moves, add `DropTarget.fourth(FourthSlot, Axis)`, and add `WindowInfo.openedWhileRunning` set by `WindowTracker`.

### The rule

Strip while `drag.kind == .move`, and either the mode is Hold ⌥, or ⌃ is in the event's flags. The second part is because UI-SPEC rows 2–3 let ⌥ be held with ⌃ in both modes, and S9 shows macOS would tile. In Automatically mode with no ⌃, nothing is stripped, so default behaviour is unchanged.

```swift
// Sources/TransomMac/Input/DragOptionRule.swift (new). Pure, like GreenButton, so the callback stays a lookup.
// `DragOptionStrip` lives in TransomEngine, because the Arranger names it: enum DragOptionStrip { case off, always, withControl }
nonisolated enum DragOptionRule {
    static func strips(type: CGEventType, flags: CGEventFlags, state: DragOptionStrip) -> Bool {
        guard flags.contains(.maskAlternate), [.flagsChanged, .leftMouseDragged, .leftMouseUp].contains(type) else { return false }
        switch state {
        case .off: return false
        case .always: return true
        case .withControl: return flags.contains(.maskControl)
        }
    }
}
```

In `InputTap`'s callback, just before the final return, after `TapEvent` has copied the original flags so Transom still sees ⌥ (`Sources/TransomMac/Input/InputTap.swift:184-185`). Every mouse-down clears the state on the tap thread, so a lost mouse-up can't leave stripping on, the same idea as `ZoomTapRules.decide`:

```swift
if type == .leftMouseDown { box.dragOption.withLock { $0 = .off } }
box.continuation.yield(TapEvent(type: type, location: location, flags: event.flags, windowUnderPointer: window, clickState: clickState))
if DragOptionRule.strips(type: type, flags: event.flags, state: box.dragOption.withLock { $0 }) {
    event.flags.remove(.maskAlternate)
}
return Unmanaged.passUnretained(event)
```

The engine says when:

```swift
// Arranger. nil session or not a move: off. The shell publishes this after every pointer and dragFrame input.
public var dragOptionStrip: DragOptionStrip {
    guard drag?.kind == .move else { return .off }
    return dragToDock == .holdOption ? .always : .withControl
}
```

Publish with `tap.setDragOption(arranger.dragOptionStrip)` after `arranger.handle(.pointer…)` and `.dragFrame`, and on a mode change. `InputTap.setGreenButtons` is the pattern for the lock. The rule is not gated on the OS: macOS 14 has no ⌥ tiling, so removing the flag there changes nothing for a title-bar move. `[ASSUMED: macOS 14 was not run; pane-test is 15.7.7 and pane-test-27 is 27.2.]`

**Conclusions:**
- ⌃ and ⌃⌘ pressed after the drag starts reach the tap unchanged and don't disturb the drag, so D-18 stands.
- A press with ⌃ down never becomes a move: the window doesn't move, `session.kind` stays nil, and no hover runs. Tab strips are already safe, because `ArrangeController` passes no `pressTab` when ⌃ is down: `let tab = strip.flatMap { event.flags.contains(.maskControl) ? nil : tabStripPanels.member(atWindowNumber: $0, point: location) }` `[VERIFIED: Sources/TransomMac/ArrangeController.swift:452-453]`. So UI-SPEC's "ignored until released and pressed again" could not be reached in any measured app. Keep it as a three-line guard for apps that move their own windows: `DragSession` stores `controlAtPress`, `hover` ignores ⌃ while it's set, and an event without ⌃ clears it. One engine test covers it; no VM check needed.
- Sticky Keys stays a backstop for host UAT; nothing here measures it.

**Chords:** every ⇧⌃⌥⌘ digit is free of macOS symbolic hot keys on both OSes, by `CopySymbolicHotKeys`, the same source `isTakenBySystem` uses (228 entries on 15.7.7, 233 on 27.2, matching on keycode and all four modifiers). `[VERIFIED: measured with tileprobe hotkeys]` Still extend `logSystemConflicts` to the ten names, as the UI-SPEC says, because users add shortcuts.

### The arithmetic

Span by slot, along the axis, 0 being the left edge or the top: `first` [0, ¼], `second` [¼, ½], `third` [½, ¾], `fourth` [¾, 1], `middle` [¼, ¾].

1. Take the window out first. A docked window's removal may collapse the root, which can change whether the root runs the same way: `[W, V(vertical)]` horizontal becomes root `V`, and a column then wraps it.
2. `children` = the root's children if it splits on the axis, otherwise `[root]` as one child.
3. Only children taking part count for position (see below). A child's centre is `(sum of earlier weights + own/2) / total`, over the taking-part children.
4. Position `pos = (start + end) / 2`. Insertion index: if `start == 0`, 0; else if `end == 1`, after the last; else the first taking-part child whose centre is not `< pos - 1e-9`, or after the last. A side with no space can't hold a tile, so 1st is always first and 4th always last.
5. If nothing is before, `start = 0`. If nothing is after, `end = 1`. That is the "grows into that space" rule.
6. Window share = `end - start`. Children before share `start` by their stored weights. Children after share `1 - end` by theirs.

**The tie:** D-14 says "centred before … go before it and the rest go after", so a tile exactly at `pos` goes after. That only matters for `middle`.

### The table (checked with exact fractions)

W is the new window, D the Desktop tile. These are stored weights, not pixels.

| Before, in root order | 1st | 2nd | 3rd | 4th | Middle |
|---|---|---|---|---|---|
| **0 docked:** `[D]` root is a leaf | `[W ¼, D ¾]` | `[W ½, D ½]` | `[D ½, W ½]` | `[D ¾, W ¼]` | `[W ¾, D ¼]` |
| **1 docked:** `[A ½, D ½]` | `[W ¼, A ⅜, D ⅜]` | `[A ¼, W ¼, D ½]` | `[A ½, W ¼, D ¼]` | `[A ⅜, D ⅜, W ¼]` | `[A ¼, W ½, D ¼]` |
| **2 docked:** `[A ⅓, B ⅓, D ⅓]` | `[W ¼, A ¼, B ¼, D ¼]` | `[A ¼, W ¼, B ¼, D ¼]` | `[A ¼, B ¼, W ¼, D ¼]` | `[A ¼, B ¼, D ¼, W ¼]` | `[A ¼, W ½, B ⅛, D ⅛]` |
| **3 docked:** `[A .6, B .2, C .1, D .1]` | `[W ¼, A .45, B .15, C .075, D .075]` | `[A ¼, W ¼, B ¼, C ⅛, D ⅛]` | `[A ½, W ¼, B ⅛, C 1/16, D 1/16]` | `[A .45, B .15, C .075, D .075, W ¼]` | `[A ¼, W ½, B ⅛, C 1/16, D 1/16]` |

Other required cases:

| Case | Result |
|---|---|
| **Nesting:** `[L ½, R(vertical c, d) ½]`, 2nd column | `[L ¼, W ¼, R ½]`; `R` moves as one child and its inner weights are bit-identical |
| **Opposite axis:** `[T ½, B ½]` vertical, 1st column | New horizontal root `[W ¼, (T, B) ¾]` |
| **Opposite axis:** same, 3rd column | `[(T, B) ½, W ½]`: the layout is centred at ½, before ⅝, and W grows to the edge |
| **Opposite axis:** same, middle column | `[W ¾, (T, B) ¼]`: tie goes after, so W grows into the empty side |
| **Docked window moving:** `[W ⅓, A ⅓, D ⅓]`, 4th | Remove first: `[A ½, D ½]`. Then `[A ⅜, D ⅜, W ¼]` |
| **Same-axis collapse:** `[W, V(vertical a, b)]` horizontal, 1st column | Remove first: root is `V`. Wrap: `[W ¼, V ¾]` |
| **Tab group:** any | `Node.tabs` passes through `insertLeaf`; the group's `TabBand` is resolved inside its leaf and it stays one child |
| **Only docked window, Desktop hidden** | `removeLeaf` shows the Desktop again when nothing stays docked (`TreeEdits.swift:131`), so the result is the "0 docked" row with the Desktop now visible. Not re-hidden, since hiding it again would make the window fill the screen and the fourth meaningless |
| **Hidden Desktop with other docked windows** | The Desktop takes no part. It keeps its stored weight and the others scale into the rest. Same for a child whose windows are all minimised or waiting |
| **Root already has `maxChildren`** | `adding` throws `.splitFull`; handle it as a refusal |
| **Tree at `maxDepth`** | Wrapping throws `.tooDeep` from `validate`; handle it as a refusal |
| **Below minimum sizes** | `resolve` water-fills, so frames can differ from weights. `Planner.plan(...).unfit` then decides: collapse with zoom on, refuse with zoom off (D-16) |

**Pixels:** a fourth isn't exactly a quarter of the screen, because `resolve` takes gaps off before sharing. With gap 8 on a 1024-wide display, `[A ½, D ½]` gives width 500, matching T2's measured `8,38 500x665`. Four children give `(1024 - 16 - 24) / 4 = 246`. Table-test weights exactly, and frames only through `resolve`.

### Code

```swift
// Sources/TransomModel/Fourths.swift (new)
public enum FourthSlot: String, CaseIterable, Hashable, Sendable {
    case first, second, third, fourth, middle
    var span: (start: Double, end: Double) {
        switch self {
        case .first: (0, 0.25)
        case .second: (0.25, 0.5)
        case .third: (0.5, 0.75)
        case .fourth: (0.75, 1)
        case .middle: (0.25, 0.75)
        }
    }
}

public enum FourthZones {
    /// UI-SPEC Surface 3: five bands in order along the axis of `visible`, the pointer clamped into it.
    public static func slot(at point: Point, in visible: Rect, axis: Axis) -> FourthSlot {
        let raw = axis == .horizontal ? (point.x - visible.minX) / visible.width : (point.y - visible.minY) / visible.height
        let p = min(max(raw, 0), 1)
        if p < 0.25 { return .first }
        if p < 0.375 { return .second }
        if p < 0.625 { return .middle }
        if p < 0.75 { return .third }
        return .fourth
    }
}

extension LayoutTree {
    /// D-14. The caller has already taken the window off the desk; `node` is its panel or tab group.
    public mutating func insertFourth(
        _ node: Node, states: [WindowIdentity: WindowState], slot: FourthSlot, axis: Axis, ids: inout IDSource
    ) throws(LayoutError) {
        guard let root else { return try insertRootLeaf(node, states: states, ids: &ids) }
        let (children, weights): ([NodeID], [Double]) =
            if case let .split(rootAxis, c, w)? = nodes[root], rootAxis == axis { (c, w) } else { ([root], [1]) }
        let (index, shares) = Self.fourthShares(
            weights: weights, takesPart: children.map(takesPart), span: slot.span)
        var next = self, nextIDs = ids
        let leading: Edge = axis == .horizontal ? .left : .top, trailing: Edge = axis == .horizontal ? .right : .bottom
        if index < children.count {
            try next.insertLeaf(node, states: states, at: leading, of: children[index], ids: &nextIDs)
        } else {
            try next.insertLeaf(node, states: states, at: trailing, of: children[children.count - 1], ids: &nextIDs)
        }
        guard let newRoot = next.root else { throw .invariantViolated("a fourth left no root") }
        try next.setWeights(in: newRoot, shares)
        self = next
        ids = nextIDs
    }
}
```

`fourthShares` is a private static pure function implementing steps 3–6 and returns `(index, shares)` with the window's share at `index`. It is what the table tests hit, through `insertFourth`. `takesPart(_:)` mirrors `Solver.aggregate`: a panel while its window is `.present`, tabs while the selected member is, the Desktop while not hidden, a split while any child does. Recursion is fine because validated trees are at most `maxDepth` deep. Non-participants keep their stored weight, and the rest scale into `P = 1 - Σ non-participants`. Floor the window's share at `minWeight`, since `setWeights` needs values above 0.

Inserting at a leading edge of `children[index]` always hits rule 1 when the root is the same-axis split, and rule 3 when `children == [root]`, so one call covers both.

### `.windowCreated` does not mean new

The tracker reports `.windowCreated` for every window it first sees, including the launch sweep (`WindowTracker.swift:181-185`), and an app's old windows first listed after a Space switch, because AX lists only what's shown (`Arranger+Placeholders.swift:5`). ### `autoTile`

Guards, first failure returns nothing and the window floats:

## Finding 5: The drag `release` path

### What today's path does

`release(now:)` calls `endDrag()` first, then `let action = kind == .move ? session.current?.action ?? .miss : .miss` `[VERIFIED: Sources/TransomEngine/Arranger.swift:1837-1869]`. No decision held means `.miss`, a snap back for a docked window.

### What the plain drag needs

Decide at mouse-up, **before** `endDrag()`, because `undockPlan()` reads `drag` (`Arranger.swift:2060`) and `endDrag` clears it, along with the cached `dragPlans`:

## Common Pitfalls

### Pitfall 1: Old windows auto-tile after a Space switch
**What goes wrong:** Switching to a Space with windows opened before Transom started docks them all.
**Why:** `.windowCreated` fires at first sight, and AX only lists what's shown.
**How to avoid:** `openedWhileRunning`. **Warning sign:** a tracker test where a non-initial observation with a low ID reports `true`.

### Pitfall 2: `undockPlan` returns nil at mouse-up
**What goes wrong:** Every plain drag of a docked window shows Blocked or refuses.
**Why:** `endDrag()` clears `drag`, and `undockPlan` needs it.
**How to avoid:** Decide before `endDrag()`. **Warning sign:** a Hold ⌥ engine test releasing inside the dwell fails.

### Pitfall 3: The no-change beep never fires
**What goes wrong:** Repeating ⇧⌃⌥⌘1 pushes undo steps and shows nothing.
**Why:** New leaf NodeIDs make `Resolution`s differ.
**How to avoid:** Compare `plan.frames` in the fourth path.

### Pitfall 4: Finder Split lands wrong with New Windows: Tile
**What goes wrong:** ⌃⌥⌘N's window goes beside the focused tile rather than the tile asked for, or `takeFinderWindow` finds it already docked and does nothing.
**How to avoid:** `autoTile` skips a window `finderExpectation` will take. Test both orders.

### Pitfall 5: The new window is its own "focused tile"
**What goes wrong:** No focused tile found, so it always splits the largest.
**Why:** `.windowFocused` can arrive before the delayed `.windowCreated`.
**How to avoid:** Skip the new window's own identity in `focusOrder`.

### Pitfall 6: A tie's window auto-tiles and takes the tile's place
**What goes wrong:** A new window that may still fill a waiting tile docks somewhere else.
**How to avoid:** The `placeholders.fresh` guard. After a tie resolves or expires, the window stays floating.

### Pitfall 7: Stripping stuck on
**What goes wrong:** ⌥ stops working for the next click if a mouse-up was lost.
**How to avoid:** Clear on every mouse-down on the tap thread, and publish `.off` from `endDrag`'s path. **Warning sign:** `DragOptionRule` tests pass but no test covers a down with stale state.

### Pitfall 8: Zoomed-in fourths land out of view
**What goes wrong:** A window docks at the desk's root, outside the current view, and is parked.
**Why:** Nothing calls `widen` on these paths today.
**How to avoid:** Call it; test in `ArrangerCameraTests`.

### Pitfall 9: `scripts/vm-cli-check.sh`
It deletes the host's Debug bundle, which the user may be running. Don't use it for this phase's checks. Use `scripts/vm-live-test.sh` with `TRANSOM_VM=pane-test-27`.

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| A web page opens `transom://dock-column-1` repeatedly | Tampering, Denial of Service | Allow-list, one per second per command (`TransomURLRateLimiter`). Worst case: one undoable layout change. It acts on the frontmost app's focused window, as Move Window would |
| The tap reads or changes input beyond its purpose | Information Disclosure, Tampering | Mask stays left-button and `flagsChanged`, so no typed characters (T-03-28). The strip removes one modifier bit, only during a `.move` session, and logs nothing |

| A user-writable plist sets a bad mode | Tampering | `GapPreference` rule |
| Auto-tile moves a window that isn't the user's new one | Tampering (layout) | `openedWhileRunning`, one undo step, fail-safe float |

No new private API, entitlement or persisted format. `WindowInfo` isn't persisted, and `openedWhileRunning` is session-only.
