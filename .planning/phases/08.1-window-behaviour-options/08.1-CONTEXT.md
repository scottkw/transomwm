# Phase 8.1: Window Behaviour Options - Context

**Gathered:** 2026-11-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Give the user three things: a choice to tile new windows automatically, a choice to show docking regions only while a key
is held, and docking to fourths or the middle half, as columns or rows, by keyboard or by dragging. Today's behaviour
stays the default for both choices.

Requirements: TILE-21, TILE-22, TILE-23.

Out of scope: the Settings window (Phase 9 shows these options later), per-app rules for new windows, fourths on nested
tiles, and changing today's snaps for floating windows.

</domain>

<decisions>
## Implementation Decisions

### New windows (TILE-21)
- **D-01 (user):** The option is "New Windows: Float / Tile". Float is the default and keeps TILE-07.
- **D-02 (user):** A new window lands beside the focused tile, splitting it along its longer side.
- **D-03:** With no focused docked tile, the window splits the largest tile. On a desk with nothing docked, it docks as
  the first tile beside the Desktop tile.
- **D-04 (user):** Dialogs, panels, excluded apps and anything too small to tile never auto-tile. They float.
- **D-05:** Only windows that open while Transom runs count. Windows found at launch, windows that fill a waiting tile
  (Phase 8) and restored windows are not new: re-matching runs first.
- **D-06:** Auto-tiling is one undo step. If the window can't fit, the existing rule applies: collapsed block with zoom on,
  and with zoom off it stays floating, with no beep or notice, because nothing the user did was refused.

### Drag behaviour (TILE-22)
- **D-07 (user):** The option is "Drag to Dock: Automatically / Hold ⌥". Automatically is the default and is exactly today's
  behaviour, including ⇧ and ⌘.
- **D-08 (user):** In Hold ⌥ mode, a plain drag pulls a docked window out to floating at its release frame, and just moves a
  floating window, with no regions shown. Holding ⌥ shows the regions and docks. ⇧ still floats. ⌘ still swaps.
- **D-09:** ⌥ can be pressed or released during a drag, and the regions follow, as ⇧ does today. Tab grouping by dwelling on
  a centre needs the regions, so in Hold ⌥ mode it needs ⌥ too. Dragging a tab out of a strip follows the same rule.
- **D-10 (user, recommended by Claude, may revisit):** Drag docking is not removed. Keyboard docking works in both modes.

### Fourths (TILE-23)
- **D-11 (user):** Fourths come as columns and as rows: 1st, 2nd, 3rd, 4th and middle half.
- **D-12 (user):** Available by keyboard and by dragging.
- **D-13 (user):** Windows already docked shrink to fit. Nothing is replaced or floated.
- **D-14:** A fourth is a share of the whole desk, at the desk's root. Tiles centred before the new window's position go
  before it and the rest go after, each side sharing the space left on that side. If one side has no tile, the window grows
  into that space, so the layout never has a hole. The Desktop tile counts as a tile. If the root split runs the other way,
  the existing layout becomes one child of a new root.
- **D-15:** Works on a floating window (docks it) and on a docked window (moves it). A tab group moves whole. One undo step.
- **D-16:** With zoom on, a fit that goes below minimum sizes collapses as usual. With zoom off it is refused with today's
  notice and beep. Weights stay editable afterwards like any other split; nothing remembers "a fourth".
- **D-17:** Default chords, all rebindable: ⇧⌃⌥⌘1–4 for columns and ⇧⌃⌥⌘5 for the middle-half column, then ⇧⌃⌥⌘6–9 for rows and
  ⇧⌃⌥⌘0 for the middle-half row. The commands also go in menu ▸ Arrange and in `transom://` and the CLI as allow-listed
  commands, because every command is reachable from all of these (D-06 of Phase 8).
- **D-18:** Dragging: hold ⌃ during a drag for columns, and ⌃⌘ for rows. The screen becomes the 4 regions, with a middle-half
  region over the centre, and the preview shows the result. ⌃ works in both drag modes. ⌃ must go down after the drag starts,
  because ⌃-click is a right click; the README says so.

### Where the options live
- **D-19 (user):** Two items in menu ▸ Arrange, and in UserDefaults, like the other preferences. Phase 9's Settings shows
  them too. They survive a relaunch. They apply at once and need no confirmation.

### Claude's Discretion

- The exact middle-half hit area for D-18, and the command names.
- Fourth arithmetic and which tree edits do D-14, as long as table tests cover 0, 1, 2 and 3+ existing tiles, nesting, and
  the opposite root axis.

</decisions>

<post_research_decisions>
## Decisions after research and the UI spec (2026-11-04, by Claude; raised with the user)

- **D-07a:** macOS's own ⌥ tiling is defeated without writing any setting: during a Hold ⌥ move session the event tap copies the flags for Transom, then removes `.maskAlternate` from `flagsChanged`, `leftMouseDragged` and `leftMouseUp`. Measured on 15.7.7 and 27.2 through posted events and virtual HID. If host UAT shows macOS's outline on real hardware, the decided fallback is for Turn Off to write `EnableTilingOptionAccelerator`. Toast N20 is dropped.
- **D-08a:** In Hold ⌥ mode a plain drag of a docked window pulls it out only after 16 pt of travel; below that it snaps back. The 3 pt minimum stays everywhere else. This keeps a small nudge from floating a window, the reverse of the user's complaint.

## Decisions after code review (2026-11-05)

- **D-06a:** A first window whose minimum is unknown can dock, show in the tile for about a second, then float silently (zoom off) or collapse (zoom on). Its undo step stays. Known limit: macOS can't report a minimum before docking.
- **D-20 (user):** A window opening during a press or gap drag joins no desk until the gesture ends, then floats, in every mode including Tile. It can't change the drag's result.
- **D-21 (user):** Two more fixes apply in every mode: the window focused at launch counts as focused, so a tie, swap or view navigation can go to it; and a session switch ends a drag in progress. This narrows success criterion 3, "behaviour is the same", and the user accepted that.
- **D-22:** In Tile mode, a new window on a Space not showing, or first seen under a sheet, floats. Both are the safe result under D-04.
- **D-23 (user, after host check 3):** A fourth's capsule and success announcement name what the window actually gets, on every route. Placement and the zone guides don't change (D-14 still grows a window into an empty side). A span equal to the slot's own keeps its name ("2nd row"); otherwise [0, .5] is "Top half" / "Left half", [.5, 1] "Bottom half" / "Right half", [0, .75] "Top three quarters" / "Left three quarters", [.25, 1] "Bottom three quarters" / "Right three quarters", and [0, 1] "Whole desk". The span comes from the arithmetic `insertFourth` uses (`LayoutTree.fourthSpan`). Menu items, the Shortcuts window and `transom help` keep "2nd row" and so on: they name the command, not the outcome. No layout reaches [.25, 1] today, because the last tile's centre is never before the 2nd or middle slot's. Its label is there anyway, so a change to the arithmetic can't produce a wrong one.
- **D-24 (user, after host check 1):** "Clear Waiting Tiles" in menu ▸ Arrange closes the placeholders on the desks now showing, through the path expiry uses (`expirePlaceholders`), so their tiles close as if their windows had closed. Greyed when no placeholder is on a shown desk. Announced once: "Cleared 1 waiting tile" or "Cleared {n} waiting tiles". As with expiry it adds no undo step, and the closed window is forgotten from the undo history, so no undo brings its tile back. Tiles on hidden desks keep waiting (D-12b), and a floating saved window has no tile to clear. Menu only: no hotkey, URL or CLI command, so it is an `ArrangerInput`, not a `Command`, and the URL allow-list doesn't change. A later reopen of that app floats, the usual result after a tile closes.
</post_research_decisions>
