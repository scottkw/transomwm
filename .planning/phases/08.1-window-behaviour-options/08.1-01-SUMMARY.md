# Phase 8.1 Plan 01: Hold ⌥ Drag Summary

**Hold ⌥ on real windows: a plain drag pulls a docked window out from 16 pt of travel, and pressing ⌥ mid-drag docks, with macOS's ⌥ tiling kept away by removing ⌥ from the events the tap passes on. Proved in the VM on macOS 27.2 and 15.7.7.**

## Accomplishments

- A plain drag in Hold ⌥ mode floats a docked window at its release frame, one undo step, announced "Floating", with no regions, even inside the 150 ms dwell. Under 16 pt from the press it snaps back. A floating window just moves.
- ⌥ pressed during the drag gives the Phase 3 hover and docks. No `Drag Guide Window` appeared in any Hold ⌥ sample on either OS, and the frames sampled after release were each at the release frame or the tile.
- Automatically mode is untouched: `ArrangerDragTests` and `ArrangerTabsTests` have no diff from 604f28e, and its ⌥-drag still shows macOS's guide on both OSes, which also proves the scan can see the guide.
- The strip can't get stuck or stay lost: the tap clears it on every mouse-down, and every Arranger change writes it back.

## Decisions Made

- Travel is the distance from the press at the last drag sample. `.up` doesn't update `session.pointer`, as today, so a mouse-up far from the last drag event would be measured at that event. Real input sends them together.
- `publishDragOption` has no cache, as the plan requires. The mutant above shows the live test catches one.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Test] The live plain drag goes one tile's width right and 25 pt down, not 120 pt down and right**
- **Found during:** Task 1, first VM run
- **Issue:** On the VM's 1024 pt display, a 120 pt drag leaves the release frame crossing window 0's reflowed tile, so it is rightly clamped into the Desktop tile (UI-SPEC plain-drag table), and the test's "near the last polled frame" failed. The window had floated and undo worked.
- **Fix:** The test drags into the space that stays Desktop, and an engine test, `aPlainDragThatWouldCrossATileClampsAndAnnounces`, pins the clamp row.
- **Files modified:** `HoldOptionIntegrationTests.swift`, `ArrangerHoldOptionTests.swift`
- **Commit:** `a1943aa`

**2. [Rule 1 - Test] The live ⌥ drag ends a screen-width eighth in, not 12 pt from the screen edge**
- **Found during:** Task 2, first VM run
- **Issue:** With the pointer 12 pt from the edge, macOS drew its guide and the window went to `0,30 512x682` before reaching Transom's tile, although the strip was on (`hid` had ⌥, `combined` didn't). Moving the same drag clear of the edge removed both. The likely cause is macOS's edge tiling (RESEARCH E1), which ⌥ has no part in. The run didn't isolate it further.
- **Fix:** `leftBand` is `visible.minX + visible.width / 8`, still in the Desktop tile's left band.
- **Files modified:** `HoldOptionIntegrationTests.swift`
- **Commit:** `089c48e`

**3. [Rule 3 - Blocking] `LiveArrange.start` pauses the previous test's controller**
- **Found during:** Task 2
- **Issue:** A controller from an earlier test in the same process leaves its gap handle panels on screen at layer 3. One sat under the next test's press point, so the window never moved and the press was never a move. `titleBar`'s topmost check looks at layer 0 only, so it didn't catch this.
- **Fix:** `start` calls `setPaused(.user, true)` on the last controller, which hides its handles.
- **Files modified:** `LiveDrag.swift`
- **Commit:** `089c48e`

**4. [Rule 1 - Bug] `Modifiers` doc comment**
- **Found during:** Task 2
- **Issue:** It said only ⇧ and ⌘ change a drop, which is no longer true in Hold ⌥ mode.
- **Fix:** Updated, as UI-SPEC planner note 4 asks.
- **Files modified:** `DragSession.swift`
- **Commit:** `089c48e`
