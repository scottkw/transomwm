# Phase 8.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 8.1 adds two options, a Hold ⌥ drag mode and docking to fourths or the middle half (TILE-21, TILE-22, TILE-23). It **extends** `03-UI-SPEC.md`, `04-UI-SPEC.md`, `07-UI-SPEC.md` and `08-UI-SPEC.md` and keeps every token, timing, panel property, colour recipe, copy rule and announcement pattern from them. Where this spec says "Phase 3 Surface N", that surface applies unchanged.

Phase 8.1 adds five surfaces, none of them a new visual system:

1. **options**: "New Windows" and "Drag to Dock", two items in menu ▸ Arrange (D-01, D-07, D-19)
2. **Hold ⌥ drags**: what a drag shows and does in Hold ⌥ mode (D-08, D-09)
3. **fourth regions**: the regions and result preview while ⌃ or ⌃⌘ is held, in the existing preview panel (D-18)
4. **fourth commands**: menu entries, hotkeys and Shortcuts rows for the ten commands (D-11, D-15, D-16, D-17)
5. **URLs and CLI**: ten allow-listed commands and their help lines (D-17)

Not in this phase: the Settings window (Phase 9 shows the two options later), per-app rules for new windows, fourths on nested tiles, any change to today's snaps for floating windows, a keyboard, URL or CLI way to form a tab group, and any new alert or confirmation. Both options apply at once and ask nothing (D-19).

**Default behaviour is unchanged.** With "New Windows: Float" and "Drag to Dock: Automatically", a drag with no ⌃ held behaves exactly as Phases 3 and 7 specify. ⌃ was carried and ignored before; it now shows fourths in both modes (D-18). Three post-review fixes apply in every mode, accepted by the user: the window focused at launch counts as focused, a window opening during a gesture waits and floats, and a session switch ends a drag in progress (D-20, D-21).

**Platform rule (unchanged).** Native macOS only. Shell = AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`). Overlays = layer-backed AppKit views drawn with Core Animation. Every colour is a semantic system colour. Every font is a system text style. The CLI writes plain ASCII to a terminal.

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom.

**Spelling.** UI strings use US English. Planning prose may stay British.

**Vocabulary added by this spec.**
- **Fourth** (UI copy, in the menu title): one of four equal shares of the whole desk, as a column or a row (D-14). "1st" is the leftmost column or the top row.
- **Middle half** (UI copy): the central half of the whole desk, as a column or a row.
- **Zone** (this spec, never in UI copy): the part of the display that picks one of the five results while ⌃ or ⌃⌘ is held.
- **Result preview** (this spec, never in UI copy): the accent rect showing the exact frame the window gets on release.
- **Pull out** (this spec, never in UI copy): a docked window becoming floating. UI copy says "floating".

## Color

Semantic system colours only, no hex literals in code. Hex values are references resolved on macOS 27 with the default appearance. `PreviewPresenter` already re-resolves `CGColor`s on appearance, accent and accessibility changes; the guides go through the same path.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | The user's windows and wallpaper | Transom adds no opaque surface |
| Secondary (30%) | `labelColor` 8% fill with `labelColor` 50% dashed border (the existing ghost recipe) for zone guides; system-drawn menus | Neutral: guides say "the screen is divided" without competing with the result |
| Accent (10%) | `NSColor.controlAccentColor` (ref default `#0088FF` light, `#0091FF` dark) | Only the elements listed below |
| Destructive / refusal | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | Only the existing Blocked preview, on a fourth that doesn't fit with zoom off. No new use. Phase 8.1 has no destructive action |
| Warning | `NSColor.systemOrange` | Not used (stays N7 / N11 only) |

Accent reserved for exactly these elements:
1. Every Phase 3, 4, 6 and 7 use, unchanged (drop preview, swap origin, gap handles, rect-zoom target preview, pick-mode ring, collapsed-block hover ring, overview selection ring, Group drop preview, system-drawn uses)
2. The **result preview** of a fourth, which is a drop preview. Its recipe is `.dock`'s. Nothing else new: the zone guides, the menu items and the Shortcuts section have no accent, except the `Recorder`'s own recording state (system-drawn)

**Overlay colour recipe (new rows).** Alpha is applied to the colour.

| Element | Fill | Border | Content |
|---|---|---|---|
| Zone guide | `labelColor` 8%, 12pt radius (`PreviewStyle.ghost`) | `labelColor` 50%, 2pt, dashed 8/4 | none |
| Result preview, fits | accent 20%, 12pt radius (`.dock` recipe) | accent 85%, 2pt solid | capsule "1st column" etc., no glyph |
| Result preview, zoom on and windows collapse | `.collapsed` recipe, unchanged | unchanged | `CollapseCopy` label, unchanged |
| Result preview, no room and zoom off | `.blocked` recipe, unchanged | unchanged | "Not enough room", unchanged |

**Increase Contrast**: `PreviewStyle.contrasted` applies to guides too (fill alpha × 1.5, border opaque). **Differentiate Without Color**: guides differ from the result by a dashed border and no label; Blocked keeps its label and glyph. **Reduce Transparency**: guides and result are tints, not materials.

## Surface 1 — Options (TILE-21, TILE-22, D-01, D-07, D-19)

**Where.** The last two items of the Arrange section, directly after Gaps ▸, in this order. No separator. Like Gaps ▸, each is a titled item with a radio-list submenu, rebuilt each time the menu opens.

| Top-level title (current value) | Submenu radio items (✓ on the current one) | Default | UserDefaults key and values |
|---|---|---|---|
| "New Windows: Float" / "New Windows: Tile" | "Float", "Tile" | Float | `newWindows`: `"float"`, `"tile"` |
| "Drag to Dock: Automatically" / "Drag to Dock: Hold ⌥" | "Automatically", "Hold ⌥" | Automatically | `dragToDock`: `"automatic"`, `"holdOption"` |

**Tooltips** on the radio items (`NSMenuItem.toolTip`, as the conflict items do):

| Item | Tooltip |
|---|---|
| Float | "New windows float on the Desktop tile until you dock them." |
| Tile | "New windows dock beside the focused tile. Dialogs, panels and excluded apps still float." |
| Automatically | "Docking regions show on every drag." |
| Hold ⌥ | "A drag moves the window and leaves it floating. Hold ⌥ to show docking regions." |

**Behaviour.**

| Situation | Result |
|---|---|
| A choice is clicked | Saved to UserDefaults, applied at once, no confirmation (D-19). The menu closes. Announcement per Accessibility. Choosing the current value does nothing and announces nothing |
| Paused, or Accessibility not ready | Both stay enabled, like Gaps ▸. Nothing moves until Resume |
| Stored value missing | The default |
| Stored value not one of the two strings | The default replaces it and an error is logged (`GapPreference` rule). Never a crash, never a silent partial value |
| Choosing "New Windows: Tile" | Windows already floating stay floating. Only later windows count (D-05) |
| Choosing "Drag to Dock: Hold ⌥" | Nothing moves |
| Relaunch | Both come back from UserDefaults (success criterion 4) |

The two options are **preferences, not `Command`s**: no hotkey, URL or CLI command, like Gaps ▸ and Restore macOS Window Settings. Each preference type has `onChange`, so Phase 9's Settings can show the same values.

### New Windows: Tile (D-02..D-06)

No new visual. There is no preview and no toast: the window moving into its tile is the feedback (Phase 3 keyboard-parity rule).

| Situation | What the user sees |
|---|---|
| Focused docked tile on the desk | The new window docks beside it, along the tile's longer side (D-02). One undo step |
| No focused docked tile | It splits the largest tile; with nothing docked it becomes the first tile beside the Desktop tile (D-03) |
| Dialog, panel, excluded app or too small to tile | It floats, as today (D-04) |
| Found at launch, filling a waiting tile, or restored | Not a new window (D-05). The Phase 8 placeholder path runs first |
| No room, zoom on | The existing collapse rule and its announcement ("Docked. 1 window collapsed.") (D-06) |
| No room, zoom off | It stays floating. **No beep, notice or announcement**, because nothing the user did was refused (D-06) |
| No room known only after docking (a first window with an unknown minimum) | It shows in the tile for about a second, then floats where it opened with no notice (zoom off) or collapses (zoom on). Its undo step stays. macOS can't report a minimum before docking (D-06a) |
| Opens during a press or gap drag | It joins no desk until the gesture ends, then floats, even in Tile mode, so it can't change the drag's result (D-20) |
| On a Space not showing, or first seen under a sheet | It floats (D-22) |
| Paused | It floats and stays floating after Resume: while paused, Transom sends no window command (Phase 3) |
| Desktop tile hidden and it can't dock | Today's rule: the Desktop tile shows first (Phase 3 D-31) |

### macOS's own ⌥ tiling

During a Hold ⌥ move the event tap copies the flags for Transom and then removes ⌥ from `flagsChanged`, `leftMouseDragged` and `leftMouseUp`, measured on macOS 15.7.7 and 27.2, with no setting written and no toast. If host UAT shows macOS's outline on real hardware, Turn Off writes `EnableTilingOptionAccelerator` (D-07a).

## Surface 2 — Hold ⌥ drags (TILE-22, D-08, D-09)

**Precedence.** Modifiers are read live, on every pointer and `flagsChanged` event (Phase 3). The first row that matches wins, in both modes. Any change restarts the 150 ms dwell (Phase 3 Timing).

| # | Held | Mode | Meaning |
|---|---|---|---|
| 1 | ⇧, with anything | both | Bypass: Phase 3's ⇧ rows (TILE-02) |
| 2 | ⌃⌘, with or without ⌥ | both | Fourths as rows (Surface 3) |
| 3 | ⌃, with or without ⌥ | both | Fourths as columns (Surface 3) |
| 4 | ⌘, docked window over another docked panel | both | Swap (TILE-11) |
| 5 | anything else | Automatically | Phase 3 state matrix and Phase 7 group and tear-off rules, unchanged |
| 6 | ⌥ | Hold ⌥ | Phase 3 state matrix and Phase 7 rules, as if Automatically |
| 7 | ⌘ without ⌥, docked window, no panel to swap with | Hold ⌥ | Snap-back ghost, release snaps back. ⌘ never pulls a window out |
| 8 | nothing (or ⌘ on a floating window) | Hold ⌥ | The plain drag below |

**The plain drag (row 8), from 16 pt of travel for a docked window or whole group.** No regions, no snap-back ghost and no group dwell. It reuses the ⇧ rows of Phase 3's matrix in full, so nothing new is drawn:

| Dragged | Situation | Overlay | On release |
|---|---|---|---|
| Docked window or whole group | Release frame fits the Desktop tile | Nothing | Pulled out: floats at its release frame. One undo step. Announces "Floating" |
| Docked window or whole group | Release frame would cross a docked tile once floating | Clamp ghost following the window | Pulled out, clamped inside the Desktop tile. Announces "Floating" |
| Docked window or whole group | **Ends over its own tile, from 16 pt** | As the two rows above | Still pulled out (CONTEXT risk 3). The tile closes and its neighbours reflow |
| Docked window or whole group | Released under 16 pt from the press, wherever the pointer went | Snap-back ghost after the dwell | Snaps back. No undo step and no announcement (D-08a) |
| Docked window or whole group | Desktop tile hidden | Snap-back ghost, "Show the Desktop Tile to float windows" | Snaps back, announces that text (Phase 3) |
| Docked window or whole group | Too big for the Desktop tile even at its minimum size | Blocked, "Not enough room" | Refused, snaps back, announces "Not enough room to dock here" (Phase 3) |
| Floating window or group | Inside the Desktop tile | Nothing | Plain move |
| Floating window or group | Would cross a docked tile | Clamp ghost | Moves to the clamped frame |

**No dwell for a plain drag.** Phase 3's rule is "if nothing is shown, the window stays where you release it". A plain drag has nothing to wait for, so the result never depends on the 150 ms dwell: a flick of 16 pt or more released in under 150 ms pulls out exactly like a slow drag, and below 16 pt it snaps back whether or not the dwell has passed. Today's release code gives `.miss` (snap back) when no decision is held; in this state the release must decide at mouse-up instead.

A plain drag of a docked window or whole group is pulled out only after 16 pt of travel, measured from the press (D-08a, `DragSession.pullOutTravel`). Below that it snaps back, showing the Phase 3 snap-back ghost after the dwell, so what is shown is what happens. The 3 pt minimum (`DragSession.minimumTravel`) stays everywhere else, and a click or a title-bar double-click has no travel, so double-click framing keeps working. A resize drag (`Kind.resize`) ignores every row above.

**Releasing or pressing ⌥ mid-drag (D-09).**

| Event | Overlay | A release before the next dwell ends |
|---|---|---|
| ⌥ pressed | Any clamp ghost withdraws (80 ms). The regions appear after 150 ms, as a Phase 3 hover | Phase 3 miss rules: docked snaps back, floating stays |
| ⌥ released | Preview withdraws (80 ms) | The plain drag's result, at once |

**Tab groups (D-09).**

| Drag | Hold ⌥, no ⌥ held | Hold ⌥, ⌥ held |
|---|---|---|
| Window held on another window's centre | No dwell, no Group preview, no grouping. Plain drag | Phase 7 group dwell and Group preview, unchanged |
| Tab dragged out of a strip | Tear-off ghost (Phase 7). Release outside the strip floats it at its landing frame. Back over its strip: nothing, release cancels | Phase 7 tear-off, unchanged |
| Selected member's whole-group drag | Plain drag: the group floats whole | Phase 7, unchanged |

Excluded apps, never-dock windows and every drag while paused get no overlay at all (Phase 3, unchanged), in both modes and with ⌃.

## Surface 3 — Fourth regions (TILE-23, D-14, D-16, D-18)

**Trigger.** ⌃ held during a move drag shows **columns**, ⌃⌘ shows **rows**, in both drag modes (rows 2–3 above). Pressing or releasing ⌘ with ⌃ held switches between them. Holding ⌥ as well changes nothing.

**⌃ must go down after the drag starts** (D-18), because ⌃-click is a right click. If ⌃ is already down at the press, the session ignores it until it has been released and pressed again during the same drag. A tab strip's ⌃-click stays a right click (Phase 7).

**Zones (the middle-half hit area).** The display under the pointer is split into five zones along one axis. A zone is a band across the whole visible frame, so only one coordinate matters. `p` is the pointer's fraction along the axis, measured from the left edge for columns and the **top** edge for rows (global top-left points).

| Zone | `p` range | Share of the axis | Result (D-14 dry run) | Capsule, columns | Capsule, rows |
|---|---|---|---|---|---|
| 1st | `0 ≤ p < 0.25` | 25% | 1st fourth | "1st column" | "1st row" |
| 2nd | `0.25 ≤ p < 0.375` | 12.5% | 2nd fourth | "2nd column" | "2nd row" |
| Middle half | `0.375 ≤ p < 0.625` | 25% | central half | "Middle half column" | "Middle half row" |
| 3rd | `0.625 ≤ p < 0.75` | 12.5% | 3rd fourth | "3rd column" | "3rd row" |
| 4th | `0.75 ≤ p ≤ 1` | 25% | 4th fourth | "4th column" | "4th row" |

- The middle-half zone is the **central quarter**: the inner half of the 2nd fourth plus the inner half of the 3rd. The zones run in order across the screen, each result is reachable by moving along one axis only, and the 1st and 4th zones line up with their fourths.
- The smallest zones on a 1280 × 800 display are about 97pt tall in rows mode and 160pt wide in columns mode.
- `p` uses the display's `visibleFrame`, clamped to 0…1, so a pointer over the menu bar or Dock still picks the nearest zone. A pointer on no display has no target: guides hide, and the miss rules apply.
- The hit test is one pure function beside `DropZones` in TransomModel, with no AppKit. Table tests cover each boundary on both axes.
- Tiles under the pointer don't matter: a fourth is a share of the whole desk (D-14). No edge band, centre or group target applies while ⌃ is held.

**What is drawn.** On the pointer's display, in the existing `PreviewPresenter` panel, back to front:

| Layer | Drawing | When |
|---|---|---|
| **Zone guides** | Exactly the five zones above, each its full band of the `visibleFrame`, inset 4pt on all sides, ghost recipe. No labels on guides | From the first dwell until ⌃ is released or the drag ends. **They stay steady while the pointer crosses zones** |
| **Result preview** | The dry run's exact frame for the window, or for the whole group frame (Phase 7 Surface 5). It is the result, not the zone: it may be larger than a fourth when one side has no tile to share (D-14), and it includes gaps | After 150 ms in a zone |
| **Capsule** | The zone's text from the table, centred in the result preview, Phase 3 overlay label with no glyph. Hidden under the Phase 3 clearance rule (rect narrower or shorter than the label + 16pt per side) | With the result preview |

Guides show hit zones, so what looks reachable is reachable; the narrower 2nd and 3rd guides are true. Guides have their own layers in the panel, below the drop preview's root layer, like `Marquee`, because the Phase 3 preview withdraws on every hover change. The result preview stays an ordinary `show(_:on:)` state, so its fades and its WYSIWYG release are unchanged. The panel orders out only when both are idle.

**State matrix** (columns or rows, docked or floating, either drag mode):

| Dry run on the held zone | Result preview after dwell | On release | Announcement |
|---|---|---|---|
| Fits | Dock recipe + capsule | Docks there or moves there (D-15). One undo step | "Docked to 1st column" etc. |
| Doesn't fit, zoom on (D-16) | Collapsed recipe + `CollapseCopy` label, at the frame ignoring minimums | Docks; windows collapse (ZOOM-13) | `CollapseCopy.dockedAnnouncement`, unchanged |
| Doesn't fit, zoom off (D-16) | Blocked recipe, "Not enough room" | Refused, then the miss rules. No beep: a refused drop never beeps (Phase 3) | "Not enough room to dock here" |
| Dwell not elapsed | Guides only, no result | Miss rules (WYSIWYG), **in Hold ⌥ mode too**: holding ⌃ is not a plain drag | none |

Other cases:

| Situation | Result |
|---|---|
| Docked window released on the zone it already holds | The same rect is previewed; release leaves it there, nothing refused |
| Whole-group drag, or a torn-off tab | Works the same. A group moves whole; a torn-off tab docks alone (D-15). Over its own strip, a tear-off still shows nothing and cancels |
| Pointer crosses to another display | Guides and result leave the old display at once; on the new display they appear after the dwell, on that display's desk (D-14) |
| ⌃ released, or ⌘ changes the axis | ⌃ released: guides and result fade out, then the row that now applies. Axis change: new guides replace the old by the 80 ms crossfade, result after the dwell |
| ⇧ pressed while ⌃ is held | Row 1 wins: guides and result fade out, bypass rules |
| Zoomed in | Guides cover the display as usual. The result is the desk-level frame like every Phase 3 preview, and the existing widening rule (Phase 4) handles a window that lands outside the view. No new UI |
| Paused mid-drag | Today's rule: the drag ends and the preview is withdrawn; guides go with it |

**Animation.**

| Event | Default | Reduce Motion |
|---|---|---|
| Guides appear, with the first result | Opacity 0→1, 120 ms, ease-out | Same |
| Pointer enters another zone | Old result fades out, 80 ms; guides don't move. New result fades in 120 ms after the dwell | Same (opacity only) |
| Guides leave (⌃ released, ⇧ pressed, drag ends, display change) | Opacity 1→0, 80 ms | Same |
| Axis change (⌘ pressed or released with ⌃ held) | Crossfade, 80 ms | Same |
| Release accepted or refused | Result and guides fade out, 80 ms, from when the frame write is sent (Phase 3). No shake, bounce or scale | Same |

**Menu.** One new submenu, **"Dock to Fourth ▸"**, in the Arrange section directly after Move Window ▸. Every item goes through `CommandMenu` once, with `setShortcut(for:)`, like every other command. The Arrange section then reads: Dock Window, Float Window, Swap with Previous Window, Undo Layout Change, Focus ▸, Move Window ▸, **Dock to Fourth ▸**, Split ▸, Snap Floating Window ▸, Tabs ▸, separator, Arrange All Windows, Float All Windows, Hide Desktop Tile, Gaps ▸, **New Windows: Float ▸**, **Drag to Dock: Automatically ▸**.

**Availability** (`Arranger.availability`, one rule for greying and beeping): the same as Move Window. The focused window is dockable, not excluded, present and on a desk, and nothing is paused.

**Hotkeys.**
- Bound by key position (KeyboardShortcuts registers by key code), like Phase 8's digits. The Shortcuts window and menu show the current layout's character.
- `Name` raw values are a persistent contract (Pitfall 13): never rename them.
- They are **not zoom names**, so they stay enabled with zoom off (TILE-10), and `Hotkeys.zoomNames` doesn't change.
- No duplicates inside Transom: the only ⇧⌃⌥⌘ defaults are the four arrows, D, F and T (`Hotkeys.swift`).
- System-shortcut check: `logSystemConflicts` iterates `zoomNames` only, so extend it to these ten names. The chords haven't been checked against `com.apple.symbolichotkeys` (this contract read code only); see UI Considerations.

**Shortcuts window.** A new **"Dock to Fourth"** section directly after "Arrange", 10 rows in the table's order, no footer. That makes **76** recorder rows in 9 sections. Restore Defaults also resets the 10 names. Duplicate checks use the Phase 4 `.shortcutValidation` text. Titles come from `ZoomCopy.shortcutTitle(_:)` (new case), so the duplicate message names them clearly.

**Result by route.** A success shows no preview: the window moving is the feedback (Phase 3 keyboard parity).

| Situation | Hotkey | Menu | URL | CLI |
|---|---|---|---|---|
| Fits | Docks or moves; announces | same | same | same, exit 0, prints nothing |
| Doesn't fit, zoom on (D-16) | Docks; windows collapse; `CollapseCopy` announcement | same | same | same, exit 0 |
| Doesn't fit, zoom off (D-16) | Beep, "Not enough room to dock here", Blocked preview flashes 600 ms at the would-be frame | same | Nothing on screen, logged | `transom: refused: Not enough room to dock here`, exit 1 |
| No change (the window already has exactly that frame) | Beep (`refusingNoChange`) | same | Nothing, logged | `transom: refused: dock-column-1 can't act right now`, exit 1 |
| Not available: no focused window, dialog, excluded, paused, not ready | Beep | Greyed | Nothing, logged | `transom: refused: dock-column-1 can't act right now`, exit 1 |
| Rate limit (a second call inside 1 s) | n/a | n/a | Ignored | `transom: refused (rate limit). Each command runs at most once per second.`, exit 1 |

Weights stay editable afterwards. Nothing remembers "a fourth" (D-16), so no menu item shows a check for a current fourth.

## Surface 5 — URLs and CLI (D-17)

**URLs.** `transom://dock-column-1` … `dock-column-4`, `dock-column-middle`, `transom://dock-row-1` … `dock-row-4`, `dock-row-middle`. Each is a plain entry in `TransomURL.commands` with an empty path, so the parser and its allow-list don't change: `transom://dock-column-5`, `/dock-column-1/`, `/DOCK-COLUMN-1` and `/dock-column/1` are rejected with no side effects and nothing logged of their contents. ## Accessibility

**Options in the menu.** Standard `NSMenuItem`s: VoiceOver reads the title and the radio check. The top-level title carries the current value. The radio item's change is announced, since the menu closes and leaves nothing to read.

**Keyboard parity.** Every drag result has a hotkey and a menu item (D-12). The menu items are the way in for a user who can't drag or hold keys. Hold ⌥ mode's pull-out has Float Window (⌃⌥⌘F), and docking has Dock Window (⌃⌥⌘D); keyboard docking works in both modes (D-10).

**Holding keys.** Drags need a held key only for docking in Hold ⌥ mode and for fourths, and both have keyboard equivalents. Whether Sticky Keys' latched modifiers reach the tap mid-drag is unverified; see UI Considerations.

**VoiceOver's ⌃⌥ modifier.** ⇧⌃⌥⌘ chords contain ⌃⌥. Phase 3's rule stands (hotkeys stay registered, Recorder rows let a user rebind).

**Overlays.** Guides, result preview and capsule are not accessibility elements (Phase 3 panel rule). VoiceOver gets the announcements above at release.

**Reduce Motion.** Guides and result only fade. Nothing morphs in this surface, in any mode.

**Increase Contrast / Differentiate Without Color / Reduce Transparency.** As in Color.

## Claude's discretion

Picked without asking, per the brief. Each can be raised with the user later; none blocks planning.

1. **Options as item + radio submenu**, not click-to-flip. A title like "New Windows: Float" that flips on click reads like an action. Gaps ▸ already does this, and the CONTEXT copy stays the top-level title. Alternative: a one-click flip, one less hover.
2. **Options are preferences, not commands**: no hotkey, URL or CLI, like Gaps. Alternative: add them as commands if the user wants to script them.
3. **Middle-half hit area = the central quarter, as five bands in order** (25 / 12.5 / 25 / 12.5 / 25). Alternative: a central box in both axes, which keeps the 2nd and 3rd zones at 25% near the screen's top and bottom but makes them unreachable by moving straight across the middle.
4. **Guides are the ghost recipe, drawing the true zones, unlabelled**; only the result has a capsule. Alternative: labels on every guide, which is busier.
5. **Names**: menu "Dock to Fourth" with "1st Column" … "Middle Half Row"; rows "Dock to 1st Column"; commands `dock-column-1` … `dock-row-middle`; `Name`s `dockColumn1` … `dockRowMiddle`; capsules "1st column" … "Middle half row". `Name`s can't be renamed after release (Pitfall 13).
6. **Precedence**: ⇧, then ⌃ (with ⌘ choosing rows), then ⌘ swap, then ⌥. ⌃ with ⌥ ignores ⌥.
7. **⌘ with no swap target in Hold ⌥ mode snaps back** instead of pulling out: someone holding ⌘ wanted a swap. D-08 doesn't cover this case.
8. **A plain drag of 16 pt or more never waits for the dwell**, so a quick flick pulls out. Follows Phase 3's "if nothing is shown, the window stays where you release it".
9. **Own-tile release floats from 16 pt** (CONTEXT risk 3). D-08a: a plain drag of a docked window pulls it out only from 16 pt of travel, and a smaller nudge snaps back, because a nudge that floats a window would be the mirror image of the user's complaint. The 3 pt minimum stays everywhere else.
10. **⌃ held at the press is ignored until pressed again**, per D-18's reason.
11. **macOS's ⌥ tiling: the tap removes ⌥ during a Hold ⌥ move; Transom writes no setting and shows no toast (D-07a).** Phase 3 D-05 leaves the setting alone, and the user asked for no extra dialogs. A line in the Conflict alert (CONTEXT's suggestion) isn't used, because the alert may never show again and is about edge drags. The strip was measured clean on macOS 15.7.7 and 27.2, and host UAT item 2 checks real hardware. If macOS's outline shows there, Turn Off writes the key.
12. **New announcements**: option changes, fourth success, and "Floating" in Hold ⌥ mode only, so Automatically stays exactly as today.
13. **No-change fourth beeps**, following the tree commands' `refusingNoChange`.
14. **Tooltips on the radio items**: the one place the Hold ⌥ meaning is explained in the app, reusing the conflict items' pattern. No new window.
15. **One "Dock to Fourth" submenu and one Shortcuts section**, with a separator, rather than two.
16. **No Debug lines**: the menu already shows both values.
17. **CLI section titled "Fourths"**, after Arrange.

---
18. **D-16's beep, on drags:** a refused drop shows the existing Blocked preview and doesn't beep, by the Phase 3 rule. Hotkeys and menu items do beep.
19. **D-09's tear-off:** a tab tears off and floats without ⌥ in Hold ⌥ mode. ⌥ is needed only for regions, as in D-08.

## Notes for the planner

1. **Guides and the preview's withdrawal.** `follow` withdraws the preview on every hover change, so a guide drawn as part of `PreviewState` would flash at each zone. Give guides their own layers and effect, as `Marquee` has, and keep the result as a normal state. `orderOutWhenIdle` and `isIdle` must count them. Add a labelled dock state (such as `PreviewState.fourth(Rect, label:)`) rather than changing `.dock`.
2. **`PreviewStyle.ghost` is private.** Expose it, or add `fourthGuide(_:increaseContrast:)` that calls it and `contrasted`.
3. **Release with no decision.** `release` uses `session.current?.action ?? .miss`. The plain drag needs its decision made at mouse-up (Surface 2). Don't change it for the other states, and don't change it for ⇧ in Automatically mode (success criterion 3).
4. **The hover.** `hover(for:)` and `decide` are the one place these rules go (CONTEXT). The drag mode has to reach the Arranger as engine input, since the engine has no AppKit and no UserDefaults. A new-windows choice goes the same way. Update the `Modifiers` doc comment, which says ⌥ and ⌃ are ignored.
5. **`ConflictPolicy.allKeys` is an allow-list of keys read and written.** The ⌥ tiling key stays out of it: nothing reads that key now (D-07a).
6. **Test counts change**: `ShortcutsModelTests` (66 → 76 rows, 9 sections), `CLICopyTests` exact help block, and the URL list tests.
7. **Fixed points checked by reading code**: `⌃⌥⌘1–3` snaps and `⌃⌥⌘0` Restore All differ from the new chords only by ⇧, so nothing collides. A fumbled ⇧ runs one of those instead; both are safe to repeat or undo.
