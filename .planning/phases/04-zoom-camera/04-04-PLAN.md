## Phase Goal

**As a** Mac user, **I want to** zoom out to see every window and zoom back in to any of them, **so that** I can find and focus any window fast.

<objective>
The first real zoom on screen: the shell side of the move protocol. ArrangeController hands each `.cameraMove` to a ZoomController that captures, shows the stage, animates, feeds `.cameraSettle`, tracks the settle's read-backs and reveals. Then real tile contents (snapshots or the app-colour fallback), the snapshot cache, Reduce Motion, retargeting, the Screen Recording explainer and the reveal announcements.

Purpose: success criteria 3 and 4 (snapshots or app colour; settle without a stale flash) are shell behaviour on top of the 04-02 engine.

Output: ZoomController, TileLayer, AppColor, ZoomCopy, extensions to StagePanel and SnapshotCapture, and two live VM suites.

Design:
- `ArrangeController.init` gains `zoomEnabled: Bool = false`; only TransomMacApp passes the preference, so every existing test and live suite keeps Phase 3 behaviour (success criterion 5).
- ZoomController is created lazily on the first move with zoom on and owns one StagePanel per display and the SnapshotCapture instance.
- The preference key `zoomEnabled` (default on) is defined on ZoomController; the menu toggle that writes it is 04-05.
- `public func zoom(to:displayUUID:)` on ArrangeController is the shell entry point the live test uses now and pointer input uses in 04-06.
- The 04-01 spike verdict may add conditions (for example "snapshots off by default" if G3 failed); read 04-SPIKE.md's Verdict and apply any condition that names this plan's files.
</objective>
