## Phase Goal

**As a** Mac user, **I want to** zoom out to see every window and zoom back in to any of them, **so that** I can find and focus any window fast.

<objective>
The feasibility spike (CONTEXT D, Mode mvp): build a measurement harness on the real AX write path and the final ScreenCaptureKit file, run gates G1-G8 in the Tart VM, record numbers in 04-SPIKE.md, and stop at a go/no-go checkpoint. Every other Phase 4 plan depends on this one.

Purpose: the risk in Phase 4 is feasibility (Electron settle latency, stale-flash-free reveal, WindowServer memory over an hour, Core Animation throughput), not code. None of it can be settled from documentation (RESEARCH Summary).

Output: `transom-zoom-spike` executable, the final `SnapshotCapture.swift`, a core `StagePanel.swift` later plans extend, `scripts/vm-spike.sh`, a narrowed `NoScreenCaptureTests`, and `04-SPIKE.md`.

Design (smallest complete change):
- The harness is a new executable target like `transom-dump`, depending on `TransomMac`, so it measures `AXWindowSystem.perform` -> `AXAppThread` -> `FrameWriter` and its `frameApplied` read-backs exactly as the product will (RESEARCH Spike Design).
- It does not use the engine camera (not built yet). Its "home" is a column grid of the measured windows in `display.visibleFrame`; its "view" gives 3 chosen windows the whole `visibleFrame` and parks the rest with the existing `DisplayInfo.parkedFrame(size:among:)` (A8: keep the live-verified `visibleFrame` bottom corners, CONTEXT E).
- `SnapshotCapture.swift` and `StagePanel.swift` are production files in `Sources/TransomMac/Zoom/`, written for keeps: 04-04 adds the cache, tile contents and retargeting to them without changing their shape.
- The spike runs only in the VM over SSH; the guest's `sshd-keygen-wrapper` already holds Accessibility and Screen Recording (RESEARCH Environment Availability).
</objective>

main.swift adds subcommands (each emits JSON lines with its gate):
- `settle` gains `--stage`: with it, the stage shows the captured images over the real windows before the batch, holds the final frame through settle, and reveals at all-returned + 50 ms (or 1500 ms cap). - `frames <mov> <outdir> [--fps 60]`: extracts PNG frames with `AVAssetImageGenerator` (host-side helper for G2's visual half; the executor reads the frames after each reveal-start timestamp).
