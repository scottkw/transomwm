# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 4 adds the zoom camera. It extends the Phase 3 contract (`03-UI-SPEC.md`) and keeps all of it unless a row below says otherwise. It adds nine surfaces:

1. the **camera stage**: a full-display snapshot overlay shown only while the camera moves and until the real windows settle
2. **tiles** on that stage: snapshot tiles, the app-colour fallback tile, and collapsed blocks
3. **collapsed-tile panels**: small persistent panels that stand in for windows too big for their tile (ZOOM-13)
4. the **rubber band** for ⌘⇧-drag rectangle zoom (ZOOM-03, ZOOM-12)
5. **pick mode**: after a zoom out, a hover ring shows that the next click zooms to that window (ZOOM-06)
6. the **zoom hotkeys and URLs** (ZOOM-01..04, 09..11), all on ⌃⌥⌘
7. the **Zoom section** of the status menu, plus the zoom on/off toggle and a **Shortcuts…** item
8. the **Shortcuts window**, with a KeyboardShortcuts `Recorder` row for every hotkey (ZOOM-08)
9. the one-time **Screen Recording explainer** alert (ZOOM-05)

It also adds one new drop-preview state ("Collapsed"), Debug lines, log lines and VoiceOver announcements.

Not in this phase: gestures (Phase 5), the all-displays overview and Spaces bar (Phase 6), saved views ⌥1–9 (Phase 8), the Settings window and onboarding copy about the monthly Screen Recording prompt (Phase 9). The Shortcuts window is folded into Settings in Phase 9.

**Platform rule (unchanged).** Native macOS only. The shell is AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`, `NSAlert`, `NSWindow`). Overlays are layer-backed AppKit views drawn with Core Animation (`CALayer`, `CAShapeLayer`). SwiftUI is used only inside `NSHostingController`, here for the Shortcuts window. Every colour is a semantic system colour, except the app colour, which is computed from the app's icon (see Color). Every font is a system text style.

**Phase 2/3 review rules still apply:** no `.font(.system(size:))` for glyphs, no padding stacked on a system inset, no duplicated controls within one surface, and no per-row AppKit lookups when the menu rebuilds. App names, icons and app colours come from the per-pid cache.

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom. None of TrellisWM's hotkeys, copy, icons or visuals is used.

**Spelling.** UI strings use US English ("canceled", "color" is never shown). Planning prose may stay British.

**Camera vocabulary used in this spec.**
- **View**: the node the camera frames on one display. The **home view** is the desk's root, which is exactly the Phase 3 layout.
- **Move**: an animated change of view. **Settle**: the AX writes after a move, until real windows are in place. **Reveal**: the stage fading out once settled.
- **Parked**: a window outside the view, moved to a display corner at its own size (never shrunk).
- **Collapsed**: a window whose tile in the current view is smaller than its minimum size. It is parked, and a collapsed block stands in its tile.

## Spacing Scale

All values are in points. The token scale is unchanged: 4 / 8 / 16 / 24 / 32 / 48 / 64. The Phase 2 exceptions (20pt window inset, 12pt button gap) apply in the Shortcuts window's bottom bar, the way Phase 2 used them. Phase 4 adds no new spacing exceptions.

| Token | Value | Phase 4 usage |
|-------|-------|---------------|
| xs | 4pt | Rubber-band start threshold (pointer must move 4pt from mouse-down before the band appears); vertical padding of the title capsule on a fallback tile |
| sm | 8pt | Gap between the icon and the title capsule on a fallback tile; horizontal padding of the title capsule; inset of the icon inside a collapsed block (icon ≤ shorter side − 8pt) |
| md | 16pt | Minimum clearance around the icon and the title capsule inside a fallback tile (each side) |
| lg | 24pt | Not used in Phase 4 |
| xl–3xl | 32 / 48 / 64pt | 64pt appears only as the fallback-tile icon size (see Fixed sizes), not as spacing |

Exceptions (non-spacing metrics, listed so the checker and auditor can find them):
- **Stroke widths:** 2pt for the rect-zoom target preview, the pick-mode hover ring and the collapsed-block hover ring. 1pt for the rubber band, the fallback-tile border, the collapsed-block border and the title-capsule border.
- **Dash pattern:** none new. Phase 3's 8/4 stays reserved for ghosts and the swap origin.
- **Corner radii:** fallback tiles 12pt (Phase 3 token). Collapsed blocks `min(12, shorter side / 2)`, so a thin strip becomes a capsule. Title capsule radius = height / 2. Rubber band 0pt (a plain marquee). Rings use the radius of the tile they outline. Snapshot tiles have no radius of their own: the captured window image carries its own transparent corners.
- **Fixed sizes:** fallback-tile icon 64pt, shrinking to `shorter side − 32pt` and hidden below 16pt. Collapsed-block icon at most 32pt, hidden below 16pt. Shortcuts window 480pt wide, default height 640pt, minimum height 400pt, resizable in height only.
- **Parking sliver:** a parked window keeps a 1pt × 1pt corner on screen (macOS will not place a window fully off screen). This is geometry, not spacing.
- **System metrics:** menu, alert, `Form` and `Recorder` metrics are system-drawn. Never override them.

## Color

Semantic system colours only, with **no hex literals in code**. Hex values are references resolved on macOS 27.0.1 with the default appearance. The Phase 3 appearance rule still applies: `CGColor`s are re-resolved inside `effectiveAppearance.performAsCurrentDrawingAppearance { … }` on `viewDidChangeEffectiveAppearance()` and on `NSColor.systemColorsDidChangeNotification`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | The user's own windows and wallpaper. On the stage that is the window snapshots plus the stage backdrop: the display's wallpaper image from `NSWorkspace.shared.desktopImageURL(for:)`, drawn aspect-fill and static (it does not zoom). If the image can't be loaded, `windowBackgroundColor` (ref light `#FFFFFF`, dark `#1E1E1E`) | The stage reproduces the screen. Transom adds no opaque chrome of its own |
| Secondary (30%) | **App colour** (computed, see below) for fallback tiles and collapsed blocks. `windowBackgroundColor` for the title capsule. `separatorColor` for 1pt tile borders. `labelColor` tints for the rubber band. System menu, alert and window materials | Tiles that stand in for windows, and neutral marquee feedback |
| Accent (10%) | `NSColor.controlAccentColor` (user's accent; ref default blue `#0088FF` light, `#0091FF` dark) | Only the elements listed below |
| Destructive / refusal | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | Phase 3 uses unchanged (the blocked preview now appears only with zoom off or for the ⇧-bypass case). New: the "Restore Defaults" button of the Shortcuts confirmation alert (`hasDestructiveAction = true`, system-drawn) |
| Warning | `NSColor.systemOrange` | Phase 3 use only (toast N7). Nothing new |

**App colour.** This is the only colour Transom computes rather than takes from the system. It is derived once per bundle ID and cached with the app-name and icon cache: downsample `NSRunningApplication.icon` to 16×16, ignore pixels with alpha below 50% and pixels with saturation below 20%, and take the mean colour of the most common hue bucket (12 buckets of 30°). If fewer than 10% of pixels survive the filter (monochrome icons), use the mean of all opaque pixels. With no icon, use `NSColor.systemGray`. It is used at 100% opacity, always with a 1pt `separatorColor` border so a pale app colour still reads against a pale wallpaper. Text is never drawn directly on it: the window title sits in a `windowBackgroundColor` capsule.

Accent reserved for exactly these elements (it extends the Phase 3 list, which stays valid):
1. Phase 3's uses: drop preview fill and border (dock, swap and the new Collapsed state), swap-origin border, gap handles while hovered or dragged, and the system-drawn uses
2. The **rect-zoom target preview**: the area the camera will frame, drawn while ⌘⇧-dragging
3. The **pick-mode hover ring** around the window a click would zoom to
4. The **collapsed-block hover ring**

The accent is **not** used for the rubber band itself, the stage, snapshot or fallback tiles, collapsed blocks at rest, the Shortcuts window (except system-drawn focus and the `Recorder`'s own recording state), menu items or the status glyph.

**Overlay colour recipe (new rows).** Alpha is applied to the semantic colour.

| Element | Fill | Border | Label |
|---|---|---|---|
| Rubber band (marquee) | `labelColor` 8% | `labelColor` 50%, 1pt solid | none |
| Rect-zoom target preview | `controlAccentColor` 20% | `controlAccentColor` 85%, 2pt solid | none |
| Pick-mode hover ring | none | `controlAccentColor` 85%, 2pt solid, drawn inside the tile rect | none |
| Collapsed block, rest | app colour 100% | `separatorColor` 1pt | app icon, centred |
| Collapsed block, hover | app colour 100% | `controlAccentColor` 85%, 2pt, inside | app icon, centred |
| Fallback tile | app colour 100% | `separatorColor` 1pt | app icon, then title capsule |
| Title capsule | `windowBackgroundColor` 100% | `separatorColor` 1pt | window title, `labelColor`, Body |
| Drop preview, **Collapsed** (new state) | `controlAccentColor` 20% | `controlAccentColor` 85%, 2pt solid | `arrow.down.right.and.arrow.up.left` (`labelColor`) + copy from Surface 7 |

**Increase Contrast** keeps the Phase 3 rule: fill alphas × 1.5 (8→12, 20→30) and every border and ring at 100%. `separatorColor` and `windowBackgroundColor` adapt by themselves. **Differentiate Without Color**: the rubber band (thin neutral line) and the target preview (thick filled rect) differ by weight and fill, not just hue; collapsed blocks carry the app icon. **Reduce Transparency**: the stage backdrop is opaque already; overlays use tints, not materials, so nothing changes.

## Surface 1 — Camera stage (ZOOM-01..07)

**What it is.** One `NSPanel` per display that covers the display's whole `frame`. It is shown only during a move and the settle after it, and it is the only thing that animates. Real windows never animate. They get one AX write each when the move ends (CONTEXT A). When the camera rests, the stage is ordered out and the real windows are what the user sees.

**Panel.**

| Property | Value | Why |
|---|---|---|
| `styleMask` | `[.borderless, .nonactivatingPanel]` | Never activates Transom or takes focus |
| `ignoresMouseEvents` | `false` while shown | While the stage is up, clicks must not reach real windows that are about to move. A click on a tile retargets the camera (Surface 5); a click on the backdrop is swallowed. The stage is up for at most 250 ms + settle (cap 1500 ms) |
| `canBecomeKey` / `canBecomeMain` | `false` | Never key, never main |
| `level` | `.floating` (same as Phase 3 overlays). When the stage orders in, any visible toast or drop-preview panel is re-ordered front, so notices stay readable | Above normal windows; below the menu bar, the Dock and open menus (`.popUpMenu`). The spike reports the level against open menus (CONTEXT D) |
| `collectionBehavior` | `[.canJoinAllSpaces, .stationary, .ignoresCycle]` | As Phase 3. No `.fullScreenAuxiliary`: fullscreen Spaces have no layout, and zoom commands there beep |
| `sharingType` | `.none` | Never captured by Transom's own snapshots or by screen sharing (Pitfall 18) |
| `isOpaque` / `backgroundColor` / `hasShadow` / `animationBehavior` | `true` / `.clear` / `false` / `.none` | The backdrop layer is opaque, so real windows moving underneath never show through |
| Accessibility | `setAccessibilityElement(false)` | Transient. Each move is announced instead (Accessibility) |
| Lifetime | Created lazily on the first move with zoom on, per display; destroyed when zoom is turned off or the display goes away | With zoom off the stage is never created (success criterion 5) |

**Layer tree.** Backdrop layer (wallpaper, static), then one tile layer per window that is visible at the start or the end of the move, in back-to-front window order. The Desktop tile has no layer of its own: it is backdrop. Floating windows on the Desktop tile get tile layers like docked windows.

**A move, step by step.**

| Step | What happens | Visible result |
|---|---|---|
| 1. Trigger | A hotkey, URL, menu item, rect zoom, pick-mode click, stage click, double-click or collapsed-block double-click asks for a view on one display (the display under the pointer; for menu items, the menu's display) | nothing yet |
| 2. Plan | The engine resolves the target view. If it equals the current view, or the command can't act (see Refusals), nothing moves | Refusal: beep (hotkey/menu) plus a VoiceOver announcement |
| 3. Capture | With Screen Recording granted: one-shot captures of the on-screen windows in the current view, concurrency 4, at the larger of the tile's start and end on-screen size × `backingScaleFactor`, capped at native size. The move starts when all captures return or after **120 ms**, whichever comes first. A window not captured in time uses its cached snapshot, or else a fallback tile. Without the permission this step is skipped | nothing yet |
| 4. Show | The stage orders in **instantly** (no fade), with every tile exactly over its real window's current frame | Invisible by design: the stage looks like the screen |
| 5. Animate | **250 ms**, `CAMediaTimingFunction(name: .easeOut)`. Tiles in the target view interpolate from their start rect to their resolved target rect. Tiles leaving the view follow the camera transform (the transform that maps the target node's current rect onto the display) and slide off the display edges. Tiles entering the view start at the inverse-transformed position and slide in. All tiles share one duration and curve | The zoom |
| 6. Settle | At the end of the animation the stage holds the final frame. Transom saves the layout (Phase 3 rule), then sends one AX write per window whose frame changed and that is visible at the target, plus one move per window that must be parked or un-parked. Writes are tagged so they are never mistaken for user drags | Stage still shown, motionless |
| 7. Reveal | When every write has returned, plus **50 ms** for apps to redraw, or at the **1500 ms** cap, whichever comes first, the stage fades out over **120 ms** (opacity). Collapsed-block panels (Surface 3) fade in over the same 120 ms | Real windows, in place, with no stale-layout flash (ZOOM-07) |
| 8. Refresh | Snapshots of the visible windows are re-captured in the background at their new size and cached. Nothing on screen changes | none |

**Retargeting.** A new move requested during steps 3–7 starts from the stage's current presentation state (no queue, no jump). Writes not yet sent for the old target are dropped; writes already sent are overwritten at the next settle. A double-press of a hotkey therefore moves two levels smoothly.

**Reduce Motion** (`accessibilityDisplayShouldReduceMotion`, observed live). Step 5 becomes a **250 ms crossfade** (`.easeInEaseOut`): the start tile set fades 1→0 while the end tile set fades 0→1, with no tile moving or scaling. Every other step is unchanged.

**Tile contents.**

| Tile | When | Contents |
|---|---|---|
| Snapshot | Screen Recording granted and a capture or cached image exists | `layer.contents = CGImage`. Aspect-fill, anchored to the top edge so the title bar stays visible, clipped by `masksToBounds`. No border, no radius (the image has the window's own corners) |
| Fallback | No permission, permission revoked, capture failed with no cached image, or a window that appeared after capture | App-colour fill, 12pt radius, 1pt `separatorColor` border. App icon centred, sized `min(64, shorter side − 32)`, hidden below 16pt. Title capsule 8pt below the icon, shown only when the tile is at least icon + 8 + capsule height + 32pt tall and capsule width + 32pt wide. Capsule: 8pt horizontal and 4pt vertical padding, Body text, middle-truncated, max width tile width − 32pt. Title from AX (never `kCGWindowName`); an empty title shows the app name. Icon and capsule are laid out for the tile's **end** size and keep that size through the move |
| Collapsed | The window is collapsed at the start or end view | As the collapsed block in Surface 3, drawn on the stage |

**Parking (visual consequence).** A parked window is moved at its own size so that only a 1pt × 1pt corner stays on screen, at the first corner of the display's `frame` not shared with another display, in the order bottom-right, bottom-left, top-right, top-left. Parked windows return on quit, after a crash, via Restore All Windows, and when zoom is turned off (CONTEXT D).

**Refusals** (no move; beep for hotkeys and menu, nothing for URLs; always a log line and a VoiceOver announcement):

| Command | Refused when | Announcement |
|---|---|---|
| Zoom Out to All Windows | The view is already home | "Already showing all windows" |
| Zoom Out One Level | The view is already home | "Already showing all windows" |
| Zoom In One Level | The view is a single leaf | "Nothing to zoom in to" |
| Back / Forward | No earlier / later entry on this display (entries whose node no longer exists are skipped) | "No earlier view" / "No later view" |
| Move View ▸ direction | No node across that edge of the view (always true at home) | "No area to the left" / "to the right" / "above" / "below" |
| Frame Focused Window | No focused window, or the focused window is floating, excluded or never-dock | "No docked window to frame" |
| Frame Desktop | The Desktop tile is hidden | "The Desktop tile is hidden" |
| Any zoom command | Arranging is paused, Accessibility is not ready, or the display is a fullscreen Space | "Arranging is paused" / "Transom needs Accessibility access" / "Zoom isn't available in full screen" |

**Step In target.** One level toward the focused window if it is inside the view; otherwise toward the tile under the pointer; otherwise toward the largest child. **Step Out** goes to the parent of the view's node. **Move View** goes to the node across that edge of the view at the same depth with the longest shared edge, ties to the most recently viewed.

## Surface 2 — Snapshots and Screen Recording (ZOOM-05)

**Capture rules (CONTEXT B).** One-shot `SCScreenshotManager.captureImage(contentFilter:configuration:)` with `SCContentFilter(desktopIndependentWindow:)`, `ignoreShadowsSingleWindow = true`, `showsCursor = false`. No `SCStream`, so the system "sharing" indicator never shows. ScreenCaptureKit is imported in exactly one file, `Sources/TransomMac/Zoom/SnapshotCapture.swift`; `NoScreenCaptureTests` is narrowed to allow only that file. Cache: per window ID, LRU, capped at 128 MB of decoded pixels, an entry dropped when its window closes.

**Permission flow.**

| Situation | Behaviour |
|---|---|
| First move ever with zoom on, `CGPreflightScreenCaptureAccess()` false, explainer never shown | The move runs at once with fallback tiles (the user is never kept waiting). After the reveal, the **explainer alert** shows once (below). The "shown" flag is saved when the alert appears, so it never shows again, even after a quit |
| Explainer "Allow Previews" | Calls `CGRequestScreenCaptureAccess()`. macOS shows its own prompt or opens System Settings. Transom does not relaunch itself; if macOS offers "Quit & Reopen", the normal quit path restores parked windows (SAFE-01) |
| Explainer "Not Now" | Closes. Transom re-activates the app that was frontmost before the alert. Fallback tiles continue. No later prompt from Transom |
| Granted later | Checked with `CGPreflightScreenCaptureAccess()` at the start of every move; snapshots start with the next move |
| Revoked, or the monthly macOS grant lapsed, mid-session | Captures fail or preflight turns false. Fallback tiles, silently. One log line per session, Debug line updated. No alert, no toast |
| Granted but captures keep failing (macOS may need a relaunch) | Fallback tiles. Log line suggests reopening Transom. Debug line "app-icon tiles (capture failing)" |
| Zoom off | ScreenCaptureKit is never touched and the preflight is never called |

**Explainer alert.** `NSAlert`, `alertStyle = .informational` (app icon), shown after `NSApp.activate()`, never during a move, a drag or a rubber band (deferred until mouse-up and reveal). Buttons: **"Allow Previews"** (first, default, Return) and **"Not Now"** (Esc). Closing it is the same as Not Now. Tracking, hotkeys and zoom keep working while it is up (Phase 3 non-blocking rule).

| Field | Copy |
|---|---|
| `messageText` | "Show window previews while zooming?" |
| `informativeText` | "Transom takes still pictures of your windows using Screen Recording. Without it, zoom shows app icons instead." |

**Recovery path.** While Screen Recording is not granted, the Zoom section shows **"Allow Window Previews…"** (Surface 6). It calls `CGRequestScreenCaptureAccess()`; if that returns false because the user already decided, it opens System Settings ▸ Privacy & Security ▸ Screen & System Audio Recording (`x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`). This is user-initiated, so it is not a re-prompt loop.

## Surface 3 — Collapsed blocks and their panels (ZOOM-13)

**When.** A window is collapsed when its tile in the current view is smaller than its minimum size. With zoom on, this happens when a drop is accepted that doesn't fit at the home view (CONTEXT A), and in any zoomed view where a subtree is still too small. The window itself is parked; the block stands in its tile.

**Panel (at rest).** One `NSPanel` per collapsed tile, recycled through a pool (the gap-handle pattern): `[.borderless, .nonactivatingPanel]`, `canBecomeKey = false`, `level = .floating`, `[.canJoinAllSpaces, .stationary, .ignoresCycle]`, `sharingType = .none`, `ignoresMouseEvents = false`. It covers **exactly** the tile rect, which would otherwise be bare wallpaper, so it steals no click from an app. Tracking area `[.mouseEnteredAndExited, .cursorUpdate, .activeAlways]`. Panels are ordered out when a move starts (the stage draws collapsed blocks itself) and fade in at reveal.

| State | Visual | Cursor | Input |
|---|---|---|---|
| Rest | App-colour fill, radius `min(12, shorter side / 2)`, 1pt `separatorColor` border. App icon centred, `min(32, shorter side − 8)`, hidden below 16pt. No title | system default | — |
| Hover | Adds a 2pt `controlAccentColor` 85% ring inside the rect. Fades in over 80 ms, out over 120 ms | `NSCursor.pointingHand` | — |
| Single click | No change. In pick mode, it zooms (Surface 5) | — | Never activates Transom |
| Double-click | Zooms to that window's leaf, then focuses the window once it settles | — | While paused: beep and "Arranging is paused" |

**Turning zoom off with collapsed windows.** Phase 3 has no collapsed tiles, so those windows float on the Desktop and toast **N1** shows ("A “{App}” window no longer fits its tile, so it's floating on the Desktop." / "{n} windows no longer fit their tiles, so they're floating on the Desktop.").

## Surface 4 — Rubber band, ⌘⇧-drag rectangle zoom (ZOOM-03, ZOOM-12)

**Trigger.** Left mouse-down with both ⌘ and ⇧ held (and neither ⌃ nor ⌥), seen by the existing `InputTap`, with zoom on, Transom ready and not paused, no move or settle in progress, and the pointer not in a fullscreen Space. Only then are mouse-down, drags and mouse-up consumed (CONTEXT C). Modifiers are read at mouse-down only. Releasing ⌘⇧ mid-drag does not cancel.

**Drawing.** In the display's existing drop-preview panel (click-through, `.floating`, Phase 3), not the stage.

| Phase | Visual |
|---|---|
| Pointer moved < 4pt from mouse-down | nothing |
| Dragging (≥ 4pt) | The **rubber band**: the rect from mouse-down to the pointer, `labelColor` 8% fill, 1pt `labelColor` 50% border, square corners. It tracks the pointer at display rate, clamped to the display where the drag began |
| A target exists | The **target preview** in addition: the on-screen rect of the target node, `controlAccentColor` 20% fill and 2pt 85% border, 12pt radius. Target = the lowest common ancestor of every leaf whose on-screen tile centre lies inside the band (collapsed tiles and the Desktop tile count). It updates when the target node changes, never per mouse move: fade in 80 ms, then a 120 ms ease-in-out morph between targets (Reduce Motion: the old rect is removed and the new one fades in over 120 ms) |
| No leaf centre inside the band | Band only, no target preview |

**Outcomes.**

| Event | Result |
|---|---|
| Mouse-up with a target | Band and preview fade out over 80 ms as the camera moves to the target (Surface 1) |
| Mouse-up with no target | Band fades out over 80 ms. Nothing happens. No beep (a marquee over nothing, as in Finder) |
| Mouse-up after < 4pt of movement (a ⌘⇧-click) | Transom re-posts the original mouse-down and a matching mouse-up at the same point and flags, tagged so its own tap ignores them, so ⌘⇧-click keeps working in apps (for example, open a link in a new tab) |
| **Esc** during the drag (ZOOM-12) | Band and preview fade out over 80 ms. No move. The rest of the drag and its mouse-up are consumed, so no click reaches an app. Announcement "Zoom canceled" |

**How Esc is heard.** The tap mask stays mouse-only, so Transom still never sees typed keys (T-03-28). For the duration of a rubber band only, Transom registers temporary Carbon hotkeys for Esc with no modifier, ⇧, ⌘ and ⌘⇧ (the user may still be holding ⌘⇧). They are unregistered at mouse-up or cancel. ⌥⌘Esc (Force Quit) is never registered. These are not rebindable and do not appear in the Shortcuts window.

## Surface 5 — Pick mode and clicks in a zoomed view (ZOOM-06)

**Why a mode.** The home view is the Phase 3 layout that people work in, so a plain click there must stay a plain click. "Clicking a window in a zoomed view" therefore applies right after the user zooms **out**, when they are looking for a window.

**Entering.** Pick mode starts on the display when a move triggered by **Zoom Out to All Windows** or **Zoom Out One Level** reveals and the new view holds more than one window.

**While in pick mode.**
- The window tile under the pointer gets the **pick-mode hover ring** (2pt `controlAccentColor` 85%, inside the tile rect, the tile's radius), drawn in the drop-preview panel. It fades in over 80 ms and out over 120 ms. Pointer position comes from a passive `NSEvent.addGlobalMonitorForEvents(matching: .mouseMoved)` installed only while the mode is on. Over the Desktop tile, gaps, the menu bar or the Dock, no ring shows.
- A left click (no modifiers) on a **docked window or a collapsed block** is consumed (mouse-down and its mouse-up). The camera zooms to that window's leaf and the window is focused once it settles. Pick mode ends.
- A click anywhere else (the Desktop tile, a floating window, the menu bar, the Dock, a gap handle) passes through untouched and ends pick mode.
- Esc ends pick mode with no move. It is heard through a temporary unmodified Esc Carbon hotkey registered only while the mode is on, so that one Esc does not reach the frontmost app.
- Any Transom command, a window drag, a ⌘⇧-drag, a Space change or a display change ends pick mode.

**Clicks on the stage.** While the stage is up (Surface 1, steps 4–7), a click on a tile retargets the camera to that window's leaf and focuses it at settle, in any mode. A click on the backdrop is swallowed.

## Hotkeys and URLs (ZOOM-01..04, 08..11)

All new hotkeys are on the **⌃⌥⌘** base, registered through KeyboardShortcuts 3.1.0 with `KeyboardShortcuts.Name("<name>", initial: …)`. The raw names are a **persistent contract** (Pitfall 13: bindings are stored under `KeyboardShortcuts_<name>`): never rename one. Each runs one new `Command` case through the existing dispatcher, the same call the menu item and URL make. While zoom is off, these 11 names are disabled with `KeyboardShortcuts.disable(_:)`, so the chords reach apps exactly as in Phase 3.

**Consistency rules (extending Phase 3):** arrows are directions. On the arrow family, no extra modifier = **focus**, ⇧ = **move the window**, and fn (Home / End / Page Up / Page Down, which fn+arrow produces on Mac laptop keyboards) = **move the view**. Brackets go back and forward, as in Safari. Comma and period step out and in. A zoom hotkey that can't act beeps and posts its announcement (Surface 1 Refusals); none fails silently.

**Why these pan keys.** The free ⌃⌥⌘ letters after Phase 3 and CONTEXT C are A, L, Q, T, V, W and Y, which form no spatial cluster, and the plain and ⇧ arrows are taken. fn+arrows complete the arrow family, work on built-in and external keyboards (where Home, End, Page Up and Page Down are their own keys), and collide with no Phase 3 chord.

**URL rules (extending Phase 3).** The 11 URLs join `TransomURL.commands` with the same strict whitelist: exact scheme, a bare lowercase host, no path beyond "/", no query, fragment, user, password or port. Unknown or malformed URLs do nothing, are logged and show no UI. Each command is rate-limited to once per second (the existing `TransomURLRateLimiter`). URL commands act on the display under the pointer. A URL that can't act, or any zoom URL while zoom is off, does nothing and logs, with no beep (Phase 3 rule). `transom://restore` additionally returns every display's camera to home.
