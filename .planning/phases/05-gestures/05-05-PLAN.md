Implements E-03 (continue from current tile positions and retarget) and UI-SPEC Surface 2's interactions.

ZoomController.beginFollow when `active[uuid]` exists:
- `.capturing`: the stage isn't up yet. Show it now with the cached images at the move's start rects, and treat the move as interrupted.
- `.moving` or `.settling`: call `stage.freezeAtPresentation()`. That removes each layer's animations after copying `presentation()` frames into the model frames, inside a CATransaction with actions off.
- `.revealing`: cancel the fade (panel alpha back to 1) and freeze.
Then store the superseded `Active` as `interrupted` on the new following Active and set the phase `.following`. The tiles keep their frozen frames, and the follow's start rects are the preview's start rects: the pending target's view, because previewMove and stillMove start from `currentView`. The first follow sample therefore moves from the frozen frames toward the gesture's lerp without a jump, since `refollow` rebuilds from current frames.

On commit: the new zoomTo replaces camera.pending, so the old move's settle is ignored by the engine (its id no longer matches) and `run` retargets as usual. Drop `interrupted`.

On spring back after a takeover: tiles go back to the preview's start rects (the pending target's view). If the interrupted move had not settled (it was capturing or moving), call its saved `settle(moveID)` once and continue with the normal settle and reveal. If it was settling, re-arm its reveal tracker. If it was revealing, run the reveal fade. Never call settle twice for one move id.

Log Phase 4's retarget line as "retarget gesture {kind} during {old phase}".

GestureController: start follow even when the controller isn't idle; the takeover is ZoomController's. Call `controller.zoomInputEndPick(reason: "gesture")` when a gesture is taken: ArrangeController gets a small internal forwarder to `zoomInput.endPick(reason:)`. Any taken gesture ends pick mode, as any Transom command does (UI-SPEC Surface 2).

ArrangeController: the forwarder above. `beginFollow` hides collapsed panels for that display (`collapsedPanels.hide(on:)`). `onFollowEnded` (spring back without settle) fades them in (`collapsedPanels.fadeIn(on:)`), and the reveal path already fades them in after a snap. `onViewChanged` stays reveal-only, so follow and spring back never change the status button.

GestureFollowIntegrationTests adds:
- `aGestureDuringAHotkeyMoveRetargetsWithoutStranding`: from a node view, `await arrange.dispatch(.camera(.stepOut))`, then within 80 ms post ⌥ Σ +1.2 at a tile. The final view is one level in from the step-out's target, `arranger.camera.pending` is empty once idle, and the guest log has "retarget gesture pinch during …".
- `aSpringBackDuringAMoveLetsThatMoveSettle`: same start, then ⌥ Σ +0.1 → the final view is the step-out's target (the interrupted move settled once) and pending is empty.
- `aGestureEndsPickMode`: after a zoom-out reveal (pick mode on, observable through ZoomInput's published pick tiles), a taken ⌥ pinch ends it.
