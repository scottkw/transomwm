## Phase Goal

**As a** trackpad user, **I want to** pinch and pan the desk with my fingers, **so that** zooming and moving around feels direct.

<objective>

Purpose: GEST-04's "never leak into the app" and D-07's "zoom off is exactly Phase 3" are properties of the tap and its lifecycle, independent of how the camera follows. This plan proves them in the VM before plan 05-04 adds follow.

Output: GestureTap.swift, Trackpads.swift, GestureController.swift, ArrangeController lifecycle wiring, VM integration tests, a display-waking vm-live-test.sh.

GestureTap.swift (new): a sibling of InputTap with the same TapBox, thread, CFRunLoop, start/stop and watchdog trial-port shape. It has its own mask `GestureTapRules.mask` and its own thread name "GestureTap". The callback:
- re-enables on tapDisabledByTimeout/UserInput, clears the latch (never resume a half-seen sequence) and bumps the matching counter under a lock;
- copies the `GestureTapRules.Input` fields (through GestureEventFields for undocumented ones) and reads the state with `withLock { $0 }`;
- calls `GestureTapRules.decide` with `GestureTapRules.liveSurface`.
The TapBox tracks the current sequence's summary on the tap thread only: consumed and passed counts, start and last time, reason. When a latch ends, or a new sequence start replaces it, the callback yields `.ended(summary)`. That happens for taken sequences and for passing sequences whose reason is anything but `.shortCircuit`; short-circuited sequences only bump a counter. A consumed event with a sample yields `.sample(sample, seq:)`. The callback returns nil to consume and the event unchanged to pass. No logging, AX, file I/O or allocation beyond the yield. InputTap.swift is not edited.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HID input → product gesture tap | Every scroll and gesture on the system crosses Transom's callback while zoom is on |
| Other processes → synthetic events | Any process with post permission can inject gestures |
| IOKit → main | Device notifications arrive from the kernel registry |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Denial of service | GestureTap latch | high | mitigate | The spike-tested timeouts and re-decide on every start; tap latch cleared on tapDisabled*; main-side timeout timer; VM test `aStuckLatchReleasesTheNextScroll` |
