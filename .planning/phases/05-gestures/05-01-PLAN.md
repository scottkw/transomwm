## Phase Goal

**As a** trackpad user, **I want to** pinch and pan the desk with my fingers, **so that** zooming and moving around feels direct.

<objective>
The gesture spike (CONTEXT D-09, E-01): build the `transom-gesture-spike` CLI on the exact consume rules the product will ship, run its synthetic half in the Tart VM, prepare the host checklist the user runs on their own trackpads, and stop at a go/no-go checkpoint where the user decides whether MultitouchSupport ships (E-01). Every later Phase 5 plan depends on this one.

Purpose: whether a session tap can see and consume magnify over other apps on macOS 27 is MEDIUM confidence (RESEARCH A1-A5). It can't be settled in the VM, which has no trackpad, so the live half is the user's (D-08).

Output: the spike target, the product's `GestureTapRules` (pure, unit-tested), the gesture field constants file, a parameterised `scripts/vm-spike.sh`, and `05-SPIKE.md` with the user's decision.

Design (smallest complete change):
- `GestureTapRules.swift` and `GestureEventFields.swift` are production files, written for keeps. Plan 05-03's product tap calls the same `decide` the spike measures.
- The MultitouchSupport shim stays in the spike target (E-01 default). It moves into TransomPrivate only if the user picks multitouch at the gate (plan 05-07).
- `GestureEventFields` holds undocumented CGEvent field numbers, not a dlsym symbol, so it needs no Capabilities entry. If a field ever stops being populated it reads 0, nothing latches, and every event passes. That is the fallback, and it is safe by construction (RESEARCH Pattern 6: "the tap path needs no canary").
</objective>

GestureTapRules.swift (new, TransomMac, `import CoreGraphics`, `import TransomPrivate`). Public, because the spike target calls it. Same shape as ZoomTapRules:
- `GestureTapState: Equatable, Sendable`: `armed` (Bool), `disarmReason` (`.zoomPaused`, `.notReady`, `.rectZoomOrDrag`, or nil; for the UI-SPEC debug log only), `deskDisplays: [CGRect]`, `fullScreenDisplays: [CGRect]` (displays whose shown Space has no desk), `finderPID: Int32` (0 = unknown), `trackpadSenders: Set<UInt64>` (empty = not known, so the sender filter is off).
- `GestureSample: Sendable`: kind (`.pinch`/`.pan`), raw CG `phase` and `momentum` (Int, CG encodings only, Pitfall 3), `magnification`, `dx`, `dy` (point deltas), `location`, `timestamp` (seconds), `flags`, `senderID`, plus `reason` at the first sample (`.optionHeld` or `.wallpaper`).
- `PointerSurface { window, wallpaper, overlay }` and `static func surface(at:in:excludingPID:display:) -> PointerSurface`. It applies the same front-to-back walk as `CGWindowList.topmost`: skip our own pid and alpha 0, look through an overlay that covers the whole display. It answers `.window` for a layer-0 hit, `.overlay` for anything above layer 0, and `.wallpaper` for no hit. `static func liveSurface(at:)` wraps it with `CGWindowList.onScreenFrontToBack()`, `getpid()` and the display bounds from `CGGetDisplaysWithPoint`. A nil list answers `.overlay`: when the list can't be read, pass.
- `static let mask: CGEventMask = (1 << CGEventType.scrollWheel.rawValue) | (1 << GestureEventFields.gestureType)`.
- Timeouts: `quietTimeout = 0.3` s (after fingers-up: scroll phase Ended with momentum still to come, or between momentum events), `fingersDownTimeout = 2.0` s (no event while began/changed is open). The 2 s fingers-down limit keeps UAT item 10 (resting fingers mid-pan) from releasing the latch into the app.
- `Input`: the fields copied from one event (type raw value, scroll phase, momentum phase, isContinuous, point deltas axis 1/2, gesture HID type, gesture phase, zoom value, target PID field 40, sender field 87, flags, location, timestamp).
- `Latch`: `.none`, or a sequence with kind, `consuming` Bool, `fingersUp` Bool, `lastEvent` time, `optionHeld` Bool, and a `PassReason` for a passing sequence: `.disarmed(reason)`, `.fullScreen`, `.notDeskDisplay`, `.chord` (⌃ or ⌘ also held), `.notTrackpad`, `.midSequence`, `.windowUnderPointer`, `.overlayUnderPointer` or `.shortCircuit` (a non-Finder target PID). These match the UI-SPEC Logging reasons, and plan 05-03 logs them.
- `Decision { case pass; case consume(GestureSample?) }`.
- `decide(_ input: Input, state:, latch: inout Latch, surface: (CGPoint) -> PointerSurface) -> Decision` implements RESEARCH Pattern 2:
  - First, an expired latch (past the applicable timeout) is cleared.
  - Scroll with phase 0 and momentum 0, or not continuous: always `.pass`, and the latch is untouched.
  - A sequence start (scroll mayBegin 128 or began 1; magnify: HID 8 with gesture phase 1) decides afresh. Not armed → passing (`.disarmed`); location in a `fullScreenDisplays` frame → passing (`.fullScreen`); outside every desk display → passing (`.notDeskDisplay`). If the sender is non-zero, `trackpadSenders` is non-empty and the sender isn't in it → passing (E-04). ⌥ with neither ⌃ nor ⌘ → consuming, reason `.optionHeld` (⌥⇧ allowed). Any ⌃ or ⌘ → passing (E-05). Otherwise the target PID decides: non-zero and not `finderPID` → passing, with no CG read. Else call `surface` once: `.wallpaper` → consuming, reason `.wallpaper`; anything else → passing.
  - A stray `changed`/`ended`/momentum event with no latch → latch passing for that sequence. Never start consuming mid-sequence.
  - Later events follow the latch. Scroll Ended sets `fingersUp`. Momentum End (3), Cancelled (8) with fingers up and no momentum, or magnify gesture phase 4/8 end the latch after this event is decided.
  - While consuming a magnify: consume type-29 events with HID 8, 5 or 0, and pass envelopes 61/62 (A4; the spike's T2 decides whether to flip this).
  - Rotate-only, smart zoom and any other HID sub-type outside a latch pass.
  - Clamp `magnification` to ±1 and drop NaN/∞ to 0 before building a sample (V5).
