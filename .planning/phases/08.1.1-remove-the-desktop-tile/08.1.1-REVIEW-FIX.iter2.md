### CR-01: A desk whose docked windows are all minimized or hidden can't take a new tile

**Files modified:** `Sources/TransomEngine/Arranger+NewWindows.swift`, `Sources/TransomEngine/Arranger.swift`, `Sources/TransomEngine/Arranger+Commands.swift`, `Tests/TransomEngineTests/ArrangerNewWindowsTests.swift`
**Commit:** 88bf509
**Applied fix:** When no tile is placed (no tree, or every docked window minimized, hidden or full screen), the drop is `.layoutEdge(.right)`. `applyDrop` already turns that into the root on an empty tree. Beside a root that takes no part, the new leaf gets the whole visible frame. This change is in autoTile (New Windows: Tile), `dock()` (as a fallback when `Planner.dockTarget` is nil and `nodeRects` is empty) and `arrangeAll()` (the else branch of `largestTile`). Dragging is unchanged: on a desk that looks empty, a drag still docks only from the edge band (UI-SPEC discretion 2). Tests: with the only docked window minimized, autoTile, Dock and Arrange All each make the floater fill the frame (D-08).

### WR-01: The one-shot `bringBackParked` drops home frames for parked windows it can't move at launch

**Files modified:** `Sources/TransomMac/LayoutStore.swift`, `Tests/TransomMacTests/LayoutStoreTests.swift`
**Commit:** 7716b58
**Status:** fixed: requires human verification
**Applied fix:** Used the review's migration-time alternative. When `LayoutStore.decode` loads a file older than schema 4, each floater that has a home frame (in `world` and in every layout set) gets that home frame as its stored floating frame. A parked window that isn't tracked at launch then comes back to its home frame through the existing "floater not where the model has it" move whenever it appears. `bringBackParked` still handles windows that are tracked at launch, because `reattach` records their live park rect. A `recordFloatingFrame` failure rejects the file as `.invalidEntry` and is not swallowed. Tests: the schema-3 fixture's FileZilla (window 4) now loads at its home frame instead of the park rect. Two synthetic schema-1/2 tests had a floater with a home frame, and their expected World now has that floater at its home frame.
**Why verify:** this is a state-handling change. Its premise is that in a legacy file, only floaters parked by a hidden Desktop have a home frame, because the old WR-06 sweep cleared floater home frames on every desk whose Desktop was shown. The dormant-wake path was not exercised live.

### WR-02: `planFloatingLostRoom` runs once, so a placeholder left unfit after the relax throws `windowNotFound`

**Files modified:** `Sources/TransomEngine/Arranger.swift`, `Tests/TransomEngineTests/ArrangerReflowTests.swift`
**Commit:** 1a35618
**Applied fix:** Restored the loop. Each pass plans again, relaxes any waiting placeholders and continues, or floats the real unfit windows and plans again. It keeps the "floating takes no room" simplification and the clamp into the area. Test: `ArrangerLostRoomPlaceholderTests` restores H[r 50 | a 500 | b 300], quits a and b's app (both placeholders with minimums), then shrinks the display to inner width 364. Relaxing a leaves b unfit. Before the fix this logged `could not plan …: windowNotFound(window 2)`; it now plans with no fault and keeps all three in the tree.

### WR-03: The floating group target uses DesktopLayer insertion order as z-order

**Files modified:** `Sources/TransomEngine/Arranger+Tabs.swift`, `Sources/TransomEngine/Arranger.swift`, `Tests/TransomEngineTests/ArrangerTabsTests.swift`
**Commit:** 35042a3
**Status:** fixed: requires human verification
**Applied fix:** This is the minimal fix the project rules ask for, without a z-order system. `floatingGroupTarget` now picks the most recently focused floater under the pointer, using `focusOrder`. When no floater has been focused it falls back to the last one added, as before. The hover code passes in the docked tile beneath, and that tile wins when its shown window was focused after the floater (D-05: the focused window is in front). A `shortcut:` comment records the limit: a raise without a focus, such as an app activation raising all its windows, can disagree with this order. It also names the upgrade: `CGWindowList.topmostWindow(at:)`. Test: with t floating over docked a, focusing t and then a, then dragging f to t's centre, f now groups with a's tile instead of t. The existing "front floater groups ahead of the tile" test still passes.
