# Phase 8.1.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 8.1.1 takes a concept away and adds one menu. It **extends** `03-UI-SPEC.md`, `04-UI-SPEC.md`, `07-UI-SPEC.md`, `08-UI-SPEC.md` and `08.1-UI-SPEC.md`. Every token, timing, panel property, colour recipe, copy rule and announcement pattern in them still applies, except where this spec removes it. "08.1 Surface N" means that surface, with the changes listed here.

Phase 8.1.1 has five surfaces. None of them is a new visual system:

1. **Removals**: every on-screen trace of the Desktop tile goes (D-01, D-07, D-09)
2. **Floating windows and drags**: what a drag shows now that there is no Desktop rect (D-05, D-06, D-07)
3. **Dock Window menu**: a submenu at the top of Arrange listing every docking position with its hotkey (D-10, D-11)
4. **Halves and thirds commands**: ten new commands with hotkeys, Shortcuts rows, URLs and CLI help (D-10)
5. **Migration and README**: what the user sees on the first launch after updating, and the exact README copy (D-02, D-03, D-09)

Not in this phase: drag regions for halves or thirds (⌃-drag stays fourths only), any new overlay, toast, alert or confirmation, any hint on an empty desk (D-07), and the Settings window (Phase 9). The collapsed-window "minimize" (D-12) is an engine investigation with no UI change of its own.

**Guiding rule (user, 2026-11-05).** Plain macOS behaviour over reference-app concepts. Where this spec had to choose, it chose whatever adds no concept, string or overlay.

**Platform rule (unchanged).** Native macOS only. Shell = AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`). Overlays = layer-backed AppKit views drawn with Core Animation. Every colour is a semantic system colour. Every font is a system text style. The CLI writes plain ASCII to a terminal.

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom.

**Spelling.** UI strings use US English ("Center Third"). Planning prose may stay British.

**Vocabulary.**
- **Floating window** (UI copy: "floating"): any tracked window not docked. It no longer lives "on the Desktop" in any UI copy.
- **Desktop rect** (this spec only): the rect Phases 3–8.1 clamped and centred floating windows into. It is gone. **Substitution rule:** every place that clamped or centred a frame into the Desktop rect now uses the display's `visibleFrame`.
- **Docking position** (this spec, never in UI copy): one of the 21 items in the Dock Window submenu.
- **Half, third** (UI copy): a share of the whole desk, as a column or a row, computed with the fourth arithmetic (D-10). "Left Half" is a column; "Top Half" is a row.

## Surface 2 — Floating windows and drags (D-04..D-08)

**Stacking (D-05, D-06).** Docked windows share the display's whole visible frame. A floating window sits wherever its app or the user put it, above or below docked windows by ordinary macOS ordering: the window you click comes to the front. Transom never hides, parks, raises, re-orders or clamps a floating window, except to keep it on screen where it already does. A new floating window stays where its app opened it.

**Commands that placed a window inside the Desktop rect** use the visible frame instead (substitution rule). The visible results:

| Command | Result after this phase |
|---|---|
| Float Window (`⌃⌥⌘F`, green button) | Its pre-dock frame, clamped on screen; with none, 90% of its tile size centred on the visible frame. The remaining tiles reflow to fill the screen and the floated window sits on top. No overlay |
| Snap Floating Window ▸ items, `⌃⌥⌘1–3`, `U I J K`, `↩`, `C`, and ⇧⌃⌥⌘ arrows on a floating window | The same targets over the whole visible frame (D-10). "Maximize" fills the visible frame, over docked windows |
| Move Out of Group (`⌃⌥⌘L`), tear-off landing | Same landing rule, clamped on screen |
| Dock Window ▸ Where It Is (`⌃⌥⌘D`) on an empty desk | The window becomes the first tile and fills the visible frame (D-08) |
| New Windows: Tile with nothing docked | The new window fills the visible frame (D-08) |
| Split with New Finder Window, with no focused docked tile | The new Finder window is placed as New Windows: Tile places a window with nothing focused: it splits the largest tile, or fills the visible frame on an empty desk (Claude's discretion 6) |
| Focus ▸ Left / Right / Up / Down | Moves between docked tiles only. From a floating window it starts at the window's frame (as today). Floating windows are never a Focus target; ⌘-Tab and clicks reach them. No neighbour: beep (unchanged) |

**Drag state matrix, changed rows only.** Phase 3's matrix, Phase 7's group rules and 08.1 Surfaces 2–3 apply otherwise. "Before" quotes the 08.1 contract.

| Dragged | Situation | Before | After |
|---|---|---|---|
| Floating window or floating group, any mode | Released where it would cross a docked tile | Clamp ghost while dragging; moves to the clamped frame | **No ghost.** Stays exactly where released, over the docked window (D-05) |
| Docked window or whole group, ⇧ held (both modes) or plain drag in Hold ⌥ mode from 16pt | Release frame crosses a docked tile | Clamp ghost; floats clamped inside the Desktop tile | **No ghost.** Floats at its release frame. Announces "Floating" in Hold ⌥ mode only (08.1, unchanged) |
| Docked window or whole group, ⇧ or Hold ⌥ plain drag | Desktop tile hidden | Snap-back, "Show the Desktop Tile to float windows" | Row gone |
| Docked window or whole group, ⇧ or Hold ⌥ plain drag | Too big for the Desktop tile | Blocked, "Not enough room"; refused | Row gone: pulling a window out of the layout never lacks room |
| Floating window or group, Automatically mode | **Empty desk**, pointer more than 24pt from every edge of the visible frame | (Desktop tile centre) plain move | **Nothing shown; plain move.** Released, it stays where it is (Claude's discretion 2) |
| Floating window or group, Automatically mode, or ⌥ held in Hold ⌥ mode | **Empty desk**, pointer within 24pt of an edge of the visible frame | Dock beside the Desktop tile | Phase 3 dock preview covering the **whole visible frame**; release docks it as the first tile (D-08) |
| Any window or group, Automatically mode, or ⌥ held in Hold ⌥ mode | Over another **floating** window's centre (middle 50% of its frame, or of a floating group's content rect) that is in front of a docked tile | Group dwell only on the Desktop tile | Group dwell and Group preview (Phase 7 D-02), taking precedence over the docked tile beneath. The rest of that floating window's area gives the docked tile's regions beneath, as usual (Claude's discretion 3) |

Unchanged and worth stating: over docked tiles, a floating window shows the Phase 3 edge regions and centre group dwell, exactly as a docked window does. In Automatically mode a drag across a screen full of docked windows therefore always shows a region except over tile centres and gaps. To move a floating window over docked ones without docking it, hold ⇧, or choose Drag to Dock ▸ Hold ⌥. The README says so (Surface 5).

**Fourths by drag (⌃ / ⌃⌘, 08.1 Surface 3).** Unchanged, except that D-04 drops the Desktop tile from the arithmetic: only docked tiles count, and with no tile on a side the window grows into it. On an empty desk every fourth therefore previews "Whole desk". Halves and thirds have **no** drag regions; the grown-span labels already name halves when a fourth grows into one.

## Surface 4 — Halves and thirds commands (D-10)

**Behaviour.** Each command acts on the **focused window** of the frontmost app, floating or docked, with the fourth arithmetic: a share of the whole desk at the root; a floating window docks, a docked window moves, a tab group member moves its whole group; one undo step; windows already docked shrink to fit; with no docked tile on one side the window grows into that side (D-04). Zoom off and no room: refused. Zoom on and no room: windows collapse. Identical to 08.1 Surface 4 in every route, including the result-by-route table (beep, Blocked flash 600 ms, announcement, silent URL, CLI exit codes, rate limit, `refusingNoChange` beep for a docked window already at exactly that frame).

**Spans.** Columns split the visible frame left to right, rows top to bottom.

| Command | Own span | Grown spans possible |
|---|---|---|
| Left Half / Top Half | [0, 1/2] | [0, 1] |
| Right Half / Bottom Half | [1/2, 1] | [0, 1] |
| Left Third / Top Third | [0, 1/3] | [0, 2/3], [0, 1] |
| Center Third / Middle Third | [1/3, 2/3] | [0, 2/3], [1/3, 1], [0, 1] |
| Right Third / Bottom Third | [2/3, 1] | [1/3, 1], [0, 1] |

**Chord layout (Claude's discretion 5).** The fourths put columns on digits 1–5 and rows on 6–0. Halves and thirds follow the same idea on the two letter rows under the right hand: **upper row = columns** (Y U halves, I O P thirds), **home row = rows** (H J halves, K L ; thirds), left to right = first to last.
- **No collision inside Transom** (read from `Hotkeys.swift`, 2026-11-05): the only ⇧⌃⌥⌘ defaults are the four arrows, D, F, T and 0–9. The saved-view fallback on macOS 15.0/15.1 is ⌃⌥ / ⇧⌃⌥ with digits, no ⌘.
- **A fumbled ⇧** runs the ⌃⌥⌘ chord instead: Y and ; are unbound, U I J K snap a floating window, O zooms out, P pauses (announced, press again to resume), H is now unbound, L moves a tab out of its group. All are safe to repeat or undo.
- Bound by key position (KeyboardShortcuts registers by key code), like the fourths. On a non-US layout the menu and Shortcuts window show that layout's character for the `;` key.
- They are **not zoom names**: they stay enabled with zoom off (TILE-10), and `Hotkeys.zoomNames` doesn't change. `logSystemConflicts` must also iterate these ten (extend the fourths list to every docking-position name).
- `Name` raw values are a persistent contract (Pitfall 13): never rename them.

**Shortcuts window.** The "Dock to Fourth" section is renamed **"Dock Window"** and holds, in menu order: "Dock Window Where It Is" (`dock`, moved from Arrange), the 4 halves, the 6 thirds, the 10 fourths. Totals: **84 rows in 9 sections** — Zoom 11 (Frame Desktop gone), Saved Views 18, Arrange 13 (Dock Window and Hide or Show Desktop Tile gone), Dock Window 21, Split 6, Snap Floating Window 9, Tabs 3, Safety 2, Exclusions 1. Restore Defaults resets the 10 new names. Duplicate checks use the Phase 4 `.shortcutValidation` text with `ZoomCopy.shortcutTitle(_:)` titles. No footer on the new section.

**URLs.** Ten plain entries in `TransomURL.commands` with an empty path, so the parser and its allow-list rules don't change. Variants (`/dock-left-half/`, `DOCK-LEFT-HALF`, `dock-half/left`) are rejected with no side effects and nothing of their contents logged. As URLs, all twenty dock commands share one one-per-second limit (WR-09); on the CLI each has its own. The URL table becomes 36 parameterless commands plus `view/{n}` and `save-view/{n}`.

**CLI help (exact, ≤ 72 columns; longest line 66, measured 2026-11-05).** The "Fourths" section is renamed **"Dock"** and gets the ten new lines before the ten fourth lines, which are unchanged:

## Surface 5 — Migration and README (D-02, D-03, D-09)

**First launch after updating.** layout.json goes from schema 3 to schema 4.

| What the file held | What the user sees |
|---|---|
| A Desktop tile beside docked tiles | The docked windows grow to fill the space it took. One frame write per docked window, as at any launch re-attach |
| Floating windows | They stay exactly where they were (D-02) and may now sit over docked windows |
| Windows parked by a hidden Desktop tile | They come back on screen at their home frame, floating (D-02) |
| Undo history | Gone: Undo Layout Change beeps until the next layout edit (D-03) |
| A saved view framing the Desktop tile | It becomes the whole-display view, as if saved zoomed out (Claude's discretion 7). Other views are unchanged |
| A desk with only a Desktop tile and floating windows | An empty desk: nothing drawn (D-07) |

No toast, alert or announcement for the migration: what the user sees is the layout, and the user asked for nothing extra. One log line (category `persist`): "migrated layout.json schema 3 to 4: dropped {n} Desktop tiles, brought back {m} parked windows, dropped undo history". A schema 4 file opened by an older Transom keeps today's rule (newer schema kept, saving disabled).

## Accessibility

**Menu.** The Dock Window submenu is standard `NSMenuItem`s and system section headers: VoiceOver reads each title and its key equivalent, and reads the headers as headers. The parent title "Dock Window" plus the item ("Where It Is", "Left Half") reads as a phrase.

**Overlays.** No new overlay. Removing the clamp ghost removes a visual that had no announcement.

**Reduce Motion / Increase Contrast / Differentiate Without Color / Reduce Transparency.** Nothing new drawn, so nothing new to adapt. Existing previews keep their 08.1 behaviour.

## Claude's discretion

Picked without asking (autonomous run; the user wasn't available). Each can be raised later; none blocks planning.

1. **Frame Desktop goes** (menu item, `⌃⌥⌘G`, `frame-desktop`, wallpaper double-click). It framed the Desktop node that D-01 deletes. Alternatives were repurposing it to frame the floating windows (a new concept) or to go to the whole-display view (Zoom Out to All Windows already does that). Both add or duplicate, against the guiding rule. Its `Name` raw value is retired, not reused.
2. **Empty desk: only the 24pt edge band docks.** Today `DropZones` returns `.emptyLayout` anywhere on an empty tree, which would turn every drag of a floating window on an empty desk into a full-screen dock. With the band rule, an empty desk behaves like the plain desktop until you aim at an edge. The keyboard (`⌃⌥⌘D`) and New Windows: Tile still dock to the full frame (D-08).
3. **The front floating window wins a group dwell over the tile beneath.** What you see is what you target. Replaces the "on the Desktop tile" condition in today's group code.
4. **"Dock Window ▸" replaces the "Dock Window" item; the plain dock becomes "Where It Is".** This keeps D-11's title without showing two items titled "Dock Window", and puts the submenu first in Arrange, where it is easiest to find (the user's request). Alternative: a separate submenu above the Arrange header, which would leave the duplicate title.
5. **Chords:** halves and thirds on ⇧⌃⌥⌘ with the right hand's two letter rows: upper row = columns (Y U, I O P), home row = rows (H J, K L ;). This mirrors the fourths (⇧⌃⌥⌘, digits, columns then rows) and keeps one modifier family for "dock to a share of the screen". `⌃⌥⌘H` stays unbound. Q was avoided: ⌥⇧⌘Q logs out with no confirmation if ⌃ slips.
6. **Split with New Finder Window, nothing docked focused:** placed as New Windows: Tile places a window with nothing focused (largest tile, or the full frame). One rule, no new one.
7. **A saved view framing the Desktop tile migrates to the whole-display view.** The only lossless choice once the node is gone; other saved views are untouched.
8. **Names:** menu "Left Half" … "Bottom Third" and "Center Third" for the column (matching Snap Floating Window's "Center Third") but "Middle Third" for the row; Shortcuts "Dock to Left Half"; commands `dock-left-half` …; `Name`s `dockLeftHalf` …; labels "Left half", grown "Left two thirds". The internal `Command` shape (generalising `.dockFourth`) is the planner's.
9. **One "Dock Window" Shortcuts section and one "Dock" help section** for all docking positions, matching the menu, instead of three sections each.
10. **No toast for the migration or the lost undo steps.** The user asked for nothing extra; the layout itself shows the result.
11. **No separator between fourth columns and rows** inside the new submenu; the "Fourths" header divides it and the titles say which.
