# Phase 08.1.1: Remove the Desktop Tile - Context

**Gathered:** 2026-11-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Remove the Desktop tile concept. Docked windows share the whole visible frame of a display; floating windows behave like
normal macOS windows and are never hidden, parked or clamped into a Desktop rect by Transom. Hide/Show Desktop Tile
(menu, `⌃⌥⌘H`, `transom://toggle-desktop`) goes away. Existing layout.json files migrate. The menu-bar menu gains a
top-level "Dock Window" submenu listing every docking configuration (halves, thirds, fourths) with its hotkey.

Supersedes the Desktop-tile parts of TILE-15 and Phase 3 D-31 (and D-24). User decision after 08.1 host UAT: "Why the
hell would I need a Desktop Tile" — hiding the tile hid FileZilla with no visible way back, and a new floating window
re-showed a hidden tile. Guiding preference: plain macOS behaviour over reference-app concepts.

</domain>

<decisions>
## Implementation Decisions

### Model & migration
- **D-01 (user):** Delete the `.desktop` node kind (`Node.desktop`, `NodeID.desktop`, `LayoutTree.withDesktop()`,
  `isDesktopHidden`, `LayoutError.nothingDocked` / `.desktopTile`). An empty desk has no tree (`root == nil`); the first
  docked window fills the visible frame. `World.validate` no longer requires a Desktop tile. `DesktopLayer` (the floating
  windows list and floating tab groups) stays; renaming it is at Claude's discretion but not required.
- **D-02 (user):** layout.json version bump with a migration step: drop the Desktop node, renormalise sibling weights
  (collapse a split left with one child, as normalisation already does), floating windows keep their frames, windows
  parked by a hidden Desktop go back to their home frame. Corrupt-corpus and round-trip tests cover the migration.
- **D-03 (user):** Undo history in old files is dropped on migration (one-time loss of undo steps).
- **D-04 (user):** Fourths (08.1 D-14) count docked tiles only; the "Desktop tile counts as a tile" clause is gone. If one
  side has no tile, the window grows into that space as before.

### Floating windows & empty desk
- **D-05 (user):** Normal macOS stacking. The focused window is in front. Transom never hides, parks, raises or re-orders
  floating windows and never clamps them into a Desktop rect (clamp on screen only, where it already does).
- **D-06 (user):** A new floating window stays where its app put it.
- **D-07 (user):** An empty desk shows nothing: the plain macOS desktop. No hint, no overlay.
- **D-08 (user):** New Windows: Tile with nothing docked: the window becomes the first tile and fills the visible frame
  (replaces 08.1 D-03's "beside the Desktop tile").

### Commands & menu
- **D-09 (user):** Remove Hide/Show Desktop Tile from the menu, the `⌃⌥⌘H` hotkey, the `toggleDesktop` command and
  `transom://toggle-desktop` (and the CLI allow-list entry). The URL/CLI reports it as an unknown command. The
  "Show the Desktop Tile to float windows" announcement/ghost label goes. README says the tile is gone.
- **D-10 (user):** Add docking commands for halves and thirds, as columns and rows, sharing the fourth arithmetic
  (share of the whole desk at the root; a floating window docks, a docked window moves, a tab group moves whole, one
  undo step; zoom-off refusal and zoom-on collapse as for fourths). Reachable from hotkeys (rebindable), menu,
  `transom://` and the CLI. The existing `⌃⌥⌘` snap commands keep working for floating windows, now over the whole
  visible frame instead of the Desktop rect.
- **D-11 (user):** A top-level "Dock Window" submenu in the menu-bar menu lists halves, thirds and fourths with their
  hotkeys shown. The fourths move there from menu ▸ Arrange.
- **D-12 (user):** The collapsed-window "minimize" seen in 08.1 UAT: the planner/researcher investigates. Fix it in this
  phase if the Desktop tile caused it; otherwise log it for Phase 9.

### Added after research (2026-11-06)
- **D-13 (user):** Retire ZOOM-11. Frame Desktop goes: menu ▸ Zoom item, `⌃⌥⌘G`, `transom://frame-desktop`, the
  wallpaper double-click. The retired shortcut names are never reused.
- **D-14 (user):** Zoomed-in views no longer hide floating windows; they stay visible on top (D-05 applies to zoom too).
- **D-15:** The migration log line drops the "dropped undo history" clause, because undo is never saved to disk.

### Added at host UAT (2026-11-06)
- **D-16 (user):** "All screen portions designated by the app should be a portion of the screen irrespective of other
  windows." Every docking position (halves, thirds, fourths, corners) gives the window exactly that part of the visible
  frame, whatever else is docked. Nothing grows into an empty side; the rest of the screen can stay empty (floating
  windows show there) until another window docks into it. Supersedes D-04's grow clause and 08.1 D-14's grow rule.
- **D-17 (user):** Add corner quarters as docking positions — Top Left, Top Right, Bottom Left, Bottom Right — each
  exactly that quarter of the screen, on every route (Dock Window menu with a Corners/Quarters section, rebindable
  hotkeys, `transom://` and the CLI). The ⌃⌥⌘U/I/J/K floating-window corner snaps stay as they are.
- **D-18 (UAT finding):** A floating window in front of a docked tile must win the tab-group dwell (check 7a failed:
  only the docked tile's "Top half" region showed). Diagnose and fix.
- **D-19 (user):** Accessibility scope: native menus and controls must keep working with VoiceOver (free); no custom
  VoiceOver work for overlays or drag previews.

### Claude's Discretion
- Default chords for the halves/thirds docking commands, as long as they don't collide with existing defaults
  (`⌃⌥⌘` snaps, `⇧⌃⌥⌘0–9` fourths) and the README lists them.
- Whether `DesktopLayer` / `FloatingWindow` keep their names; any internal naming of the new commands.
- How the Planner's floating-window logic simplifies once there is no Desktop rect (D-05), as long as tests cover
  floating windows over docked ones, an empty desk, and migration.

</decisions>

## Existing Code Insights

### Reusable Assets
- `Sources/TransomModel/Fourths.swift` + `FourthSlot` + `ArrangerFourthTests`: the share-of-the-desk arithmetic to
  generalise to halves and thirds.
- `LayoutTree.root` is already `NodeID?`, so an empty tree is representable today.
- `Sources/TransomModel/DesktopLayer.swift`: floating windows and floating tab groups — keep.
- Layout versioning/migration chain in `LayoutFile.swift` / persistence tests (Phase 1 D-hardened persistence).

### Established Patterns
- Commands flow `Command` enum → `Arranger+Commands` → hotkeys (`TransomMac/Input/Hotkeys.swift`, KeyboardShortcuts
  names) → menu (`ArrangeController`) → `TransomURL` / CLI allow-list (Phase 8 D-06: every command reachable from all).
- Tree edits are transactional, one undo step per user action (`world.edit(... history:)`).

### Integration Points
- Desktop references across ~40 source files: `LayoutTree`, `World`, `Resolve`, `Planner` (desktopRect, parks),
  `Arranger` (parkRequested, homeFrames, showParkedDesktops, toggleDesktop), `Arranger+NewWindows`, `Arranger+Tabs`,
  `Snap`, `Neighbours`, `Navigator`, `OverviewLayout`, `ViewPlanner`, `LayoutRestore`, `TransomURL`, `Notice`,
  `Hotkeys`, `ArrangeController`, `GestureTapRules`. Tests: `DesktopLeafTests`, `DesktopLayerTests`,
  `ArrangerDesktopTests` and many Arranger tests that construct `.withDesktop()`.
- Parking stays for hidden tabs (sized parks); only Desktop-hidden parking goes.

</code_context>
