# Phase 08.1.1 Plan 23: Corner quarters Summary

**`transom://dock-top-left` (and top right, bottom left, bottom right, with the same `transom` CLI commands) docks the focused window into exactly that quarter of the visible frame, under the same rules as halves and thirds. A corner is built from edits that already exist: `insertFourth` for its half, then the window's leaf split in two with an empty area. If a docked child already fills that half, `insertShare` runs inside the child instead.**

## Accomplishments

- **Model (8.1.1 D-17, E1-E3).** `DockCorner` gives its `rows` and `columns` halves. `insertCorner` takes the first axis from the root's split, or uses rows for a leaf or an empty root:
  - If a docked root child spans the corner's half exactly, the window goes inside that child along the other axis via `insertShare`, which is `insertFourth`'s body taking any node.
  - Otherwise `insertFourth` places the window in that half, with empty space used first and nothing growing. The window's leaf then becomes `[window | empty]` (or the reverse, or the row version).
  - Both paths are all-or-nothing.
- **Engine.**
  - `Command.dockCorner` is dispatched through `dockFourth(_:at:)`, which now takes a `DropTarget`. It is in the no-window beep list and in `availability`.
  - In `dropping`, `.corner` gets the E4 vacate rule and the label "Top left quarter".
  - `admitOpenedURL` puts `.dockCorner` in the `.dockFourth` bucket, so all 24 dock URLs share one per second.
- **Copy.** The announcement is "Docked to top left quarter". The menu title is "Top Left" (`cornerTitle`) and the Recorder title is "Dock to Top Left Quarter". `transom help` lists the four corners after the halves. Its longest line is 66 columns.
- **URL and CLI.** There are now 40 parameterless commands. Variants are rejected: `/dock-top-left/`, `DOCK-TOP-LEFT`, `dock-corner/top-left`, a path, a query, and `dock-left-top`. `transom dock-top-left extra` gives "transom: dock-top-left takes no argument." (`.usage`, exit 64).
