## Warnings

### WR-01: A torn-off tab over its own docked group groups with a floater hidden behind that group (introduced by the iteration-2 WR-02 fix)

**File:** `Sources/TransomEngine/Arranger.swift:1751`

**Issue:** The new guard is meant to stop "the dragged window's own tile" from competing with a floater:
```swift
let beneath: NodeID? = if case .tile(let id, _)? = target, !(key == ownKey && id == ownDesk.tree.leaf(containing: window)) { id } else { nil }
```
It does not check `docked`. During a tear-off (D-10), the torn tab is still a member of its docked tabs leaf until release, and the window stays put (`Arranger+Tabs.swift:874-876`). So `ownDesk.tree.leaf(containing: window)` is the group's leaf, and that leaf still shows the group's selected member on screen. The own-tile exclusion in the `switch` just below (`Arranger.swift:1757`) is correctly limited to `docked`, which is `false` for a tear-off (`Arranger.swift:1703`). The new guard is not.

As a result, for a tear-off over its own group's tile, `beneath` is nil, and `floatingGroupTarget`'s focus-recency check (`Arranger+Tabs.swift:255-260`) is skipped. A floater that lies behind the group's visible selected member (focused after the floater) wins the group dwell. The user sees the group's content under the pointer, but the preview and the release group the torn tab with a window they cannot see. This is the iteration-1 WR-03 defect again, for tear-offs.

Reproduced at HEAD with an engine test: group `[b, f]` (f selected) docked on the right, `t` floating inside that tile, focus `t` then `f`, `b` torn onto `t`'s centre. The result is the tick preview `.group(frame: t, label: "Group as tabs")` and, on release, the floating group `[t, b]`. Before 169835c this released as a tear-off float.

**Fix:** Limit the exclusion to a title-bar drag of a docked window, matching the `switch` below:
```swift
let beneath: NodeID? = if case .tile(let id, _)? = target, !(docked && key == ownKey && id == ownDesk.tree.leaf(containing: window)) { id } else { nil }
```
Verified in a scratch clone: with this change the repro passes, and so do `aDockedWindowDraggedOntoAFloaterOverItsOwnTileGroups`, `aFloaterBehindAFocusedDockedWindowDoesNotGroup` and every `ArrangerTearOff*` suite. Add the repro as a test in `ArrangerTearOffReleaseTests`:
```swift
@Test func aTornTabOverItsOwnGroupDoesNotGroupWithAFloaterBehindTheGroup() throws {
    // [b, f] docked (f selected), t floating inside the group's tile, focus t then f;
    // tear b onto t's centre, hold 400 ms, release: no floating group.
}
```

**File:** `Sources/TransomMac/Zoom/ZoomInput.swift:86`, `Sources/TransomMac/Zoom/ZoomInput.swift:152`

**Issue:** `guard …, let leaf = arranger.leafNode(of: …) else { continue }` binds `leaf` and never uses it.

**Fix:** Use `arranger.leafNode(of: info.window) != nil`, and the same at line 152.

### IN-02: The migration log line counts the wrong windows (carried forward)

**File:** `Sources/TransomMac/LayoutStore.swift:67-75`

**Issue:** The "brought back N parked windows" count:
- covers every floater in `world` that has a home frame, including hidden floating tab members, which the rewrite at lines 177-181 now skips;
- does not count the set floaters that the rewrite now changes when a window is absent from `world`;
- is counted before any bring-back has run.

"dropped N Desktop tiles" counts every desk, including desks of a schema 4 file that holds a World schema 1.

**Fix:** Count the floating frames the rewrite actually changed, and count Desktop nodes during the legacy decode.

### IN-03: Stale "Desktop" references in comments and logs (carried forward)

### IN-04: Two hand-kept `FourthSlot` label switches must stay in sync (carried forward)

**File:** `Sources/TransomMac/Shell/MenuCopy.swift:63-78`, `Sources/TransomEngine/DragSession.swift:99-114`

**Issue:** `MenuCopy.fourthTitle` and `FourthCopy.label` each map all ten slots by hand. If a new slot is added to one but not the other, the menu and the announcement will name it differently.

**Fix:** Derive the title-case form from `FourthCopy.label`, or share one table.

### IN-05: `FourthSlot` / `dockFourth` / `fourthNames` now also cover halves and thirds (carried forward)

**File:** `Sources/TransomModel/Fourths.swift:5-7`, `Sources/TransomEngine/Command.swift`, `Sources/TransomMac/Input/Hotkeys.swift:214-215`

**Issue:** The names are misleading now that these types also cover halves and thirds. Only the `Command` case names are a persistence contract.

**Fix:** Optionally rename the internal types (`DeskShare`, `dockPositionNames`), and keep `Command.dockFourth` as it is.

### IN-06: Arrange All's "nothing placed" branch is not covered by the per-window skip (carried forward)

**File:** `Sources/TransomEngine/Arranger+Commands.swift:160-161`

**Issue:** The `largestTile` branch catches an `insertLeaf` failure and counts that window as skipped ("a full split"). The `else` branch calls `trial.tree.applyDrop(.layoutEdge(.right), …)` without a catch. If the root is a same-axis split already at `LayoutTree.maxChildren`, or the tree is at `maxNodes`, and none of its leaves is placed, the throw escapes `candidate.edit`. The whole Arrange All then fails as a fault, where it should skip that one window. This is unlikely in practice.

**Fix:** Wrap the `applyDrop` in the same `do { … } catch { skipped += 1; continue }` as the `insertLeaf` branch.

### IN-07: A home frame for a window absent from `world` is still written into every set where it floats, and that branch has no test

**File:** `Sources/TransomMac/LayoutStore.swift:188-191`, `Tests/TransomMacTests/LayoutStoreTests.swift:523-536`

**Issue:** When the window is in no desk of `contents.world`, the loop writes `home.frame` into every layout set where the window is a shown floater. A home frame comes from one World only. If the same window floats in two stored sets, the set that did not park it loses its frame. This is the original WR-01 pattern, now limited to windows absent from the current World. A legacy set records no provenance, and World schema 1 decode drops the hidden-Desktop flag, so the right set cannot be identified exactly. That is why this is Info.

The only new test exercises the in-`world` branch. Nothing checks that the absent-from-`world` branch rewrites a parked set floater at all.

**Fix:** Add a fixture test for the absent-from-`world` branch (window only in a set, with a home frame → the set's stored frame becomes the home frame). Optionally, rewrite only when a single set holds the window as a shown floater, and log the ambiguous case instead of guessing.
