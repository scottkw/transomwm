### CR-01: A view on a node that becomes an empty area stops arranging that display and blocks zooming out

**Files modified:** `Sources/TransomEngine/Arranger+Camera.swift`, `Tests/TransomEngineTests/ArrangerFourthTests.swift`
**Commit:** 58d6a44
**Status:** fixed: requires human verification (zoom state logic)
**Applied fix:** `Arranger.exists(_:in:)` now treats an empty area (`.spacer`) as gone, as well as a missing node. Every place that resolves a view uses it:
- `resolvedView` uses it for the committed view and for the fallback along the stored path.
- `currentView` drops a pending target that is gone or now an empty area.
- `zoomTo` refuses such a target.

`cameraSettle` commits a pending target as before. Its `planShown` then resolves the fallback through `effectiveView`.
**Test:** `aViewOnALeafThatBecomesAnEmptyAreaFallsBackAndZoomOutWorks`:
1. Start from [a | W] with zoom on and zoom into W.
2. Dock W to the top half. W's old leaf becomes a spacer under the same NodeID.
3. Settle and replan.

The test asserts there is no `.fault`, the view is no longer the spacer, and `zoomTo(.home)` emits a camera move. Without the fix it failed with `invariantViolated("root n2 is an empty area")` on every replan and on zoom-out.

### WR-01: Dragging a docked window into the empty area beside it is a silent snap-back

**Files modified:** `Sources/TransomModel/TreeEdits.swift`, `Sources/TransomEngine/Arranger.swift`, `Tests/TransomEngineTests/ArrangerDragTests.swift`
**Commit:** 545888a
**Status:** fixed: requires human verification (drag behaviour)
**Applied fix:** New model edit `LayoutTree.move(_ id:into spacer:)` covers E4 and E6. The leaf takes the spacer's NodeID slot and weight, and the leaf's old slot becomes a spacer. It then normalises and validates, all in one edit. In `Arranger.dropping`, a `.fill(s)` target on the desk where the leaf is already docked now calls `move`, not remove-then-fill. This covers a single panel and a docked, non-floating group. A tab dragged out of a group, a floater and a window from another desk still take the old path.
**Test:** `aDockedWindowDraggedIntoTheEmptyAreaBesideItMovesThere` checks two layouts:
- [a | _] (Left Half): dragging a to the right edge band gives [_ | a].
- [_ | a | _] (Center Third): dragging a to the right edge band gives [_ | a].

Each case asserts:
- The preview is exactly the drop.
- The root is `[.spacer, .panel(a)]`.
- The weights and frame match the Right Half and Right Third docked from scratch (E1).
- The drag adds one undo step.

Without the fix, both cases snapped back.

### WR-02: The one-way schema 4→5 upgrade goes ahead when the pre-migration backup fails

**Files modified:** `Sources/TransomMac/LayoutStore.swift`, `Tests/TransomMacTests/LayoutStoreTests.swift`
**Commit:** 71514f6
**Applied fix:** `load()` now checks `backUp`'s result. When an older-schema file cannot be backed up, `savingDisabled` is set and an error is logged, so `layout.json` stays as it was for the session. This uses the same mechanism as `.newerVersion`.
**Test:** `aFailedBackupBeforeMigratingDisablesSaving` sets up a schema-4 file in a read-only directory, so the copy fails. It asserts `savingDisabled`, that `save` returns false and that the file is unchanged. Before the fix, `save` threw `writeFailed`.
