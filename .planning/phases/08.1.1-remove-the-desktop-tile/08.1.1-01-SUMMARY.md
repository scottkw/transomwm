# Phase 8.1.1 Plan 01: Desktop Tile Migration Summary

**layout.json schema 3 (World 1) now loads through a decode-only LegacyNode path that validates the whole legacy tree, drops the Desktop tile through the tree's own removeLeaf and saves as schema 4 / World 2, and parked floaters come back at their home frames on the first restore.**

## Performance

- **Duration:** about 8 min from the recorded start
- **Completed:** 2026-11-06
- **Tasks:** 3
- **Files modified:** 15 (2 created)

## Accomplishments

- `LegacyNode` plus `LayoutTree(legacyRoot:nodes:states:)`. A Desktop node is allowed only at n0. It becomes a stand-in panel, the full tree goes through `validate()` (cycles, single-child splits, bad weights and duplicates are rejected, never repaired), and then the stand-in leaves through `removeLeaf`. The tile's share goes back by weight, one-child splits collapse, same-axis children merge, and a desk that held only the Desktop tile gets `root == nil`.
- `World.currentSchemaVersion = 2` and `LayoutFile.schemaVersion = 4`. `LayoutStore` decodes schemas 2, 3 and 4. `Desk.validate` no longer requires a Desktop tile. New desks still get one (`Desk.init` is unchanged until 08.1.1-09).
- `LayoutStore.migrationLine` logs one `persist` line with counts only, e.g. "migrated layout.json schema 3 to 4: dropped 2 Desktop tiles, brought back 1 parked windows".
- `Arranger.bringBackParked()` runs right after `reattach` succeeds. It returns stranded floaters that have a home frame to `Recovery.destination`. Desks whose Desktop is still hidden are skipped. It adds no undo step, and it runs once because the home frame is cleared.
- REQUIREMENTS.md: 7 requirements reworded and reopened, TILE-23 reopened, TILE-15 superseded, ZOOM-11 retired, TILE-24..26 added, total now 93. The ROADMAP's 8.1.1 Requirements line is filled in.
