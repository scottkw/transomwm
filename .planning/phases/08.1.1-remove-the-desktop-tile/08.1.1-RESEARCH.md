## Summary

The Desktop tile is a leaf of the layout tree at the reserved `NodeID(raw: 0)`. About 40 source files depend on it, along with tests for it in about 54 test files. Most engine code already copes with a desk that has no Desktop node: `isDesktopHidden` returns `nil`, `Resolution.desktopRect` returns `nil`, and many call sites fall back with `?? area`, which is already the UI-SPEC's substitution rule. The real work is in about a dozen places where the code silently assumes the Desktop leaf exists. With no Desktop leaf those places **beep, throw `nodeNotFound(n0)` or refuse** instead of failing to compile: Snap, Move Out of Group / tear-off, ⇧-undock, Arrange All and New Windows: Tile on an empty desk, Split with New Finder Window, the empty-desk drag, and the relaunch of windows a hidden Desktop had parked. A probe in a throwaway worktree flipped only the default desk to an empty tree. It produced 212 failing tests in two test targets, and a crash (`root!` in a test helper) that killed the Engine target's run. So the test churn is large, and it is the main cost of the phase.

Persistence has a trap. The legacy `Node.desktop` case is a synthesized-`Codable` enum case. Every layout.json on disk (schema 1, 2 and 3) contains `"0":{"desktop":{"hidden":…}}`, so deleting the case makes every old file fail to decode and get set aside as corrupt. Migration must therefore decode the legacy node shape in the model and drop it with the tree's own `normalize()`. **Undo history is not persisted at all** ("Session state only: not Codable", Undo.swift:6), so D-03 needs no code. Parked windows need runtime help: on relaunch, `reattach` records the window's *current* frame, the 1-pt park sliver, as its floating frame (Arranger.swift:788). Dropping the node alone would leave those windows stranded. The home frames in the file are exactly the parked floaters, so a one-shot "bring back floaters with home frames" step at restore fixes it.

D-12 (the collapsed "minimize") was **not caused by the Desktop tile**. In the user's `[TextEdit | Desktop | Safari]` thirds, a 3rd-column fourth gives Safari 1/4 of the width. Without the Desktop tile, `[TextEdit | Safari]` gives Safari the same 1/4. The existing FourthTests table already proves both rows. The Desktop tile only squeezed TextEdit (1/4 instead of 1/2). Recommend: defer the collapse UX to Phase 9 and add one regression row here. Halves and thirds generalise the fourths with five new `FourthSlot` cases. `insertFourth`/`fourthShares` only read `slot.span`, so the arithmetic, `DropTarget.fourth`, `Command.dockFourth`, the dock-URL rate limit, `Hotkeys.fourthNames`/`logSystemConflicts` and the availability rule all cover the new commands with no new code paths.

**Primary recommendation:** Work "compile-first, expand then contract". First add the migration and halves/thirds (green). Then flip new desks to empty and fix the dozen behavioural sites and their tests. Last, delete the `Node.desktop` case and every leftover symbol, using the compiler's errors as the exhaustive checklist. Verify each plan with module-scoped `swift test --filter`, and run the full suite at each wave end.

### Pattern 1: Compile-first "expand, then contract"
**What:** Do the additions and the migration while `Node.desktop` still compiles, then flip behaviour, then delete the case and let the compiler list every leftover.
**Why here:** Deleting `case desktop(hidden: Bool)` at once breaks compilation in every module and every test target, and SwiftPM must compile all test targets before running any filter. Plans would have no green checkpoint.
**Verified fact enabling per-plan checks:** `swift test --filter 'TransomModelTests\.'` runs exactly the model target (242 tests), and `--filter 'TransomEngineTests\.ArrangerFourthTests'` runs one suite (52 tests) `[VERIFIED: run this session]`. A plan can therefore be green on its own suites while unrelated suites still fail at runtime, as long as everything compiles.

### Pattern 2: Migration = legacy decode in the model, versioned by the World's own schema
**What:** Bump `World.currentSchemaVersion` 1 → 2 and `LayoutFile.schemaVersion` 3 → 4. `World.init(from:)` accepts inner version 1 (legacy shape: decode `[NodeID: LegacyNode]`, drop node 0, `normalize()`, `validate()`) and version 2 (strict `Node`, no Desktop case). Every World in the file (the current `world` and every `layoutSets[].world`, schema-1 files through `LayoutFileV1`) migrates automatically because they all go through `World.init(from:)`.
**Why not JSON surgery:** Dropping a child can leave a one-child split whose only child has the same axis as its grandparent. That needs the collapse-then-merge loop of `collapseOrMergeOnce()` plus `clamped()` weights. Re-implementing it on `[String: Any]` duplicates `normalize()`. The model's own `normalize()` is internal to TransomModel, so the drop must live there.
**Why version-gated rather than "always tolerate a Desktop node":** It keeps schema 4 strict (T-03-15, reject on any doubt), so a v2 World with a Desktop node is rejected, not silently fixed.
**`World.decode(from:migrations:)` (tests only, Persistence.swift:34-73):** today it runs the JSON `MigrationChain` for any `version < currentSchemaVersion`. After the bump, an inner v1 World would go to the chain and throw `missingMigration(from: 1)`. Make the chain run only below the oldest natively readable version (1); `World.init(from:)` handles 1 and 2. PersistenceTests:262 (`.newerVersion(found: 2, supported: 1)`) changes to 3/2.
**What the migration does NOT need:**
- Undo history: not persisted. Verbatim: `/// Session state only: not Codable and not part of World, so saved layouts never carry undo stacks.` `[VERIFIED: Sources/TransomModel/Undo.swift:6]`. D-03 is satisfied by construction. Every launch also resets it: `history = UndoHistory()` in `reattach` `[VERIFIED: Arranger.swift:742]`.
- Saved views: they hold window identities, never NodeIDs (`/// Never a NodeID or a rect`, SavedViews.swift:5). A view saved while framing the Desktop holds only floating identities. `viewDestination` maps them through `leafNode(of:)`, which after this phase returns nil for floaters. `Navigator.lowestCommonAncestor([])` returns nil (`guard var common = paths.first else { return nil }`, Navigator.swift:53), so the view goes `.home` with `allGone == false`. That is exactly the UI-SPEC's "becomes the whole-display view". No file rewrite is needed.
- Floating frames: kept as stored (D-02).

### Pattern 3: Halves and thirds are five more `FourthSlot` cases
**What:** `FourthSlot.span` is the only thing `insertFourth`, `fourthSpan` and `fourthShares` read from a slot. Add `.firstHalf (0, 0.5)`, `.secondHalf (0.5, 1)`, `.firstThird (0, 1/3)`, `.middleThird (1/3, 2/3)`, `.lastThird (2/3, 1)` (names at the planner's discretion). Then:
- `DropTarget.fourth(FourthSlot, Axis)`, `applyDrop`, `Arranger.dropping`'s `nameFourth`, `dockFourth`, `fourthChangesNothing`, `commit`'s collapse/refusal: unchanged.
- `TransomURLRateLimiter.admitOpenedURL`: `guard case .dockFourth = command` already puts all twenty in one shared bucket (UI-SPEC "all twenty dock commands share one one-per-second limit"). `[VERIFIED: TransomURL.swift:112]`
- `Hotkeys.fourthNames` (`entries.compactMap { if case .dockFourth = $0.command … }`) already covers all twenty for `logSystemConflicts` (UI-SPEC note 4). `[VERIFIED: Hotkeys.swift:196]`
- `Arranger.availability`: `case .moveOrSnap, .dockFourth:` gives halves/thirds the fourths' rule (UI-SPEC Surface 3). `[VERIFIED: Arranger.swift:913]`
- `FourthZones` (drag bands) uses its own fixed five-slot table. It is unaffected, so there are no drag regions for halves/thirds (UI-SPEC).
- The exhaustive switches that must grow (the compiler lists them): `FourthCopy.label(_:_:)` and `label(_:_:span:)` (DragSession.swift:98-120), `MenuCopy.fourthTitle` (MenuCopy.swift:60), and test helpers. `FourthSlot.allCases` appears only in `TreeFuzzTests.swift:67`, which then fuzzes the new slots too.
- Naming: renaming `FourthSlot`→`DockSlot` and `.dockFourth`→`.dockShare` is optional churn. No raw value of `FourthSlot` is persisted or printed: `grep 'slot.rawValue|FourthSlot(rawValue'` finds nothing in Sources. Recommend keeping the names and adding a doc comment, so the diff stays small (CLAUDE.md premature-abstraction / Ponytail guidance).

Arithmetic check against the UI-SPEC "grown spans" table:
- Right Third on `[A]`: `end == 1`, so `index = count`, `after = 0` and `end = 1`. W gets `[2/3, 1]`, labelled "Right third".
- Center Third on `[A]`: the position 0.5 equals A's centre, so W goes before A (`>= position - 1e-9`, "A tile centred exactly at the window's position goes after it"). `before = 0` and `start = 0`, so W gets `[0, 2/3]`, labelled "Left two thirds". This matches the UI-SPEC's grown spans, but users may find it surprising. Note it for UAT.

### Pattern 4: An empty desk is `root == nil`, and the code paths that must grow a root branch
The model already supports it: `insertFourth`'s `guard let root else { return try insertRootLeaf(…) }` (Fourths.swift:49), `fourthSpan`'s `guard let root else { return (0, 1) }` (Fourths.swift:70), `applyDrop`'s `.emptyLayout` and `.layoutEdge` with no root (DropZones.swift:59-63), `resolve`'s `guard let root = tree.root else { return result }` (Resolve.swift:60), and `DropZones.target`'s `guard tree.root != nil else { return .emptyLayout }` (DropZones.swift:29).
These Engine paths have **no** root branch and fall through to a beep or a float:
- `autoTile`: `guard let (target, rect) = tile ?? Self.largestTile(resolution, in: desk.tree) else { return [] }` (Arranger+NewWindows.swift:33). On an empty tree `largestTile` is nil, so the window floats. D-08 needs `insertRoot`.
- `arrangeAll`: the same `largestTile` guard (Arranger+Commands.swift:151). On an empty desk every window is "skipped", so it beeps. Make the first window the root.
- `finderSplit`: `let target = focused.flatMap { … } ?? .desktop` (Arranger.swift:1556). UI-SPEC discretion 6 says to use the largest tile, or `.emptyLayout` on an empty desk.

### Anti-Patterns to Avoid
- **Deleting `Node.desktop` before a legacy decoder exists:** every user's layout.json becomes "corrupt" and is set aside (`LayoutStore.setAside`). Their layouts are lost.
- **Treating "drop the node" as the whole parked-window fix:** see Pitfall 2.
- **Changing `DropZones.target` for the empty-desk band:** the keyboard `.dock` ("Where It Is") goes through `Planner.dockTarget` → `DropZones.target`. It must still get `.emptyLayout` anywhere (UI-SPEC note 1). Filter `.emptyLayout` to the 24 pt band in `Arranger.hover` instead.
- **Removing `Decision.clampInto` wholesale:** the tear-off landing preview uses it too (`Decision(action: .tearOffFloat(key), display: uuid, clampInto: try tearOffDesktop(window, on: key) ?? display.visibleFrame)`, Arranger+Tabs.swift:910). UI-SPEC note 2 says "both go", but only the crossing-clamp uses go. Keep `clampInto` with `display.visibleFrame` for tear-off.
- **Reusing the retired `Name` raw values** `toggleDesktop`/`frameDesktop`: user bindings are stored under `KeyboardShortcuts_<name>` (Hotkeys.swift:6-7, Pitfall 13).

## Common Pitfalls

### Pitfall 1: Deleting the enum case makes every old layout.json "corrupt"
**What goes wrong:** `Node` has synthesized `Codable`, and the case name is its JSON key. Without the case, decoding `"0":{"desktop":{…}}` throws. `LayoutStore.load` then logs "rejected", moves the file to `layout.json.corrupt-<ts>` and starts empty (LayoutStore.swift:53-54). Every user would lose every layout.
**How to avoid:** Keep a decode-only `LegacyNode` with the same four case names (`split`, `panel`, `tabs`, `desktop(hidden:)`) inside TransomModel, used only for inner World schema 1.
**Warning signs:** `LayoutStoreTests` loading `LayoutFileV1Fixture.json` fails with `.corrupt`.

### Pitfall 2: Parked windows stay at the sliver after migration
**What goes wrong:** At relaunch, `reattach` runs `try candidate.recordFloatingFrame(info.frame, for: info.window)` for every present floater (Arranger.swift:788). For a window a hidden Desktop parked, `info.frame` is the park rect: 1 pt on screen, `DisplayInfo.parkedFrame` (WindowSystem.swift:19-31). Today `showingDesktop()` later restores `homeFrames`. After this phase nothing calls it, so the window stays a sliver forever.
**How to avoid:** In the `.restore` path after `reattach`, for each tracked present floating window that is not a hidden tab, has `homeFrames[id]`, and `Recovery.isStranded(info.frame, displays:)`: emit `.setFrame(window, Recovery.destination(for:home:display:))` and `recordFloatingFrame` (the `showParkedDesktops(keeping:)` pattern, Arranger.swift:874). Count them for the UI-SPEC log line ("brought back {m} parked windows"). It is one-shot by construction: floater home frames are cleared on every handle once no Desktop is hidden.
**Warning signs:** The VM fixture check (UI-SPEC backstop) shows FileZilla still missing after the update.

### Pitfall 3: Silent beeps and throws where the Desktop *leaf* was assumed
These all compile and only fail at runtime (the probe hit the tear-off one):
- `snap`: `let desktop = try Planner.plan(…).desktopRect` inside a `guard … else { return [.beep] }` (Arranger+Commands.swift:79-83)
- `tearOffDesktop`: `try desk.tree.setDesktopHidden(false)` throws `nodeNotFound(n0)` (Arranger+Tabs.swift:898). The probe log shows `"group n2: move out of window 2 … failed: nodeNotFound(n0)"`
- ⇧-undock: `guard let plan = dragPlan(.undock), let desktop = plan.desktopRect, plan.unfit.isEmpty, … else { … .refuse(Self.noRoom) }` (Arranger.swift:1886-1891), so every ⇧-drag of a docked window would be refused
- `autoTile` / `arrangeAll` `largestTile` guards; `finderSplit` `?? .desktop`
**How to avoid:** Fix these in Plan 02/03 with one test each, *before* deleting the case (Pattern 1).

### Pitfall 4: The empty desk turns every floating drag into a full-screen dock
**What goes wrong:** `DropZones.target` returns `.emptyLayout` for any point when `root == nil` (DropZones.swift:29). In Automatically mode, any drag of a floating window on an empty desk previews and docks full screen.
**How to avoid:** In `Arranger.hover`, keep `.emptyLayout` only when the pointer is within `DropZones.displayEdgeBand` (24 pt) of the visible frame's edge, else nil (UI-SPEC discretion 2). Leave `DropZones.target` and the keyboard path alone.

### Pitfall 5: Group dwell over a floating window has no z-order information
**What goes wrong:** UI-SPEC discretion 3 says "the front floating window wins a group dwell over the tile beneath". The engine has no docked-vs-floating z-order. `DesktopLayer.windows` is "back to front" among floaters only, and the real stacking is only in the shell's `CGWindowList.onScreenFrontToBack()`. `floatingGroupTarget` (Arranger+Tabs.swift:243-257) already picks the frontmost floater under the pointer and checks its centre.
**How to avoid:** Run `floatingGroupTarget` first for every hover target, not only when `overDesktop`, and let a hit win. That assumes a floater under the pointer is in front of the tile, which is usually true since the user just interacted with it `[ASSUMED]`. Real z-order would need a new shell input, which is out of scope.

### Pitfall 6: `NSMenuItem` can belong to one menu only
**What goes wrong:** `.dock`'s item moves into the persistent Dock Window submenu (built once in `CommandMenu.init`). If `addArrangeItems` still adds `commands.item(for: .dock)` to the status menu, AppKit raises "already in another menu" at menu open.
**How to avoid:** Remove `.dock` from the `[Command.dock, .float, .swapPrevious, .undo]` loop (StatusItemController.swift:132), and add the Dock Window parent first. A `CommandMenuTests` case asserts the item's `menu` is the submenu.

### Pitfall 7: Hundreds of test edits; one `root!` crashes a whole target
**What goes wrong:** The probe flipped only the `Desk` default. It gave 212 failing tests, mostly `Caught error: .nodeNotFound(n0)` from `of: .desktop` docking, plus 36 in LayoutStoreTests. Then `TransomEngineTests/ArrangerFourthTests.swift:35: Fatal error: Unexpectedly found nil while unwrapping`, which ended the Engine target's run with no summary. Hand-computed rect expectations that assumed a Desktop share (e.g. FourthTests' table, PlannerTests) change values, not just setup.
**How to avoid:** Add the per-target helper first. Re-derive table expectations rather than patch them. Treat "Test run with N tests" for **each** of the 4 targets as the pass signal (a crash prints no summary for that target).

### Pitfall 8: Floating-point thirds in label switches
`FourthCopy.label(_:_:span:)` switches on exact span tuples (e.g. `case (0, 0.75)`). The spans `fourthShares` returns are either the slot's literals or exactly 0/1, so exact matching works if the thirds use the same constant (`1.0 / 3`, `2.0 / 3`) in the slot table and the label switch. Define them once (e.g. `static let third = 1.0 / 3`) to avoid `0.3333…37` vs `0.3333…3` drift.

## Code Examples

### Legacy decode (sketch; in TransomModel, internal)
```swift
// Source: shape read from LayoutTree.swift:3-11 (synthesized Codable) and LayoutFileV1Fixture.swift ("0" : { "desktop" : { "hidden" : false } })
/// Decode-only: the node shape of World schema 1, with the Desktop tile (Phases 3–8.1).
enum LegacyNode: Decodable {
    case split(axis: Axis, children: [NodeID], weights: [Double])
    case panel(WindowRef)
    case tabs(windows: [WindowRef], selected: Int)
    case desktop(hidden: Bool)
}

extension LayoutTree {
    /// A schema-1 tree without its Desktop tile: the tile's share goes back to its siblings and a split left with one
    /// child collapses (D-02), by the same `normalize()` every edit uses. Rejects a Desktop tile anywhere but NodeID 0.
    init(legacyRoot root: NodeID?, nodes legacy: [NodeID: LegacyNode], states: [WindowIdentity: WindowState]) throws(LayoutError) {
        var nodes: [NodeID: Node] = [:]
        var desktop: NodeID?
        for (id, node) in legacy {
            switch node {
            case let .split(axis, children, weights): nodes[id] = .split(axis: axis, children: children, weights: weights)
            case let .panel(window): nodes[id] = .panel(window)
            case let .tabs(windows, selected): nodes[id] = .tabs(windows: windows, selected: selected)
            case .desktop:
                guard id.raw == 0, desktop == nil else { throw .invariantViolated("Desktop tile at \(id)") }
                desktop = id
            }
        }
        var tree = LayoutTree()
        tree.root = root == desktop ? nil : root
        if let desktop, let parent = nodes.first(where: { if case let .split(_, c, _) = $0.value { c.contains(desktop) } else { false } })?.key,
            case let .split(axis, children, weights)? = nodes[parent], let i = children.firstIndex(of: desktop) {
            var c = children, w = weights
            c.remove(at: i); w.remove(at: i)
            nodes[parent] = .split(axis: axis, children: c, weights: w)
        }
        tree.nodes = tree.root == nil ? [:] : nodes
        tree.states = states
        tree.normalize()          // collapse the one-child split, merge same-axis, renormalise weights
        try tree.validate()       // every hostile-file check still runs
        self = tree
    }
}
```
Note: `normalize()` is iterative and bounded (`collapseOrMergeOnce` removes a node per pass), so a hostile legacy file cannot loop it. The planner must also keep `World.init(from:)`'s record-level checks (duplicate desk keys, duplicate state records).

## D-12 Investigation: the collapsed "minimize" in 08.1 UAT

**Evidence:** "the desk was `[TextEdit | Desktop tile | Safari]` in thirds (read from layout.json). A 3rd-column drop left Safari too narrow; it most likely collapsed (the user saw it as minimized; not confirmed)" `[VERIFIED: .planning/phases/08.1-window-behaviour-options/08.1-UAT.md:36]`.

**Arithmetic with and without the Desktop tile** (existing rows, `[VERIFIED: Tests/TransomModelTests/FourthTests.swift:79-98]`):
- With the tile (`twoDocked` = three equal children; the slot is `.third`): `after: [("A", 1.0 / 4), ("B", 1.0 / 4), ("W", 1.0 / 4), ("D", 1.0 / 4)]`. Mapped to the user's desk (D in the middle), Safari, the last child, gets **1/4**, and TextEdit gets 1/4.
- Without the tile (`oneDocked`-shaped `[TextEdit .5 | Safari .5]`, slot `.third`): the row `after: [("A", 1.0 / 2), ("W", 1.0 / 4), ("D", 1.0 / 4)]` shows the trailing child gets **1/4**. Safari gets 1/4, and TextEdit gets 1/2.

**Conclusion:** Safari's share is 1/4 of the visible width either way. Its collapse came from Safari's minimum width against a quarter-width tile with zoom on (08.1 "Zoom on and no room: windows collapse"), not from the Desktop tile. The Desktop tile's only effect was squeezing TextEdit to 1/4. It also had a minimum (the per-axis max of the floaters' minimums, FileZilla's here) that could pin more width. That path is deleted by this phase anyway. **Recommendation:** do not fix the collapse here. Log "collapsed block reads as minimized" to Phase 9 (deferred per CONTEXT). Add one FourthTests regression row (`[A .5, B .5]`, `.third` → `B 1/4`) documenting the finding, and re-run 08.1 UAT item 8 (row labels) in this phase's UAT, as the 08.1 UAT deferred it here.

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Hostile legacy layout.json (Desktop node at another ID, two Desktop nodes, Desktop as a split child with a cycle, huge trees) | Tampering / DoS | Legacy path rejects a Desktop node anywhere but ID 0 and more than once. `normalize()` is iterative and bounded. `validate()` (iterative, depth/node limits) runs after the drop. The 16 MB cap and `maxLayoutSets` are unchanged |
| A schema-4 file with a Desktop node (crafted) | Tampering | World schema 2 decodes strict `Node` (no case), so it is rejected and set aside as corrupt |
| Downgrade: an older Transom overwrites a schema-4 file | Tampering (data loss) | Outer schema bump 3 → 4: the old app sees `newerVersion`, leaves the file and disables saving (LayoutStore.swift:48-51) |
| Stale URL `transom://toggle-desktop` from a web page | Spoofing | Not in `TransomURL.commands`, so `parse` returns nil and nothing runs. Logged without contents |
| Ten more dock URLs amplify undo flushing | DoS | Shared one-per-second dock bucket (`case .dockFourth`) already covers them |
