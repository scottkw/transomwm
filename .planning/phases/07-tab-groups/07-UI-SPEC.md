# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 7 adds tab groups (TABS-01..06). It **extends** `03-UI-SPEC.md`, `04-UI-SPEC.md` (approved 2026-10-27) and `06-UI-SPEC.md` (approved 2026-10-31), and keeps every token, timing, panel property, colour recipe, copy rule, Debug-line style and announcement pattern from them. Where this spec says "Phase 3 Surface N" or "Phase 4 Surface N", that surface applies unchanged.

Phase 7 adds seven surfaces:

1. the **Group drop preview**: a new drop-preview state shown after the pointer rests in a tile's or floating window's centre (TABS-01, D-01..D-03)
2. the **tab strip**: a persistent, non-activating panel along the top of every tab group, with the group buttons and one tab per member (TABS-02, TABS-03, D-04..D-06)
3. **switching and hiding tabs**: what the user sees when a tab is clicked, when a hidden member is activated another way, and how hidden members are parked (TABS-02, D-07..D-09)
4. **leaving a group**: tearing a tab out of the strip, the tab context menu, and how a group dissolves (TABS-04, TABS-06, D-10..D-12)
5. **group-wide actions**: close, minimise and dock/float for the whole group, and what Phase 3/4 commands do to a group (TABS-03, D-06)
6. **groups on the zoom stage and in the overview** (Claude's discretion)
7. the **Tabs submenu**, three new hotkeys and URLs, Shortcuts rows, Debug line, log lines and announcements

Not in this phase: reordering tabs by dragging within the strip (deferred), merging two whole groups by dropping one onto another, Settings (Phase 9), saved views and the `transom` CLI (Phase 8).

**Platform rule (unchanged).** Native macOS only. Shell = AppKit (`NSStatusItem`, `NSMenu`, `NSPanel`, `NSAlert`). Overlays = layer-backed AppKit views drawn with Core Animation. SwiftUI only inside `NSHostingController` (the Shortcuts window). Every colour is a semantic system colour except the Phase 4 app colour. Every font is a system text style.

**Phase 2/3/4 review rules still apply:** no `.font(.system(size:))` for glyphs, no padding stacked on a system inset, no duplicated controls within one surface, no per-row AppKit lookups when the menu rebuilds. App names, icons and app colours come from the per-pid cache.

**Clean-room rule.** Every string, default key and visual below was written fresh for Transom. None of TrellisWM's tab-bar visuals, copy or hotkeys is used, and Safari's or Finder's tab bar is not copied: the strip is a separate rounded bar above the window, not a title-bar extension.

**Spelling.** UI strings use US English ("Minimize", "canceled"). Planning prose may stay British.

**Vocabulary added by this spec.**
- **Tab group** (UI copy) / **group** (this spec): two or more windows, from any apps, sharing one tile or one floating frame. Model: `Node.tabs(windows:selected:)`.
- **Member**: a window in a group. **Tab**: a member's entry in the strip. **Selected tab**: the one member on screen. **Hidden tab**: every other member, parked.
- **Group frame**: the tile rect (docked) or floating frame of the group, strip included. **Content rect**: the group frame minus the 32pt band at its top. Every member is sized to the content rect.
- **Tear off**: dragging a tab out of the strip. **Dissolve**: a group left with one member becomes a plain tile or floating window.
- **Group dwell**: the 400 ms rest in a centre zone that turns a drop into grouping.

## Spacing Scale

All values are in points. The token scale is unchanged: 4 / 8 / 16 / 24 / 32 / 48 / 64.

| Token | Value | Phase 7 usage |
|-------|-------|---------------|
| xs | 4pt | Inner padding of the strip on every side; gap between group buttons; gap between tabs; gap between a tab's icon and its title; gap between the strip and the content rect; vertical padding of the tear-off ghost; pointer travel below which a press on a tab is still a click |
| sm | 8pt | Horizontal padding inside a tab and inside the tear-off ghost; gap between the last group button and the first tab; offset of the tear-off ghost from the pointer (right and down) |
| md | 16pt | Rest radius of the group dwell (the pointer must stay within 16pt of where the dwell started); minimum label clearance inside the Group preview (Phase 3 rule) |
| lg | 24pt | Cascade offset (right and down from the group's top-left) for a window moved out of a group or floated by Restore All Windows |
| xl–3xl | 32 / 48 / 64pt | 32pt only as the reserved band height and the icon-only tab width (sizes, see Exceptions). Not used as spacing |

Exceptions (non-spacing metrics, listed so the checker and auditor can find them):
- **Reserved band: 32pt** = strip height **28pt** (D-04) + 4pt gap. The content rect is the group frame minus this band at the top. Both are on the 4pt grid.
- **Controls inside the strip: 20pt tall** (28 − 2 × 4). Group buttons and the overflow button are 20 × 20pt.
- **Tab widths.** Tabs share the tab region equally: `(region − 4 × (n − 1)) / n`. At **96pt or wider** a tab shows icon + title; from **32pt up to 96pt** it shows the icon only; below 32pt the overflow rule applies (Surface 2).
- **App icon in a tab and in the ghost: 16 × 16pt** (a size, like Phase 4's 64pt and 32pt icons).
- **Tear-off ghost: max width 240pt**, height = Body line 16pt + 2 × 4pt = 24pt.
- **Minimum strip width for buttons: 116pt** = 4 + 3 × 20 + 2 × 4 + 8 + 32 + 4. Below it the group buttons hide (Surface 2).
- **Corner radii.** Strip 8pt (the Phase 6 thumbnail token). Tabs, group buttons, the overflow button and the ghost are capsules (radius = height / 2 = 10pt, 12pt for the ghost). The Group preview keeps the Phase 3 12pt radius; its strip band uses 8pt.
- **Stroke widths.** 1pt `separatorColor` for the strip border and the ghost border; 1pt `labelColor` for the selected tab under Increase Contrast only. The Group preview keeps the Phase 3 2pt border.
- **Small offsets.** The clamp ghost's top edge sits 12pt above the pointer during a tear-off, so the window's title bar lands under the pointer. The Group preview's strip band is inset 2pt inside its border, matching the Phase 3 2pt border. On the zoom stage the strip radius scales with the camera but is never under 2pt, so it stays visibly rounded.
- **System metrics.** Menu, context-menu, toast and `Recorder` metrics are system-drawn or Phase 3's. Never override them.

## Color

Semantic system colours only, no hex literals in code. Hex values are references resolved on macOS 27 with the default appearance. The Phase 3 appearance rule applies to the strip and every new layer: `CGColor`s re-resolved inside `effectiveAppearance.performAsCurrentDrawingAppearance { … }` on appearance change and on `NSColor.systemColorsDidChangeNotification`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | The user's windows and wallpaper | The selected member fills the content rect; Transom adds no opaque surface except the strip |
| Secondary (30%) | `windowBackgroundColor` (ref light `#FFFFFF`, dark `#1E1E1E`) for the strip and the tear-off ghost; `separatorColor` for their 1pt borders; `labelColor` tints for tab and button hover, press and selection; `secondaryLabelColor` for unselected tab titles and button glyphs | The strip is quiet, neutral chrome that matches the Phase 4/6 capsules |
| Accent (10%) | `NSColor.controlAccentColor` (ref default `#0088FF` light, `#0091FF` dark) | Only the elements listed below |
| Destructive / refusal | `NSColor.systemRed` (ref `#FF383C` light, `#FF4245` dark) | Phase 3 Blocked preview only, now also shown for a group drop that leaves no room (zoom off). **No Phase 7 control is red**: Close Group and Close Tab ask the apps to close their windows, which then show their own save prompts |
| Warning | `NSColor.systemOrange` | Not used by Phase 7 |

Accent reserved for exactly these elements (extends the Phase 3/4/6 list, which stays valid):
1. Phase 3, 4 and 6 uses (drop preview, swap origin, gap handles, rect-zoom target preview, pick-mode ring, collapsed-block hover ring, overview selection ring, system-drawn uses)
2. The **Group drop preview**: its frame fill and border and its strip band

The accent is **not** used anywhere in the tab strip (selected tab, hover, buttons, overflow), on the tear-off ghost, in the context menu or in the Tabs submenu. Selection inside the strip is neutral, like the current-Space marker in Phase 6.

**Overlay colour recipe (new rows).** Alpha is applied to the semantic colour.

| Element | Fill | Border | Content |
|---|---|---|---|
| Strip | `windowBackgroundColor` 100%, 8pt radius | `separatorColor` 1pt, inside | buttons, tabs |
| Tab, rest | none | none | icon 100%, title `secondaryLabelColor`, Body |
| Tab, hover | `labelColor` 8% | none | as rest |
| Tab, pressed | `labelColor` 16% | none | as rest |
| Tab, selected (hover or not) | `labelColor` 16% | none | icon 100%, title `labelColor`, Heading |
| Group button / overflow button, rest | none | none | glyph `secondaryLabelColor` |
| Group button / overflow button, hover | `labelColor` 8%, circle | none | glyph `labelColor` |
| Group button / overflow button, pressed | `labelColor` 16%, circle | none | glyph `labelColor` |
| Tear-off ghost | `windowBackgroundColor` 100%, capsule | `separatorColor` 1pt | icon, title `labelColor`, Body |
| Group preview, frame | `controlAccentColor` 20%, 12pt radius | `controlAccentColor` 85%, 2pt solid | label capsule centred in the content rect |
| Group preview, strip band | `controlAccentColor` 50%, 8pt radius | none | none |
| Group preview label | Phase 3 overlay label (`windowBackgroundColor` capsule, `separatorColor` 1pt) | | glyph `rectangle.topthird.inset.filled` (`labelColor`) + copy, Heading |

**Increase Contrast**: Phase 3 rule. Fill alphas × 1.5 (8→12, 16→24, 20→30, 50→75), every alpha'd border at 100%, and the selected tab gains a 1pt `labelColor` border. `separatorColor`, `windowBackgroundColor` and `secondaryLabelColor` adapt by themselves. **Differentiate Without Color**: the selected tab differs by fill **and** semibold title; the Group preview differs from Dock by its strip band and label. **Reduce Transparency**: nothing translucent is added (strip and ghost are opaque).

## Surface 1 — Making a group: the Group drop preview (TABS-01, TABS-05, D-01..D-03)

**Centre zones.** A docked tile's centre is `DropZone.center` (middle 50% on both axes, unchanged). New: a **floating window on the Desktop tile** also has a centre zone, the middle 50% of its frame on both axes, taken from the topmost floating window under the pointer (never the dragged window). A group's centre zone is the middle 50% of its content rect. The Desktop tile itself has no grouping centre (its centre stays a plain floating move, Phase 3).

**The group dwell.** It starts when the pointer enters a centre zone and completes after **400 ms** during which the pointer stays within **16pt** of where the dwell started and no modifier changes. Moving more than 16pt (still in the same centre) restarts the 400 ms from the new point; leaving the centre zone cancels it. The Phase 3 150 ms preview dwell runs as before inside this window, so for the first 400 ms the user sees exactly the Phase 3 centre behaviour.

| Time in the centre | Dragged window is docked | Dragged window is floating |
|---|---|---|
| 0–150 ms | nothing (Phase 3 dwell) | nothing |
| 150–400 ms | Phase 3 snap-back ghost on its own tile | Phase 3: nothing, or the clamp ghost if the release frame would cross docked tiles |
| ≥ 400 ms, the drop fits | **Group preview** (below), morphing from the ghost over 120 ms `.easeInEaseOut` (Phase 3 target-change morph); from nothing, it fades in over 120 ms | same |
| ≥ 400 ms, the content rect is smaller than the dragged window's minimum size, zoom off | Phase 3 **Blocked** preview over the group frame, "Not enough room" | same |
| same, zoom on | Phase 4 **Collapsed** preview over the group frame, "Collapsed until you zoom in" (the whole group collapses) | same |

Once shown, the Group preview stays while the pointer is anywhere in that centre zone (no second dwell). Leaving the zone hands over to the normal targets (an edge band shows Dock, Phase 3 morph). Coming back needs a new dwell.

**What the Group preview draws** (WYSIWYG: it is exactly what release produces):
- the **group frame**: the target tile's rect (docked target), the target window's current frame (floating target, D-02: the new group floats there), or the existing group's frame (adding a tab), in the Dock colours (accent 20% fill, 2pt 85% border, 12pt radius)
- the **strip band**: the top 28pt of that frame, inset 2pt inside the border, accent 50% fill, 8pt radius: where the real strip will sit
- the **label**, centred in the content rect: glyph `rectangle.topthird.inset.filled` + **"Group as tabs"** (new group) or **"Add as a tab"** (target is already a group). Phase 3 clearance rule: hidden when the content rect is smaller than the label plus 16pt per side

**Modifiers and exclusions.**

| Situation | Result |
|---|---|
| ⇧ held (bypass) | No grouping, no dwell. Phase 3 bypass rules |
| ⌘ held over another docked **panel** | Phase 3 Swap wins over grouping, no dwell. Over a group, ⌘ is ignored and the dwell runs |
| The dragged window's own tile, a collapsed block, the Desktop tile, a gap, an excluded or never-dock target window | No grouping. Phase 3 rules |
| The whole group dragged by its selected window's title bar (Surface 5) onto any centre | No grouping (merging groups is out of scope). Phase 3 miss rules |
| Paused, excluded dragged window, never-dock dragged window | No overlay at all (Phase 3) |

**Release.**

| Released with | Result | Announcement |
|---|---|---|
| Group preview shown, new group | The target and the dragged window form a group at the group frame. The dragged window is the **selected tab** (D-03) and is placed in the content rect; the target window resizes to the content rect and is parked (Surface 3). A docked dragged window's old tile closes and its neighbours reflow (Phase 3). The strip fades in over **120 ms** once the frame writes are sent. The preview fades out over 120 ms (Phase 3) | "Grouped as tabs, 2 tabs" |
| Group preview shown, existing group | The dragged window is appended as the last tab and becomes selected; the previously selected member is parked | "Added as a tab, {n} tabs" |
| Blocked shown | Refused; Phase 3 miss rules | "Not enough room" (Phase 3) |
| Collapsed shown | Accepted; the group collapses (Phase 4 Surface 3, block shows the selected member's icon) | "Docked. Zoom in to see it." (Phase 4) |
| Before the 400 ms dwell completed | **Exactly as today**: Phase 3 miss rules (a docked window snaps back to its tile, a floating window stays where released or is clamped inside the Desktop tile). Transom adds no new refusal here | none |

A drag release is never a keyboard command, so it never beeps (Phase 3). The keyboard **Dock Window** command still maps a centre position to the nearest edge (`Planner.dockTarget`): keyboard commands never create groups.

**Undo.** Making a group and adding a tab are one undo step each on the desk (Undo Layout Change returns the dragged window to its previous tile or floating frame and the target to its plain tile).

## Surface 2 — The tab strip (TABS-02, TABS-03, D-04..D-06, D-09)

**Panel.** One `NSPanel` per group, kept in a recycled pool (the `CollapsedPanels` pattern), created when a group appears and returned when it dissolves.

| Property | Value | Why |
|---|---|---|
| `styleMask` | `[.borderless, .nonactivatingPanel]` | A click on a tab never activates Transom |
| `canBecomeKey` / `canBecomeMain` | `false` (subclass override) | Never takes keys from the app being worked in |
| `ignoresMouseEvents` | `false` | Tabs and buttons take clicks. The panel covers only the strip rect, which no window occupies (the members get the content rect), so it steals nothing from apps |
| Views | `acceptsFirstMouse(for:)` = `true` | The first click on an inactive strip acts at once |
| `allowsToolTipsWhenApplicationIsInactive` | `true` | Tooltips show although Transom is never active |
| `level` | `.normal` | The strip is part of the group, not an overlay: a floating window raised over a floating group covers its strip like any window |
| Ordering | `orderFrontRegardless()` whenever a member of the group is raised, focused or moved into the content rect, and when the group is created | Keeps the strip on top of its own group without ever activating Transom |
| `collectionBehavior` | `[.stationary, .ignoresCycle]`. **No** `.canJoinAllSpaces` | The strip belongs to its group's Space. It is not spread by Mission Control and not in ⌘\` cycling |
| Space changes | A strip whose group is not on the shown Space is ordered out; when the group's Space is shown again, the strip is re-shown, and replaced through `NSWindow.leftOnAnotherSpace(_:)` if macOS left it on another Space (the macOS 27 lock-stranding fix, `debug/resolved/overview-stuck-after-voiceover.md`) | |
| `sharingType` | `.none` | Kept out of Transom's own snapshots (the stage draws the strip itself, Surface 6) |
| `isOpaque` / `backgroundColor` / `hasShadow` / `animationBehavior` | `false` / `.clear` / `false` / `.none` | The strip layer draws the rounded rect |
| Tracking | `NSTrackingArea` `[.mouseEnteredAndExited, .mouseMoved, .activeAlways]` | Hover works in an inactive app |
| Accessibility | The panel **is** an accessibility element (Accessibility section) | It is persistent, interactive chrome, like Phase 4's collapsed-block panels |

**Geometry.** The strip rect is the top 28pt of the group frame, full width. The content rect starts 4pt below it. Left to right inside the 4pt padding:

1. **Group buttons**: three 20 × 20pt circles, 4pt apart, in this order: **Close Group** (`xmark`), **Minimize Group** (`minus`), **Float Group** (`macwindow`, docked group) or **Dock Group** (`rectangle.split.2x1`, floating group). The order mirrors the window buttons (close, minimise, then the size-mode button).
2. **Tab region**: from 8pt after the last button to 4pt before the strip's right edge.

**Tabs.** One per member, in group order (insertion order, D-03 appends), equal widths per the Spacing exception, 4pt apart, capsules 20pt tall.

| Tab width | Content |
|---|---|
| ≥ 96pt | 8pt padding, 16pt app icon, 4pt, title (one line, middle-truncated) |
| 32–96pt | 16pt app icon, centred. The title is the tab's tooltip and accessibility label |
| < 32pt (overflow) | A 20 × 20pt **overflow button** (`chevron.down`) takes the right end of the tab region; as many 32pt icon-only tabs as fit fill the rest. The selected tab is always one of them: if it would fall past the last visible slot, it takes that slot. The overflow button opens an `NSMenu` listing every member not in the strip, each item = its 16pt app icon (`NSMenuItem.image`) + title (app name when untitled), in group order; choosing one selects it |

**A native tab group as a member (D-09).** It is one tab, showing the app icon and the title of the native group's shown tab (`visibleMemberID`). Switching native tabs inside it updates the title; it never adds tabs to the strip.

**Narrow groups.** When the strip is narrower than 116pt, the group buttons hide and the tab region takes the whole strip minus the 4pt padding. The buttons' actions stay reachable: the tab context menu (Close Tab, Move Out of Group), ⌘W / ⌘M in the app, Float Window / Dock Window, and VoiceOver actions on the strip.

**Tooltips.** Tab: its full title (the app name when untitled). Buttons: "Close Group", "Minimize Group", "Float Group" / "Dock Group". Overflow button: "More Tabs".

**Following the group.** The strip tracks the **selected member's** CG bounds (roadmap scope note):
- while the user drags or resizes the selected member, at display rate through the existing `DragFramePoller`, with implicit layer animations disabled, so the strip moves with the window and never trails it by more than a frame
- otherwise on every frame-change event for the selected member, plus a 500 ms CG-bounds poll while the strip is shown, as a backstop for apps that move themselves silently
- the strip is placed from the **group frame** Transom planned whenever the group is at rest; the polled bounds are used only while the window is moving or when it no longer matches the plan (an app moved itself), in which case Phase 3's return-to-tile rule runs and the strip follows the window back

**Appearing and disappearing.**

| Event | Strip |
|---|---|
| Group created, layout restored at launch, group's Space shown, camera reveal (Surface 6) | Fades in over **120 ms** |
| Group dissolved, closed or minimised; selected member enters native fullscreen; group parked or collapsed by the camera; group's Space hidden | Fades out over **120 ms** (Space hidden: ordered out at once, macOS is already animating) |
| Selected member leaves native fullscreen, restored from the Dock | Fades in over 120 ms once its frame is back in the content rect |
| Hover on a tab or button | Fill fades in over **80 ms**, out over **120 ms** (Phase 4 hover-ring timing) |
| Selection changes | The selected fill and title weight swap at once, no animation (the window swap is the feedback) |

Reduce Motion changes nothing here: every strip transition is already an opacity fade (Phase 3 rule: opacity is not motion).

**Interaction.**

| Pointer action | Target | Result |
|---|---|---|
| Click (press and release with < 4pt travel) | Unselected tab | Selects it (Surface 3). Selection happens on **mouse-up**, so a press that turns into a tear-off never switches tabs first |
| Click | Selected tab | Focuses its window (raise + activate its app). No other change |
| Click | Close / Minimize / Float or Dock button | Surface 5. Acts on mouse-up inside the button, standard button tracking (dragging off cancels) |
| Click | Overflow button | Opens the overflow menu below the button |
| Click | Strip background | Focuses the selected tab's window |
| Right-click or ⌃-click | A tab | The tab context menu (Surface 4). The tab gets the pressed fill while the menu is open |
| Right-click or ⌃-click | Buttons or background | Nothing |
| Press on a tab and drag | Pointer stays inside the strip | Nothing (no reordering in Phase 7). Release inside the strip does nothing |
| Press on a tab and drag | Pointer leaves the strip rect | Tear off (Surface 4) |
| Press on the background or a button and drag | anywhere | Nothing. The group moves only by its selected window's own title bar (Surface 5) |
| Double-click | anywhere on the strip | Treated as one click |
| Hover | Tab or button | Hover fill (recipe). Cursor stays the system arrow (tabs and window buttons use the arrow on macOS) |

`InputTap` ignores presses on Transom's own strip panels (matched by window number from the pool), so a press on a tab never starts a Phase 3 window drag or a ⌘⇧ rubber band.

**While paused, or Accessibility not ready.** The strip stays visible and keeps following its window (no AX write is needed for that). Any click on a tab, a group button or a context-menu item does nothing to windows: beep + "Arranging is paused" / "Transom needs Accessibility access" + log line. Hover still shows.

## Surface 3 — Switching and hiding tabs (TABS-02, D-07..D-09)

**Hidden tabs are parked** by the Phase 4 mechanism: moved, at the content rect's size, so only a 1pt × 1pt corner stays on screen at the display's parking corner (Phase 4 Surface 1, "Parking"). Never minimised, never hidden with ⌘H. They keep their size, so selecting one never re-wraps its content.

**Selecting a tab** (click, the overflow menu, Next/Previous Tab, or activation below):
1. The new member is moved into the content rect and raised, and its app is activated (Phase 3 focus path: AXMain + AXRaise, then activate).
2. Once that write has been read back, the previous member is parked.
3. The strip's selection updates as step 1 starts and the strip is ordered front.

This order means the content rect is always covered: the user sees the new window replace the old one with no wallpaper flash. There is no animation (Reduce Motion needs no variant). If step 1's read-back has not matched within **1 s** (the app did not move its window), the previous member is **not** parked, the strip goes back to the previous tab, and Transom beeps, announces "Couldn't show “{App}”" and logs it.

**Activated another way (D-08).** When a hidden member becomes focused by ⌘Tab, a Dock click, a click on a notification, the app activating it, or the Window menu, the group selects that member with the same three steps, so the window the user asked for appears in the group's place. A hidden member that opens a sheet or alert is handled the same way (its app activates it).

**Selection survives.** The selected tab is saved in layout.json with the group (D-13) and comes back on relaunch. Selecting a tab is not an undo step.

**What the user never sees.** Hidden members are excluded from Phase 3 neighbour focus (focus moves land on the selected tab), from Arrange All (they are already placed), from the gap handles, and from every toast count except Restore All Windows'.

## Surface 4 — Leaving a group (TABS-04, TABS-06, D-10..D-12)

### Tearing a tab out (D-10)

**Start.** A press on a tab followed by the pointer leaving the strip rect (any distance outside it) starts a tear-off. Nothing has moved yet: the window stays where it is (selected or parked) until release.

**While tearing.**
- The **tear-off ghost** follows the pointer: a capsule with the tab's icon and title (Body, middle-truncated, max 240pt wide), its top-left 8pt right of and 8pt below the pointer, so it never hides the drop target under the pointer. It lives in its own click-through panel (`ignoresMouseEvents = true`, `.floating`, `[.canJoinAllSpaces, .stationary, .ignoresCycle]`, `sharingType = .none`), ordered above the drop-preview panel. It appears with a 120 ms fade.
- The **drop preview** runs exactly as for a window drag (Phase 3 Surface 2, this spec's Surface 1), with the torn-off window as the dragged window and the pointer as the hit point: edge bands show Dock, ⌘ is ignored (a torn tab has no tile to swap from, so Swap is never offered), centres after the dwell show the Group preview (joining another group or forming a new one), ⇧ bypasses.
- Where no dock or group target applies, the **landing frame** is shown as the Phase 3 **clamp ghost** (`labelColor` 8% fill, 50% dashed 8/4 border): the window at its pre-group size (its saved wanted frame) or else the content rect's size, centred horizontally on the pointer with its top edge 12pt above the pointer (so the title bar is under it), clamped inside the Desktop tile. Because the window is not under the pointer during a tear-off, this ghost always shows.
- The pointer back inside the source strip: no preview, the ghost stays (release there cancels).

**Release.**

| Released over | Result | Announcement |
|---|---|---|
| A Dock preview | The window leaves the group and docks there (one undo step). The group selects a neighbour if it was the selected tab (D-12 rule below) | "Moved out of the tab group" |
| A Group preview on another tile or window | The window leaves this group and joins or forms that one, selected (Surface 1) | "Added as a tab, {n} tabs" / "Grouped as tabs, 2 tabs" |
| Anywhere else outside the source strip | The window floats at the landing frame shown. If the Desktop tile is hidden, it is shown first (Phase 3 D-31) | "Moved out of the tab group" |
| The source strip | Canceled. Nothing changes | none |
| Esc pressed during the tear-off | Canceled. Ghost and preview fade out over 80 ms; the rest of the drag is ignored | "Tab move canceled" |

The ghost fades out over 80 ms on every release. **How Esc is heard**: the Phase 4 rubber-band pattern: temporary Carbon hotkeys for Esc (no modifier, and ⇧, ⌘, ⌘⇧) are registered only for the duration of a tear-off and unregistered at release or cancel; ⌥⌘Esc is never registered. Not rebindable, not in the Shortcuts window.

### The tab context menu (D-11)

An `NSMenu` popped up at the pointer from the strip panel (`popUp(positioning:at:in:)`), system-drawn, two items:

| Item | Result |
|---|---|
| **"Close Tab"** | Closes that member's window with a normal AX close press. A hidden member is selected first (Surface 3), so a save prompt appears in view. If the window is still open 1 s later (a prompt is up), it stays selected and Transom does nothing more |
| **"Move Out of Group"** | The member leaves the group and floats: at its pre-group size (saved wanted frame) or else the content rect's size, placed beside the group (D-11): 8pt (the gap token) to the right of the group frame, top edges aligned; if it doesn't fit there, 8pt to the left; if neither side has room, its top-left 24pt right of and 24pt below the group frame's top-left (cascade). Then clamped inside the Desktop tile (Phase 3 clamp; a hidden Desktop tile is shown first). It is raised and focused. One undo step |

Both items are always enabled (a group always has two or more members). While paused or not ready, choosing either beeps and announces the Surface 2 refusal. The menu takes keyboard navigation from the system (it is a real menu).

### Selecting a neighbour and dissolving (D-12)

- When the **selected** member closes (Close Tab, ⌘W in the app, the app quitting) or leaves (tear-off, Move Out of Group), the group selects the member to its **right** in the strip, else the one to its left, using the Surface 3 steps (no park step: the old one is gone).
- When a hidden member closes or leaves, only the strip changes: its tab is removed and the other tabs re-share the width at once.
- When the group is left with **one** member, it **dissolves**: the strip fades out over 120 ms and the remaining window is resized to the full group frame (the 32pt band returns to it) as a plain docked tile or floating window, under the same NodeID. No notice; announcement "Tab group ended" (in addition to the action's own announcement, joined as "Moved out of the tab group. Tab group ended.").

## Surface 5 — Group-wide actions (TABS-03, D-06)

**The three group buttons.**

| Button | Action | Announcement |
|---|---|---|
| **Close Group** (`xmark`) | Closes every member with a normal AX close press, one at a time, **selected tab first**, then the others in strip order. Before each hidden member is closed it is selected (Surface 3), so any save prompt appears in the group's place. Before it starts, Transom asks (Close Group confirmation, below). If a member is still open **1 s** after its close, Transom checks it for a sheet (the app's save prompt): **while a prompt is up it waits**, with no time limit. Save or Don't Save closes the window, and Close Group goes on to the next member. Cancel leaves the window open: Transom stops there (after one more 1 s for the close to confirm), that member stays selected, the members not yet closed stay in the group, and a second click on Close Group continues from there. A member still open with no prompt (the app refused) stops it the same way. A group that changes while Close Group waits (a member moved out, Float / Dock Group) stops it with nothing announced (2026-11-02) | When all close: none (the windows vanishing is the feedback). When stopped: "“{App}” didn't close" |
| **Close Group confirmation** (2026-11-02) | An `NSAlert` before Close Group starts: message "Close all {n} windows in this tab group?", informative "Apps may ask to save changes before their windows close.", buttons **"Close Group"** (default, Return) and **"Cancel"** (Esc), suppression checkbox **"Do not show this again"**. Checked on a confirmed alert, it is saved in UserDefaults as `tabs.confirmCloseGroup = false` and later Close Group clicks go straight ahead; checked on Cancel, it is not saved. The app frontmost before the alert is activated again after it, so a save prompt shows in front. The strip's × (and its VoiceOver press) is Close Group's only trigger: there is no Close Group hotkey, menu item or URL. Close Tab asks nothing | Cancel: nothing closes, logged "group {node}: close canceled" |
| **Minimize Group** (`minus`) | Minimises the **selected** member through AX (the Dock shows that one window). Hidden members stay parked. The strip fades out. Restoring the window from the Dock brings the group back in its tile or frame with the same selected tab and the strip fades in (Phase 3: a minimised docked window returns to its tile) | none (the Dock animation is the feedback) |
| **Float Group** (`macwindow`, docked group) | The whole group floats at `Planner.floatFrame` (its pre-dock frame, else 90% centred, Phase 3), strip included; its tile closes and neighbours reflow. One undo step | none (the move is the feedback, Phase 3) |
| **Dock Group** (`rectangle.split.2x1`, floating group) | The whole group docks where Dock Window would dock a window at the group's centre (Phase 3 D-12, `Planner.dockTarget`). No room: refused with the Phase 3 600 ms Blocked flash and "Not enough room". One undo step | Phase 3 |

**Phase 3/4 commands acting on a group.** A group is one leaf, so every tree command treats it as one tile. Where a command names "the focused window" and that window is a member:

| Command | Effect on the group |
|---|---|
| Dock Window / Float Window (⌃⌥⌘D / ⌃⌥⌘F), green button on the selected member | The same as Dock Group / Float Group: the whole group moves. (To take one window out, use Move Out of Group) |
| ⌘W / ⌘M inside the app | The app closes or minimises its window; Transom answers as for a member closing (Surface 4) or the group minimising (above) |
| Focus / Move / Swap / Grow / Shrink / Balance / Rotate / Flip / Snap | Act on the group's tile or floating frame; focus lands on the selected tab |
| Arrange All Windows / Float All Windows | A group counts as one window; it docks or floats as a unit |
| Frame Focused Window, double-click on the selected member's title bar, pick-mode click | Frame the group's leaf (Phase 4) |
| Title-bar drag of the selected member | Moves the **whole group**: the strip follows at display rate; drop previews show the group frame (strip included); dock, ⇧ float, ⌘ swap (the target must be a plain panel, Phase 3), miss rules all apply to the group as a unit; hidden members follow at commit (re-parked at the new content size). Centre zones do not group (Surface 1) |

**Safety commands.**

| Event | What the user sees |
|---|---|
| **Quit Transom** | Every member is placed at the group's content rect, the selected one on top; strips disappear. Windows overlap after quit, as with any stacked windows; nothing is left off screen (Phase 3 quit restore, D-07) |
| **Crash, then relaunch** | Phase 3 recovery brings every parked member back on screen with the other stranded windows (N2 counts them). Groups saved in layout.json then re-form (D-13), re-hiding their unselected members |
| **Restore All Windows** (⌃⌥⌘0, menu, `transom://restore`) | Brings every hidden member on screen by **dissolving every group** on the affected desks: the selected member keeps the group's place (tile or float), the others float cascaded 24pt apart from the group's top-left, clamped inside the Desktop tile (a hidden Desktop tile is shown first). One undo step per desk, so Undo Layout Change brings the groups back. Toast N6's count includes these windows |
| **Relaunch with a member missing** (window closed while Transom was off) | A group with two or more members left re-forms without it; one left dissolves into a plain tile; none left behaves like a Phase 3 absent window. Silent; log line |

## Surface 6 — Groups on the zoom stage and in the overview

The real strip panel is a normal-level window and the stage (`.floating`) covers it during a move, so the stage draws each group itself. The strip panel is ordered out when the stage orders in and fades back in at reveal (with the Phase 4 collapsed-block panels, 120 ms).

**Group tile on the stage and in the overview main area.**

| Part | Drawing |
|---|---|
| Content | The **selected** member's tile in the content rect: snapshot, cached snapshot or Phase 4 fallback tile, chosen as for any window. Hidden members are never captured (they are parked) and never drawn |
| Strip layer | At the group frame's top, height 28pt × scale, the strip recipe (`windowBackgroundColor`, `separatorColor` 1pt, radius 8pt × scale, at least 2pt). Inside, one chip per tab in strip order, **icon only** (16pt × scale, hidden below 8pt), chips sharing the width as in Surface 2; the selected chip has the `labelColor` 16% fill. No titles, no buttons, no overflow button on the stage. Below 4pt tall the layer draws only its fill |
| Parked group (outside the view) | Leaves and enters the view like any tile (Phase 4 slide); content and strip move together |
| Collapsed group | One Phase 4 collapsed block showing the selected member's app icon. Its accessibility label is "Tab group, {n} windows, collapsed: “{App}”, {title}" |

**Overview** (Phase 6). Main-area group tiles use the drawing above. Selecting a group tile shows the Phase 6 title capsule with the selected tab's title; picking it focuses the selected tab. Mini tiles on other Spaces show only the selected member, no strip layer. Hidden members are not counted in "Overview, {n} windows". The selection announcement adds the tab position: "“{App}”, {title}, tab 2 of 3".

**Snapshots.** The selected member is captured at the content rect's size (Phase 4 rules). When a tab switch happens with zoom on and Screen Recording granted, the newly selected member is captured once in the background after it is in place, so the next move or overview shows it. Nothing on screen changes.

## Surface 7 — Tabs submenu, hotkeys, URLs, Shortcuts rows, Debug line

**Commands.** Three new commands through the one dispatcher (hotkey, menu, URL make the same call). Each acts on the **focused window's** group.

| Command | Menu title (location) | Default | `Name` | `Command` case | URL |
|---|---|---|---|---|---|
| Select the next tab, wrapping | Arrange ▸ Tabs ▸ Next Tab | **⌃⌥⌘T** | `nextTab` | `.tabs(.next)` | `transom://next-tab` |
| Select the previous tab, wrapping | Arrange ▸ Tabs ▸ Previous Tab | **⇧⌃⌥⌘T** | `previousTab` | `.tabs(.previous)` | `transom://previous-tab` |
| Move the focused tab out of its group | Arrange ▸ Tabs ▸ Move Out of Group | **⌃⌥⌘L** | `moveOutOfGroup` | `.tabs(.moveOut)` | `transom://move-out-of-group` |

- **Why these keys** (Claude's discretion). Free ⌃⌥⌘ letters after Phase 6 are L, Q, T, V, W, Y. T reads as "tab", and its ⇧ variant follows the Phase 3 pattern where ⇧ is the companion action (⇧⌃⌥⌘D / F). L reads as "leave". V and W stay free for Phase 8. Q is avoided because ⌃⌘Q is Lock Screen and a near miss would lock the Mac.
- **System-shortcut check (2026-11-01, macOS 27.2).** `com.apple.symbolichotkeys` on the dev machine has no entry with the ⌃⌥⌘ (1835008) or ⇧⌃⌥⌘ (1966080) modifier masks, so none of the three collides with a macOS default. The launch-time `isTakenBySystem` log (Phase 4) covers user changes.
- `Name` raw values `nextTab`, `previousTab`, `moveOutOfGroup` are a persistent contract (Pitfall 13): never rename them. They are **not** zoom names: they stay enabled with zoom off.
- **URLs** join `TransomURL.commands` under the Phase 3/4 whitelist and the once-per-second rate limit. A URL that can't act does nothing and logs (no beep).
- **VoiceOver fallback** (Phase 3/4): T and L are letter chords, so they are disabled with the other letter chords while that fallback is active.

**Refusals** (beep for hotkeys and menu, nothing for URLs; always a log line and an announcement):

| Refused when | Announcement |
|---|---|
| No focused window, or the focused window is not in a tab group | "The focused window isn't in a tab group" |
| Arranging paused | "Arranging is paused" |
| Accessibility not ready | "Transom needs Accessibility access" |

**Menu.** A new **"Tabs"** submenu in the Arrange section, directly after the Snap Floating Window submenu, following the Focus / Move / Split / Snap submenu pattern. Items use `setShortcut(for:)`.

| # | Item | Shortcut | Enabled |
|---|------|----------|---------|
| T1 | "Next Tab" | ⌃⌥⌘T | Only when the focused window is in a tab group and arranging is not paused or not ready (one `Arranger.availability` rule, Phase 3) |
| T2 | "Previous Tab" | ⇧⌃⌥⌘T | Same |
| T3 | "Move Out of Group" | ⌃⌥⌘L | Same |

The "Tabs" submenu item itself is always enabled (an all-disabled submenu still opens). Disabled items keep their titles (Phase 3 rule).

**Shortcuts window.** A new **"Tabs"** section after "Snap Floating Window" with three rows: `Recorder("Next Tab", name: .nextTab)`, `Recorder("Previous Tab", name: .previousTab)`, `Recorder("Move Out of Group", name: .moveOutOfGroup)`. That makes **48** recorder rows. Restore Defaults also resets the three names. Duplicate checks use the Phase 4 `.shortcutValidation` text.

**Debug submenu.** One new line, directly after "Last overview: …":

| Line | Values |
|---|---|
| Tab groups | "Tab groups: none" · "Tab groups: 1 group, {t} tabs" · "Tab groups: {g} groups, {t} tabs". `{t}` counts every member of every group on every desk (always ≥ 2 when a group exists, so "tabs" needs no singular branch); `{g}` has explicit branches |

**Note for the planner (D-01 wording).** CONTEXT says a release before the dwell is "refused as today (beep, window returns)". Today's drag path (`Arranger.release(now:)` → `.miss`) does not beep: a docked window snaps back and a floating one stays or is clamped; only the keyboard Dock path beeps on a centre target.
