## Phase Goal

**As a** Mac user, **I want to** group windows from any apps into one tabbed tile, **so that** related windows share space without overlapping.

<objective>
TABS-05's floating half: groups made on and living on the Desktop tile. The model gains a sidecar `groups` list on `DesktopLayer` whose members stay ordinary floating windows (RESEARCH Pattern 2, Open Question 1), so the ~80 existing `desktop.*` call sites keep working and older builds degrade to stacked floaters. The engine hit-tests floating centres, drops into them as one undo step, plans and parks members, and feeds floating strips; selection and D-08 reuse 07-02's state machine.

Purpose: D-02 requires groups on floating windows; Core Value requires that adding them cannot break the docked path or existing files.

Output: `FloatingTabGroup` + validation + compat decode, World validation, `GroupTarget.floating`/`.floatingGroup`, `droppingIntoFloating`, Planner floating-group placement, floating strips, hidden-member exclusions.
</objective>

<assumption_delta_decision>
Detector: `assumption-delta scan 7` → detected (pluralization, "another"). Identity question: does one entry per window on the Desktop layer still name the right noun once several windows share one floating frame?
- Primary noun: `FloatingWindow` stays the primary record of a floating window (frame, state, z-order); `FloatingTabGroup` is a grouping over those records.
- Decision: `add-alongside`, deliberately. Rationale: promoting a group record to primary would move members out of `windows` and force an audit of every `desktop.*` caller (Arranger ×56, World ×11, Commands ×7, LayoutRestore, validation), raising regression risk on the Core Value path; keeping members in `windows` also makes an older build read a new file as plain floaters (safe downgrade).
- Accepted debt: member frames are duplicated (each equals the group's content rect). What would force a later promote: per-group state beyond membership/selection/frame (for example group-level z-order or nesting), or a bug where member frames drift from the group.
- Invariant test (accepted, Task 1): after every `DesktopLayer` mutation, each group member's stored frame equals `TabBand.content(of: group.frame)` and every member is in `windows` exactly once.
</assumption_delta_decision>
