## Phase Goal

**As a** Mac user, **I want to** drag windows into nested tiles that reflow as windows open and close, **so that** my windows never overlap.

<objective>
Close UAT gap G-03-5: keyboard and menu commands must act on the app's focused window, so a second window of an app that has a docked window can be docked.

Root cause (binding, from 03-UAT.md and .planning/debug/g-03-5-focused-window-identity.md): AXWindowSystem never records focus moving to a newly created window. AXAppThread's observer gives `windowID` nil for an element it has not cached yet, so `handle(_ hint:)` records nothing. Even a hint with an ID is consumed by `refresh()` while the window is still in WindowTracker's 250 ms settle `pending` set, so no `windowFocused` is emitted. When the window settles, the tracker emits only `windowCreated`. `focusedWindow(of:)` then returns the stale `focusedIdentities[pid]` (docked A), so every hotkey, menu validation and pane:// command acts on A. The `_NS:34` axIdentifier lead is refuted.

The fix keeps an unresolved focus hint until its window is tracked. focusedIdentities' tab-switch and panel behaviour stays unchanged. FakeWindowSystem bypasses AXWindowSystem, so the rule is extracted as a pure PaneEngine value, following the SpaceSwitchMarks precedent (02-17), and unit-tested there.

Output: `PendingFocus.swift` with its tests, AXWindowSystem wired through it, and a VM re-check of UAT tests 6 and 7.
</objective>

  <behavior>
    - A hint naming window 8 while 8 is tracked: resolve returns 8's WindowRef and consumes the hint (a second resolve returns nil)
    - A hint naming window 8 while 8 is not tracked yet (settling): resolve returns nil and keeps the hint; once 8 is in the tracked list, resolve returns it
    - A hint with no window ID: resolve uses the AXMain ID passed in. If the AXMain window is tracked it is returned. If it is untracked, or the AXMain ID is nil, the hint is kept
    - Second window of the same app (the G-03-5 case): A (id 1) was focused earlier; a hint with no ID arrives for new window B (id 2); resolve with tracked [A] and AXMain 2 gives nil and keeps the hint; resolve with tracked [A, B] and AXMain 2 gives B
    - A tab group: a hint naming the group's visible member ID resolves to the group's WindowRef (matching visibleMemberID ?? windowID, as today)
    - Only the same pid's windows match. A newer hint replaces an older one for that pid. Rekey moves a pending window ID from old to new. Forget drops the pid's hint
  </behavior>
  <action>
Per G-03-5 (binding root cause) and TILE-09 (one command dispatcher acting on the focused window). First commit the failing tests (RED), then the implementation (GREEN).

Create `public struct PendingFocus: Equatable, Sendable` in PaneEngine. It imports PaneModel only, never AppKit. It holds at most one pending hint per pid: either a named window ID or "the app's main window" (a hint with no ID). API, using the names the tests use:
- `hint(pid:windowID:)` records or replaces the pid's hint. A nil windowID means "resolve through AXMain".
- `resolve(pid:mainID:windows:) -> WindowRef?` takes the tracked windows (it may filter by pid itself). The target ID is the named ID, or `mainID` for a no-ID hint. It matches a window of that pid whose `visibleMemberID ?? window.windowID` equals the target. On a match it consumes the hint and returns the WindowRef. Otherwise it keeps the hint and returns nil.
- `rekey(pid:from:to:)` and `forget(pid:)`.

There is no expiry: a hint that never resolves (an untracked panel) is harmless and is replaced by the next focus hint.

Wire AXWindowSystem through it. Replace the `[Int32: UInt32]` property with a `PendingFocus` value, still named `pendingFocus`.
- `handle(_ hint:)`: for a focus notification, call `pendingFocus.hint(pid:windowID:)` whether or not the hint has an ID. A nil ID is no longer dropped.
- `refresh(pid:)`: after `ingest`, replace the consuming dictionary removal with `pendingFocus.resolve`. Pass `mainWindowIDs[pid]` only when this observation's `listFailure` is nil, otherwise pass nil, so a failed read never resolves a no-ID hint to a stale main window (T-03-54). Emit `.windowFocused(ref)` on a match. Ingest runs first, so a window that settled in this refresh is emitted as created before it is emitted as focused. The settle follow-up refresh, which ingest already schedules while `tracker.hasPendingWindows`, is what resolves the new window.
- `emit(.windowRekeyed)`: call `pendingFocus.rekey(pid:from:to:)` with the visible ID mapping used today.
- `appStopped`: call `pendingFocus.forget(pid:)`.

Leave `focusedWindow(of:)`, focusedIdentities and the tracker's tab-switch windowFocused unchanged. Leave AXAppThread unchanged: a nil-ID hint is now handled downstream.
  </action>
