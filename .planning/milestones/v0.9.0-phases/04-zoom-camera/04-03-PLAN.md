## Phase Goal

**As a** Mac user, **I want to** zoom out to see every window and zoom back in to any of them, **so that** I can find and focus any window fast.

<objective>
Every camera navigation the engine can answer: zoom out, step in and out, back and forward, move the view, frame the focused window or the Desktop with toggle-back, the rect-zoom target, zoom-to-with-focus for clicks, and the CONTEXT E widening rule. All pure, all headless-tested; the shell wiring is 04-05 and 04-06.

Purpose: one engine path for every trigger (hotkey, menu, URL, pointer), so refusals, history and toggles behave the same everywhere (UI-SPEC Surface 1).

Output: `Navigator.swift`, `Command.camera(CameraCommand)`, `ArrangerInput.camera`, history in `CameraState`, menu titles in `MenuCopy`.

Design:
- One new `Command` case, `.camera(CameraCommand)`, carries all zoom commands, so the menu, hotkey and URL tables stay one-to-one with `Command`. The display under the pointer and the pointer itself are not part of a hotkey's command, so they arrive with a new input `ArrangerInput.camera(CameraCommand, displayUUID: String, focused: WindowRef?, pointer: Point?)`; a bare `.command(.camera(...))` has no display and returns `.fault`.
- `CommandContext` gains `displayUUID: String? = nil` (defaulted, so every caller compiles); camera availability needs it.
- Refusal announcement strings live in the engine (`Navigator.Refusal.announcement`), like `Arranger.noRoom`, because the engine emits them.
</objective>
