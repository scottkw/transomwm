## Phase Goal

**As a** user, **I want to** have docked windows fill the whole screen and floating windows sit on top of them like normal macOS windows, **so that** I never have to learn or manage a "Desktop tile".

<objective>
Close UAT check 7a (8.1.1 D-18), following `.planning/debug/08.1.1-front-floater-group-dwell.md`. `floatingGroupTarget` decides "in front" from `focusOrder`, the shell's focus recency, which is lossy. On the host it ranked the docked window B ahead of the floater T that was in front of it, so B's Top half region showed and nothing grouped. The fix: the shell reads the real front-to-back order once at mouse-down (`CGWindowList.onScreenFrontToBack()`, no AX) and passes it in as an engine input. The engine ranks by it and keeps `focusOrder` only as the headless fallback.

Purpose: "what you see is what you target" for the group dwell (UI-SPEC discretion 3) on real windows.
Output: `PointerEvent.stacking`, ranking by it in `floatingGroupTarget`, the shell read, a red-first engine regression test, and a live test of 7a with three apps in both VMs.
</objective>
