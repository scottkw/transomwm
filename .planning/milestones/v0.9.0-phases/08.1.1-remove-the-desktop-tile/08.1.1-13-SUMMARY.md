# Phase 08.1.1 Plan 13: Engine and shell without a Desktop leaf Summary

**Focus, the zoom hover ring, saved views, placeholders and the parked-floater bring-back now work on docked leaves and floaters only. `leafNode` returns nil for a floater, and no engine or shell file reads `isDesktopHidden`.**

## Performance

- **Duration:** about 25 min
- **Started:** 2026-11-06
- **Completed:** 2026-11-06
- **Tasks:** 2
- **Files modified:** 10

## Accomplishments

- `Navigator.leafNode(of:)` is now `desk.tree.leaf(containing:)`. A floater has no leaf, so the green-button, hover-ring and stage-click paths in `ZoomInput` lose their three `leaf != .desktop` guards.
- `Arranger.focusNeighbour` no longer has a Desktop target or the `floating` candidate list. `recency(on:)` maps docked windows only.
- `Arranger.handle` clears floater home frames on every desk, and `bringBackParked` drops the hidden-Desktop condition (its `shortcut:` comment is gone). The bring-back stays one-shot.
- A node view saves `subtree.windows` only (D-14). `withoutWaiting` drops `sub.nodes[.desktop] == nil`, and `tileName` falls back to "floating".
- New tests:
  - `NavigatorTests.leafNodeIsForDockedWindowsOnly`
  - `ArrangerFocusTests.focusLeftFromAFloaterFocusesTheDockedTileToItsLeft`, plus a Left-beep expectation in `aFloatingWindowUsesItsFrame`
  - `ArrangerViewsTests.savingANodeViewSavesOnlyItsDockedWindows`
  - `ArrangerViewsTests.aViewOfOnlyFloatingWindowsGoesHome`
  - `ArrangerRestoreTests.aFloatersHomeFrameIsClearedOnEveryDesk`
