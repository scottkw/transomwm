# Phase 08.1.1 Plan 08: Drags no longer lean on the Desktop tile Summary

A ⇧ or Hold ⌥ pull-out now floats the window at its release frame, over docked tiles, and is never refused. A floating drop stays where it is released, with no clamp ghost. An empty desk docks a dragged window only from its 24 pt edge band. A floating window's centre in front of a docked tile wins the group dwell.

- **Duration:** about 15 min (16:14 to 16:29 UTC)
- **Completed:** 2026-11-06
- **Tasks:** 2
- **Files modified:** 8

## Accomplishments

- **`hover`:**
  - `floatHover` is a plain ⇧ hover with no plan.
  - The final `Hover` no longer takes `crossesTiles`.
  - An `.emptyLayout` target is kept only within `DropZones.displayEdgeBand` of an edge of the visible frame. Elsewhere the target is nil, so the release is a plain move.
  - `floatingGroupTarget` is asked first for every display target, unless the drag is a whole group. If it finds a floater (other than the torn group), that floater is the group target and the tile's own regions don't apply.
  - `overDesktop` is gone.
- **`decide`:**
  - A floating miss is `Decision(action: .miss, display: own)`.
  - ⇧ gives `.undock` for a docked window and the miss for a floating one.
  - The hidden-Desktop refusal and the `dragPlan(.undock)` room check are gone.
- **`commitUndock`:** a single window keeps its release frame. A whole group floats at `TabBand.frame(ofContent: frame)`. Neither is clamped.
- **`missed`:** the Planner clamp block is gone. It no longer ran anyway, because 08.1.1-06 stopped giving floaters a plan frame.
- **`floatingGroupTarget`:** the `isDesktopHidden` guard is gone. Its docs now say it wins over the docked tile beneath.
- **`Decision.clampInto`:** kept, and now documented as the tear-off landing ghost only. `settleDrag` still reads it.
- **Deleted:**
  - `Hover.crossesTiles`
  - `Arranger.crosses(_:_:except:)`
  - `Arranger.showDesktopToFloat`
  - `DragPlanKey` with its `.undock` case, and `undockPlan()`. `dragPlan` now takes a `DeskKey`.
