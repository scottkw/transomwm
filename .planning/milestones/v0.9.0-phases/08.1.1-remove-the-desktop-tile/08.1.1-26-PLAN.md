## Rules for every task in this plan

- Live checks run only in the Tart VMs: `TRANSOM_VM=pane-test-27` (macOS 27.2) and `TRANSOM_VM=pane-test` (macOS 15.7). Run one VM job at a time through `scripts/vm-session.sh`, wrapped on the host in `caffeinate -i`, with `set -o pipefail`. Remove the log first and check it with grep, so a stale log can't pass. After each run there must be no `tart` process, no `.build/transom-vm.lock`, no host `TransomFixtureApp`, and the VM must be `stopped`. Before booting a VM, compile once with `swift build --build-tests --scratch-path .build/vm`.
- Never on this Mac: live tests, `TRANSOM_LIVE=1`, event taps, key posting, `transom://` or `transom-debug://` opens, the user's real `layout.json` or `com.eightabyte.transom.debug` defaults, or a signal to any Transom process. Never `osascript … System Events` over SSH. Don't delete or rebuild `xcode/.xcode-build/Build/Products/Debug/Transom Debug.app`, and don't call `scripts/vm-cli-check.sh`.
- Fix a VM failure in test code only when the test's own expectation is stale (it still assumes the grow rule). A product failure stops the task, and the SUMMARY names the failing test and its log (RULE 0 for anything unexplained). macOS 15.7 has dropped posted events before: if a failure shows a press that never became a drag, re-run, at most three runs per VM, keeping every log.
- The known macOS 27.2 failures that predate this phase (deferred-items.md: TabGroup close confirmation, OverviewSpaceSwitch ×3, TabStripSpace, Overview's helper) are not in these suites. Never gate on them.
- Cite decisions as "8.1.1 D-16" / "D-17" and the rules as E1-E7.
- Never stage `.planning/config.json`, `.planning/state.json` or `.planning/milestone.lock`. Every commit message ends with these two lines:
