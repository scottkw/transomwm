## What the migration test checks

The test opens two fixture windows. The fixture moves W1 to `parkedFrame`, and the window system has to see it stranded before the test goes on. The test then writes a schema-3 file by hand in LayoutFileV3Fixture's shape. The desk is H[W0 0.5, `{"desktop":{"hidden":true}}` 0.5], W1 floats at the park rect, and W1 has an on-screen home frame. The file carries the live identities, desk key, arrangement and boot session. `ArrangeController` then starts on that directory. The test expects all of these:

- No load error.
- The tree holds W0 alone, and W1 still floats.
- Within 5 s, W0 sits at its planned tile, which is wider and taller than 90% of the visible frame, and W1 sits at `Planner.clamp(home, into: visible)`.
- `history.depth(for:)` is 0.
- layout.json on disk says schema 4 and has no `"hidden"`.

## Deviations from Plan

### Auto-fixed Issues (test code only, each a Desktop-era expectation)

**1. [Rule 1 - Bug] HoldOption tests assumed the Desktop tile**
- **Found during:** Task 2, first 27.2 batch (3 failures).
- **Issue:** `aPlainDragFloats…` dragged window 1 one tile right "where the Desktop tile is", so the release frame left the screen and was clamped (984 vs 1032). `leftBand` aimed at "the Desktop tile's left band". On the empty desk that is a plain move, so there was no dock preview and no dock.
- **Fix:** The plain drag goes half a tile left. A first fix aimed at the empty desk's edge band, 12 pt in. On 27.2 that drew macOS's own edge-tiling guide (RESEARCH E1). The final fix makes `floatingWindow()` dock window 1 first and order it back, as Fourths' `centredWindow` does, so `leftBand` (1/8 of the width) is window 1's tile's left region.
- **Commit:** 2652339

**2. [Rule 1 - Bug] QuitRestore read the docked frame mid-dock**
- **Found during:** Task 2. It failed on both OSes ("the docked window moved").
- **Evidence:** A probe run (`.build/0811-18-probe-quit-vm15.log`) showed `dockedFrame` read as (40, 80, 984, 633), partway through the dock. Window 0 sat at its tile (8, 33, 1008, 673) before and after the restore, and the restore plan held window 1 only. The product was right. In 08.1.1-02's rewrite, the hide-and-park wait no longer gave the dock time to land.
- **Fix:** Wait until window 0 is at its planned tile, then read it.
- **Commit:** 2652339

**3. [Rule 1 - Bug] Views `aViewOnAnotherSpaceSwitchesFirst` docked a lone window**
- **Found during:** Task 2. It failed on 15.7, where it had passed in 08.1.
- **Issue:** Alone, the window's leaf is the whole desk, so the saved view is the home view. A second window of the same fixture then took focus at the Space switch, and `widen(toShow:)` took the camera home ("Showing all windows").
- **Fix:** Another fixture app, launched first, docks a window beside it. The test's window then stays focused.
- **Commit:** 2652339

**4. [Rule 2] HoldOption's "press was never a move" message now names the strip, the drag and the session's modifier flags.** This is for the intermittent 15.7 failure below.
