## Kept subjects, hide step removed

- **ArrangerDesktopTests** `anExcludedFloatingWindowIsNeverParked`: no hide. It settles and expects nothing parked, nothing dropped, x unmoved and no home frame. `aFloaterTooBigForTheRoomLeavesTheDockedWindowDocked` had no hide step and is unchanged. 08.1.1-06 ports both.
- **ArrangerExclusionTests** `anExcludedFloatingWindowIsNeverClampedOrParkedAndStaysFloatingWhenIncludedAgain`: only the hide/show pair and its park assertion were removed.
- **ArrangerRestoreTests** `aCrashLoopLaunchStartsPausedButStillRescuesStrandedWindows`: it had no hide step. The plan's note was wrong, see the deviation below. It is unchanged and passes.
- **AppDelegateTests** `aRefusedURLCommandDoesNotBeep` dispatches `.floatAll`, which a controller that was never started refuses: 0 beeps from the URL, 1 from the hotkey. In `aValidURLDispatchesOnceAndAnythingElseNothing`, the wrong-scheme URL is now `transom://float-all`.
- **QuitRestoreIntegrationTests** is now `theQuitRestoreBringsAParkedFloaterBackOnScreen`. It docks window 0, pauses, moves window 1 to `display.parkedFrame` with the fixture's `move`, and waits for the arranger to see it stranded. The quit restore must then move exactly 1 window, put window 1 back on screen and leave window 0 alone. Before writing it, a throwaway FakeWindowSystem probe (deleted, never committed) confirmed the engine half: a paused arranger records the stranded frame, and `restorePlan()` sends only that window, centred on screen.

## Deviations from Plan

**1. [Rule 3 - Blocking] ArrangerRestoreTests' second hide site was the `parkedC` helper, not the crash-loop test**
- **Found during:** Task 1
- **Issue:** The plan named `aCrashLoopLaunchStartsPausedButStillRescuesStrandedWindows` as the incidental hide site. The real second `toggleDesktop` was in `parkedC()`, which three Restore All tests used.
- **Fix:** Deleted `parkedC` and its three tests, whose subject was the hidden Desktop's home frames (table above). The crash-loop test is unchanged.
- **Commit:** 7c30314

**2. [Rule 1 - Accuracy] The quit-restore oracle changed from "at its home frame" to "back on screen"**
- **Found during:** Task 2
- **Issue:** Without hiding, Transom records no home frame, so `Recovery.terminationPlan` uses its stranded rule (centre of the display). It also had to pause first, or the plan could clamp the floater back on screen before the quit.
- **Fix:** The test is renamed `theQuitRestoreBringsAParkedFloaterBackOnScreen` and the suite doc says "back on screen".
- **Commit:** baa88be
