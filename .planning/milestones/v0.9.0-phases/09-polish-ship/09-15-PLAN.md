## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner ↔ signing secrets | The release job holds the Developer ID key and the App Store Connect API key |
| tag push → release | Whoever can push a v tag can start a signed build |
| tap token → scottkw/homebrew-transom | A write token for the tap repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-30 | Elevation of privilege | Signing secrets in CI | high | mitigate | Secrets only in the `release` environment (required reviewer, refs main and v*), only in the release job; gate job has no environment; keychain deleted before tests compile; .p12 and .p8 removed right after import; `persist-credentials: false`; only GitHub's own actions, pinned by SHA |
| T-09-31 | Tampering | Script injection through tag names | medium | mitigate | `github.ref_name` and inputs reach the shell only through `env:` (acceptance grep: no `${{` in run lines) |
| T-09-32 | Tampering | Cask hash | high | mitigate | tap.yml hashes the published asset and requires it to match the `.sha256` asset (and the API digest) before writing the cask |
| T-09-33 | Elevation of privilege | Tap token scope | medium | mitigate | Fine-grained PAT, contents: write on scottkw/homebrew-transom only (docs/releasing.md); used only in tap.yml |
| T-09-34 | Spoofing | Designated requirement change slipping through a PR | medium | mitigate | PR CI fails unless project.yml keeps the bundle ID, team and Developer ID identity (Pitfall 13); release.sh compares the DR exactly (09-14) |
| T-09-SC | Tampering | npm/pip/cargo installs | low | accept | No package is added to Transom; the runner installs XcodeGen from Homebrew with its version asserted |
</threat_model>
