## Phase Goal

**As a** new user, **I want to** install Transom with Homebrew and be guided through setup, **so that** it starts at login and keeps itself updated.

<objective>
Close the macOS 27 gap D-23 names before v0.9.0 ships (09-26 to 09-28 run after this plan). On macOS 27.2 a window an app closes but keeps alive (`isReleasedWhenClosed = false`, a window controller) leaves AX and the screen but stays in the full CG window list, layer 0, on its Space (09-25 deferred-items: 8.5 s and more). `CloseRule` needs the CG list to agree, so it rechecks forever: the tile stays and Close Group stops at its 1 s confirmation. On macOS 15.7 the same close confirms in 0.109 s because the entry leaves the CG list.

The change (Claude's discretion within D-23): CG's second-source evidence may now also be "present but ordered out on a Space a display shows" instead of only "absent". New fact `cgOrderedOut`. The row applies only when AX also says the element is gone (-25202), so the two-source rule (D-09, WIN-09) holds. It comes after the tab-member check and is guarded three ways:
- AX-valid windows are never touched. Minimised, app-hidden, hidden-tab and other-Space windows all answer AX valid.
- On-screen entries are kept, since the element may be rebuilding or WindowServer may lag.
- Entries on a Space no display shows are kept (other Spaces).

With the Spaces lookup off, the fact is false, as `cgSpacesKnownEmpty` already is, so `withTheLookupOffAGhostKeepsRechecking` stays as it is.

There is no macOS version check. The row only adds evidence: on 14 and 15 a closed window leaves the CG list first, so the row never decides anything there. The 15.7 runs prove that.

Purpose: Core Value. Windows must stay correctly arranged as they close. On macOS 27 a closed window must not keep its tile.
Output: the CloseRule row and its computation, engine tests written to fail first, a logged diagnostic line in the TabGroup live test, live proof in both VMs, and a deferred-items record.
</objective>
