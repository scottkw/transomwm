## Phase Goal

**As a** new user, **I want to** install Transom with Homebrew and be guided through setup, **so that** it starts at login and keeps itself updated.

<objective>
Before asking for any permission, a Transom opened from a disk image, the Downloads folder or a translocated path offers to move itself to Applications (D-08, ROADMAP scope note "App Translocation check", UI-SPEC Surface 2 step 0, RESEARCH Pattern 6).

macOS ties permissions to where the app lives, so granting Accessibility to a translocated copy wastes the user's effort. There is no supported API for the original path of a translocated app (Apple DTS), so Transom copies itself from `Bundle.main.bundleURL`.
Output: `InstallLocation.classify`, `AppMover`, the Move step, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Transom → /Applications | Writes a copy and may trash the user's existing app |
| Transom → /bin/sh | Starts a helper process with a path argument |
| Gatekeeper quarantine | The copy's quarantine flag is removed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-47 | Tampering | Relaunch command injection | medium | mitigate | Fixed script string; pid and path passed as `$1` / `$2` argv, never interpolated (`theRelaunchPassesPidAndPathAsArguments` uses a path with spaces and quotes) |
| T-09-48 | Elevation of privilege | Stripping quarantine | medium | mitigate | Only on Transom's own fresh copy, from the bundle that already passed Gatekeeper to be running; never on other files |
| T-09-49 | Denial of service | Losing the user's existing app | low | mitigate | Replace only after the destructive alert, and the old copy goes to the Trash (`anExistingCopyGoesToTheTrashNotAway`) |
| T-09-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed or added; no SPI |
