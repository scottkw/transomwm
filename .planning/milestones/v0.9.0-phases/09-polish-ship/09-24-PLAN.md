## Rules for every task in this plan

- Live checks run only in the Tart VMs: `TRANSOM_VM=pane-test-27` (macOS 27.2) and `TRANSOM_VM=pane-test` (macOS 15.7). One VM job at a time through `scripts/vm-session.sh`, wrapped on the host in `caffeinate -i`, with `set -o pipefail`; one live suite per session (combined filters run suites in parallel and their posted events collide). Remove the log first and check it with grep. After each run: no `tart` process, no `.build/transom-vm.lock`, no host `TransomFixtureApp`, and the VM `stopped`. Before booting a VM, compile once with `swift build --build-tests --scratch-path .build/vm`.
- Never on this Mac: live tests, `TRANSOM_LIVE=1`, event taps, key posting, `transom://` or `transom-debug://` opens, the user's real `layout.json` or `com.eightabyte.transom.debug` defaults, or a signal to any Transom process. Never `osascript … System Events` over SSH. Don't delete or rebuild `xcode/.xcode-build/Build/Products/Debug/Transom Debug.app`, and don't call `scripts/vm-cli-check.sh`.
- Only test setup may change in a live suite (timing, waits, preconditions, fixture placement). A failure caused by product code stops the task: write the failing test, its log and the evidence to `deferred-items.md` and report it as a deviation for the user (RULE 0 for anything unexplained). Never skip, disable or delete a test to make a run green. At most three runs per VM per suite; keep every log.
- Swift 6.3 (the CI runner): explicit closure and tuple types; no local named like a method in scope.
- Plans in this phase run one at a time (each `depends_on` the previous plan): executors share one working tree, one `.build` and the VM lock.
