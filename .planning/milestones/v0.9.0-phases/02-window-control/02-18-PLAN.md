## Phase Goal

**As a** Mac user, **I want to** grant Transom access and have it track and move every window, **so that** no slow app or lock screen can freeze or lose them.

<objective>
Close UAT gap G-02-1 (WIN-01, D-02). With no Accessibility grant, Transom opens its Set Up Transom window at 1x28 pt: a title bar with no content. `SetupWindowController.makeWindow()` sets `hosting.sizingOptions` to the intrinsic-content-size option (line 44). That option only updates the hosting view's intrinsicContentSize, and NSWindow never sizes itself from that. The window therefore keeps the empty frame it got from `NSWindow(contentViewController:)` and is centred at that size. The diagnosis is in `.planning/debug/g-02-1-setup-window-1x28.md`. It was reproduced line for line in the macOS 15.7.7 VM, where `[.preferredContentSize]` sized the window to 480x353 by the time `layoutIfNeeded()` returned.

Planner measurement on this host (macOS 27, 2026-10-27, scratch copy of makeWindow in a plain process and in a `swift test` runner, window never shown): with `[.preferredContentSize]` alone, the window is still 1x32 when `layoutIfNeeded()` returns. It reaches its real size only after a run-loop turn, and it then grows downward from its top edge. The centring code reads `window.frame` before that turn, so the window would open with its top-left corner at the screen centre: readable, but not centred. Adding `window.setContentSize(hosting.view.fittingSize)` after `layoutIfNeeded()` sized it at once on macOS 27 (480x269 for the lookalike view). A later content change still resized it (269 to 157, top edge fixed), because `[.preferredContentSize]` keeps publishing. The debug file's warning against a one-off setContentSize applies only when it *replaces* the sizing option. Here it is added before centring, and the sizing option still handles every later state. The brief called this a one-line fix; this plan changes two lines. Record that as a deviation in the SUMMARY, with these measurements.

Purpose: the onboarding window is the only route to a grant, and the phase goal starts with "grant Transom access".
Output: the fix in makeWindow(), an internal test seam on PermissionController, and `Tests/TransomMacTests/SetupWindowTests.swift`.
</objective>
