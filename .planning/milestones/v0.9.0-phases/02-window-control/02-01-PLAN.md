## Phase Goal

**As a** Mac user, **I want to** grant Pane access and have it track and move every window, **so that** no slow app or lock screen can freeze or lose them.

<objective>
Tracer for Phase 2: prove the whole window-control architecture end to end on one real window before anything else is built. A fixture app opens a window; Pane's per-app AX thread reads it (window ID through the PanePrivate dlsym shim), the pure PaneEngine tracker turns the observation into a WindowInfo, and AXWindowSystem serves it from its cache. The same path runs from the PaneApp executable against every running app. Then add the FakeWindowSystem (same tracker, simulated OS) with the engine and Mac unit-test targets, and finish the fixture app with every window kind later plans need.

Purpose: WIN-02 (track windows) and SAFE-05 (private API isolation with a capability registry) start here. Every later plan in this phase plugs into the contract, tracker, threads and fixture created here, so this plan fixes them interface-first.
Output: new targets PanePrivate, PaneMac, PaneApp, PaneFixtureApp, PaneTestSupport and three test targets; the revised WindowSystem contract; WindowTracker; AXAppThread/AXSnapshotReader/AXWindowSystem; FakeWindowSystem; the fixture app.
</objective>

<assumption_delta_decision>
Noun now primary: `WindowIdentity.windowID` (PaneModel, unchanged) stays the identity noun. With `_AXUIElementGetWindow` it is the CGWindowID; in fallback mode (SAFE-05) it is the CGWindowID of the CG entry matched by pid + frame (+ title), and only when that match is ambiguous a synthetic session ID from the reserved range `0xF000_0000 | counter`. For a native tab group it is the first-seen member's CGWindowID (the leader), while `WindowInfo.visibleMemberID` carries the CGWindowID to address right now.
Decision: add-alongside. `WindowInfo.idSource: WindowIDSource` (`axPrivate`, `cgFrameMatch`, `synthetic`) and `WindowInfo.visibleMemberID` are added next to the identity; PaneModel's `WindowIdentity` is not changed, so Phase 1's persisted JSON shape and tests are untouched.
Rationale: in all but the ambiguous fallback case the identity really is a CGWindowID, and Phase 2 persists no layouts, so promoting to a Pane-owned ID now would change PaneModel for no consumer.
What would force a later promote: Phase 3 (SAFE-06) or Phase 8 (VIEW-04) persisting refs whose CGWindowID can die while the window lives on (tab leader closed while the group survives), or WindowServer reusing a CGWindowID within one session for a different window; either means identity must become a Pane-owned stable ID with the CGWindowID demoted to an attribute.
Suggested invariant (implemented in WindowTrackerTests): the tracker never holds two live WindowInfos with the same identity, an identity never changes across a tab switch (Plan 10), and a synthetic ID never equals any CGWindowID present in the same refresh (Plan 11).
</assumption_delta_decision>
