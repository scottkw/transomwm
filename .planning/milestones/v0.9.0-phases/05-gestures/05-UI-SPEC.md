# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Phase 5 lets trackpad gestures drive the Phase 4 camera. It **extends** `04-UI-SPEC.md` (approved 2026-10-27) and keeps every token, timing, stage property, colour, copy rule, Debug-line style and announcement from it. It also keeps the Phase 3 rules that 04-UI-SPEC kept. Nothing here redefines a Phase 4 value. Where this spec says "Phase 4 Surface N", that surface applies unchanged.

Phase 5 adds **no new window, panel, menu item, setting, colour, font size or spacing value**. It adds eight things:

1. **Follow mode** on the existing camera stage: the stage tracks a pinch or a pan live (GEST-01, GEST-02)
2. **Overscroll**: the elastic resistance past one level, or where there is no target (D-03, E-02)
3. **Release**: snap to a level, or spring back (D-01, D-03)
4. **Reduce Motion** rules for 1–3
5. **Refused gestures**: what the user sees, hears and reads when there's nowhere to go
6. **Debug-menu lines** for the gesture path (and multitouch, only if the spike gate ships it)
7. **Log lines** for consume and pass-through decisions (VNC can't show toasts or beeps)
8. The **spike CLI's printed output** and the **user checklists** for the spike gate and the phase UAT

Not in this phase: free-scale resting zoom and the all-displays overview (Phase 6); gesture settings for sensitivity, on/off and the no-⌥ wallpaper toggle (Phase 9, deferred in CONTEXT); onboarding copy about ⌥-scroll in apps (Phase 9).

**Platform rule (unchanged).** Native macOS. The stage is the Phase 4 `StagePanel` (`NSPanel` + Core Animation). The spike is a command-line tool with no windows.

**Clean-room rule (unchanged).** Every string, threshold and visual below was written for Transom. None of TrellisWM's gestures, copy or feel parameters is used.

**Spelling.** UI strings use US English. Planning prose may stay British.

**Vocabulary added by this spec.**
- **Gesture**: one trackpad sequence, pinch or two-finger pan, from its first event through the end of its momentum. Transom decides once, at the first event, whether the gesture is **taken** (consumed: no event reaches any app) or **passed** (every event reaches the app untouched). The decision is never changed during the sequence (RESEARCH Pattern 2).
- **Follow**: the stage tracking the fingers before release.
- **Progress `p`**: how far the gesture has gone toward its target level, where `p = 1` means the stage shows the target exactly.
- **Overscroll**: elastic resistance when there is no target, or past `p = 1`. CONTEXT D-03 and E-02 call this "rubber band". This spec uses **overscroll** so it can't be confused with Phase 4 Surface 4's ⌘⇧-drag **rubber band** (the marquee). Code names follow this spec: `overscroll`, never `rubberBand`, in gesture code.
- **Snap**: the animated finish to the target level after release. **Spring back**: the animated return to the start view after release.

## Surface 1 — Follow mode on the camera stage (GEST-01, GEST-02)

**What it is.** The Phase 4 stage (Surface 1 panel, layer tree and tile contents, all unchanged) gains a **follow** phase before its move animation. While a taken gesture is under way, the stage is up and its tiles track the fingers. Real windows never move during follow. They move once, at settle, after a snap (Phase 4 steps 6–7), or not at all after a spring back.

**When the stage appears.**

| Moment | Visible result |
|---|---|
| First event of a taken gesture (the latch) | Nothing visible. The gesture is already consumed. Snapshot captures start for visible windows with no cached snapshot (Phase 4 capture rules, concurrency 4) |
| Pinch inside the dead zone (`|ln s| < 0.03`) or pan before axis lock (`|Σ| < 12pt`) | Nothing visible. A gesture that never leaves this zone ends with no stage at all |
| First sample past the dead zone (pinch) or after axis lock (pan) | The stage orders in **instantly** (no fade) within one display refresh, every tile exactly over its real window (Phase 4 step 4). It **never waits** for the 120 ms capture budget |
| A capture that returns while the stage is up | That tile's fallback contents are replaced by the snapshot with a **120 ms** opacity crossfade of the layer contents (opacity is not motion, so this also applies under Reduce Motion). The tile's frame is unaffected |

**Display.** The gesture acts on the display under the pointer at the latch. Only that display's stage appears. Other displays never change.

**Target, chosen when the stage appears** (non-mutating preview, RESEARCH Pattern 4: no pending move, no history):

| Gesture | Direction | Target (Phase 4 rules, unchanged) |
|---|---|---|
| Pinch, fingers apart (`p > 0`) | in | One level in, toward the child under the **pinch point** (the pointer location at the latch). Called with no focused leaf, so the pinch point always decides. If the point is over a gap, it falls back to Phase 4's largest-child rule. This differs from the hotkey on purpose: a pinch is spatial |
| Pinch, fingers together (`p < 0`) | out | The parent of the view's node, or home |
| Pan, fingers moving left | shows the area to the **right** | `Navigator.pan(edge: .right)`: same depth, longest shared edge, most recently viewed |
| Pan, fingers moving right / up / down | left / below / above | `.left` / `.bottom` / `.top`. Deltas are used as macOS delivers them, so the stage moves like scrolled content in every app. With natural scrolling off, pans reverse too, matching other apps (IN-07, user decision 2026-10-30) |

If a pinch crosses `p = 0` (fingers apart, then together) or a pan reverses past its start, the target is recomputed for the new direction and the tile set is rebuilt from the tiles' **current** frames. At `p ≈ 0` the tiles are at their start rects, so nothing jumps. The pan axis stays locked for the whole gesture; motion on the other axis is ignored.

**Mapping fingers to tiles.** One mechanism for both gestures: every tile's frame is `lerp(start, end, t)`, where `start` is its rect in the current view and `end` its rect in the previewed target (Phase 4 step 5 semantics: tiles leaving the view follow the camera transform off the display, tiles entering slide in from it). Frames are set inside a `CATransaction` with actions disabled, once per sample, so the stage moves at the rate events arrive and never animates between samples.

| Quantity | Value (constants in `GestureTuning`) |
|---|---|
| Pinch scale | `s = 1 + Σ magnification` (additive, as NSEvent documents) |
| Pinch progress | `p = ln(s) / ln(2)`: one full level per doubling or halving of finger spread, whatever the tree's size ratio |
| Pan progress | `p = |d| / W`, where `d` is the summed point delta on the locked axis and `W` is the display's `visibleFrame` width (horizontal) or height (vertical) |
| Displayed `t` with a target, `0 ≤ |p| ≤ 1` | `t = |p|` |
| Displayed `t` with a target, `|p| > 1` | `t = 1`, plus overscroll (below) |
| No target | `t = 0`, plus overscroll from `p = 0` |

**Overscroll** (E-02 one level per gesture; D-03 at home). The same resistance curve as iOS scroll views:
`R(x, L) = L · (1 − 1 / (x · 0.55 / L + 1))`. It approaches `L` but never reaches it.

| Case | `x` | `L` | What the user sees |
|---|---|---|---|
| Pinch past one level (`|p| > 1`) | `|p| − 1` | 0.25 level | Tiles sit at their end rects, and the whole tile set scales uniformly about the pinch point by `2^(±R)`, so at most ×1.19 (in) or ×0.84 (out) |
| Pinch with no target: out at home, in on a leaf | `|p|` | 0.25 level | The start tile set scales about the pinch point by `2^(±R)`, at most ×1.19 / ×0.84 |
| Pan with no neighbour (always at home) | `|d|` in pt | `W` | The start tile set translates along the locked axis by `R · sign(d)`. A drag of a third of the display shows ≈ 0.16 W of movement |
| Pan past `p = 1` | `|d| − W` | `W` | Tiles at end rects, translated by `R · sign(d)` |

The backdrop (wallpaper) never moves or scales, as in Phase 4. No tile is clipped to anything but the display.

**What the stage does not do during follow.** No beep, no announcement, no Debug or log write per sample, no AX write, no history entry, no pending move. The stage still swallows clicks while it is up (Phase 4 `ignoresMouseEvents = false`); since the gesture itself is consumed at the tap, it never reaches the stage.

## Surface 2 — Release: snap or spring back (D-01, D-03)

**Decision on release** (fingers up: pinch phase ended, or scroll phase ended; momentum is only a velocity estimate and is swallowed through its end):

| Gesture | Commits (snap) when | Else |
|---|---|---|
| Pinch | `|p| ≥ 0.5`, or a flick: `|dp/dt| ≥ 2.0 /s` over the last 80 ms with `|p| ≥ 0.15`, in the direction of the target | Spring back |
| Pan | `p ≥ 1/3`, or a flick: `v ≥ 800 pt/s` toward the drag (last 80 ms of samples, or the first momentum sample) with `|d| ≥ 24pt` | Spring back |
| Either, with no target | never | Spring back (a refused gesture, Surface 3) |
| Either, never left the dead zone / axis lock | never | Nothing to do: no stage was shown |

All thresholds are tuned at UAT, live only in `GestureTuning`, and are covered by trace tests (D-08).

**Timing.** Every value is Phase 4's constant, never a new one.

| Outcome | Animation | Then |
|---|---|---|
| **Snap** | The committed move is the previewed one, through the normal `zoomTo` → `.cameraMove` path. `StagePanel.retarget` runs every tile from its **presentation rect** (including any overscroll scale or offset, which resolves to 1 / 0) to its end rect over **250 ms** (`StagePanel.moveDuration`), `CAMediaTimingFunction(name: .easeOut)`. Fixed duration, whatever distance is left | Phase 4 steps 6–8 unchanged: settle (one AX write per changed visible window, plus parks), reveal fade **120 ms** (`StagePanel.revealFade`), background refresh. History is pushed at settle, exactly like a hotkey move (D-02) |
| **Spring back** | Every tile returns from its presentation rect (and any overscroll) to its start rect over **250 ms**, `.easeOut` | The stage fades out over **120 ms**. No settle is needed: the real windows never moved. No engine call, no AX write, no history, no Debug "Last settle" update |

**A gesture during a move or settle (E-03).** If a gesture is taken while a Phase 4 move or settle is in progress (from a hotkey, URL, click or an earlier gesture), the running animation stops at its presentation frame and follow takes over from there. The base view is the pending target. Writes not yet sent for the old target are dropped, as in Phase 4 Retargeting. Nothing jumps. A second pinch right after a snap therefore continues smoothly one more level.

**Interactions with other Phase 4 modes.**
- **Pick mode** ends when a gesture is taken (any Transom command ends it, Phase 4 Surface 5).
- While a **⌘⇧ rect zoom** or a **window drag** is in progress, gestures are not armed and pass through.
- **Collapsed-block panels** order out when follow begins (the stage draws collapsed blocks itself) and fade back in at reveal or after the spring back's fade, over the Phase 4 120 ms.
- The **status button** description changes only after a settle ("Transom: zoomed in", Phase 4); follow and spring back never change it.

## Surface 3 — Refused gestures and "no neighbour"

A gesture is **refused** when its target doesn't exist: pinch out at home, pinch in on a leaf (a tab group is a leaf), or a pan with no area across that edge (always true at home).

| Channel | Behaviour |
|---|---|
| Visual | Overscroll while the fingers move (Surface 1), spring back on release (Surface 2). No colour, no shake, no icon, no toast |
| Sound | **Never a beep.** The gesture path does not call `dispatchCamera`. A beep under the fingers would fire on every curious pinch |
| VoiceOver | Silent while the fingers move. On release, the Phase 4 refusal announcement is posted **only if the gesture would have committed** had a target existed (the same threshold or flick rule as Surface 2). A short, sub-threshold overscroll is a "never mind" and stays silent |
| Log | Always: one `gesture` line at release (Logging) |
| Debug | "Last gesture: …" shows the refusal (Surface 5) |

| Refused gesture | Announcement (reused from Phase 4 Surface 1 Refusals, `Navigator` reasons) |
|---|---|
| Pinch out at home | "Already showing all windows" |
| Pinch in on a leaf | "Nothing to zoom in to" |
| Pan with no area to that side | "No area to the left" / "No area to the right" / "No area above" / "No area below" |

**Gestures that are never taken.** These never show a stage, never announce and never beep. Their events reach the app unchanged, and they are logged only as the Logging table says:

| Situation | Why it passes |
|---|---|
| Zoom is off | D-07: no gesture tap exists and no multitouch device is opened. Behaviour is exactly Phase 3 |
| Arranging paused, Accessibility not ready, pointer in a fullscreen Space, pointer not on a desk display | Not armed (the same conditions that refuse Phase 4 zoom commands) |
| No ⌥, pointer over any window, menu or popover | D-05 |
| ⌥ with ⌃ or ⌘ also held | E-05: keeps ⌃-scroll Accessibility zoom and app chords |
| A mouse wheel, Magic Mouse scroll, or any non-trackpad sender | E-04 |
| ⌥ pressed after the gesture began | The app already saw its start; Transom never takes a gesture mid-sequence |
| Rotate-only, smart zoom (two-finger double-tap) and other gesture types | Not Transom's |

## Surface 4 — Reduce Motion

`accessibilityDisplayShouldReduceMotion`, read when the stage appears (it is observed live, as in Phase 4, for later gestures).

| Phase | Reduce Motion off | Reduce Motion on |
|---|---|---|
| Follow | Tiles lerp with the fingers | **Unchanged: tiles still lerp with the fingers** (D-01, locked). Motion driven directly and continuously by the user's fingers is direct manipulation, not an animation. This is the one intended exception to Phase 4's "nothing slides or scales" rule |
| Overscroll | Elastic scale or offset | Unchanged (part of follow) |
| Snap | 250 ms ease-out from presentation rects | **250 ms crossfade** (`.easeInEaseOut`): the tile set at its current follow frame fades 1→0 while the end tile set fades 0→1, with no tile moving or scaling (Phase 4's crossfade, carried by `StagePanel.retarget`'s crossfade flag, which follow sets at stage-in) |
| Spring back | 250 ms ease-out to start rects, then 120 ms fade | **The stage fades out over 250 ms** (window alpha). The real windows are already at their start frames under the opaque stage, so this crossfades the displaced tiles into the real windows with nothing moving |
| Capture swap during follow | 120 ms contents crossfade | Unchanged (opacity) |
| Settle and reveal | Phase 4 | Phase 4 |

## Surface 5 — Status menu: Debug lines

No new menu items. The Phase 4 menu, Zoom section and toggles are unchanged. Turning zoom off also turns gestures off (D-07); there is no separate gesture toggle in this phase.

New Debug submenu lines go **directly after Phase 4's "Snapshot cache: …" line**, in this order. They are plain disabled informational items, like the Phase 3/4 Debug lines, rebuilt when the menu opens (no per-row AppKit lookups during rebuild; values come from counters the gesture controller already holds).

| # | Line | Values |
|---|---|---|
| G1 | Gestures | "Gestures: on, trackpad events" · "Gestures: on, trackpad events and multitouch" (only if multitouch ships) · "Gestures: on, pan only (pinch is off in Trackpad settings)" (see note) · "Gestures: off (zoom off)" · "Gestures: off (gesture tap not running)" · "Gestures: unavailable (no gesture source)" |
| G2 | Gestures taken | "Gestures taken: none yet" · "Gestures taken: {n}" · "Gestures taken: {n}, {t} ended by timeout" (when `t > 0`). Counts since launch. The number follows a colon, so no plural branch is needed |
| G3 | Last gesture | "Last gesture: none yet" · "Last gesture: {kind}, moved" · "Last gesture: {kind}, sprang back" · "Last gesture: {kind}, {refusal}" · "Last gesture: {kind}, too small". `{kind}` ∈ "pinch in", "pinch out", "pan left", "pan right", "pan up", "pan down" (the direction the **view** moved, matching Move View ▸ Left/Right/Up/Down). `{refusal}` is the Phase 4 refusal text in lower-case-first form: "already showing all windows", "nothing to zoom in to", "no area to the left" / "to the right" / "above" / "below" |
| G4 | Multitouch (**only if the spike gate ships multitouch**; otherwise this line does not exist) | "Multitouch: available, 1 trackpad" · "Multitouch: available, {n} trackpads" · "Multitouch: available, no trackpad found" · "Multitouch: off, trackpad events only" (`--disable-private=Multitouch` or symbols missing) · "Multitouch: off after a crash last launch, trackpad events only" (crash canary) |

**Note on "pan only".** Shown only if the spike (checklist item 3) confirms that turning off System Settings ▸ Trackpad ▸ Scroll & Zoom ▸ "Zoom in or out" stops pinch events, **and** multitouch does not ship. Transom then reads that Trackpad preference when the menu opens. If the spike shows pinch events still arrive, or multitouch ships, this value is dropped and G1 never shows it.

"Gestures: off (gesture tap not running)" covers a tap that failed to start or stayed disabled after the watchdog's re-enable; the Phase 3 "Event tap: …" line keeps describing the mouse tap only.

## Surface 6 — The spike CLI's printed output (D-09)

`transom-gesture-spike` is a command-line tool the **user** runs in their own terminal on the host for the live half (agents never run it live on the host, D-08). It opens no window, makes no layout change and moves no window. The VM half (`synth`) is run by agents through the `scripts/vm-spike.sh`-style wrapper.

**Streams.**
- **stdout**: human-readable, for the user watching the terminal (format below).
- **`--out <file>`**: JSON lines, one object per event or sequence, for the agent writing `05-SPIKE.md`. Always written. Default path `.build/spike/gesture-{subcommand}-{yyyyMMdd-HHmmss}/out.jsonl`, printed at start and end.
- **stderr**: errors only.
- Every subcommand accepts `--seconds N` (default 30, max 120) and `--label "<text>"`. The label is copied into every JSON record so the agent can match records to checklist steps (for example `--label "safari alt builtin"`).

**Header** (every subcommand):

## Surface 7 — User checklists (D-08)

The user runs these on their own Mac. Wording is fixed here so the agent can paste it into `05-SPIKE.md` and `05-UAT.md` unchanged. Each item says what to do and what should happen. The user answers each with **"pass"** or with what they saw instead. Items marked **(both)** were meant for every trackpad on the Mac; this Mac has the built-in trackpad only (05-SPIKE C5), so they run on the built-in trackpad.

### Spike gate checklist (with `transom-gesture-spike`, Transom not running)

Before you start: give your terminal app Accessibility (System Settings ▸ Privacy & Security ▸ Accessibility). Turn it off again when you're done.

1. **(both)** Run `tap-listen --seconds 60 --label "surfaces {trackpad}"`. Pinch 10 times and two-finger scroll 10 times over each of: a Safari page, a PDF in Preview, a Finder window, bare wallpaper, and one app in full screen. *Expected: one line per gesture appears for every pinch and scroll.*
2. **(both)** Run `tap-consume --seconds 60 --require-alt --label "consume {trackpad}"`. Hold ⌥ and repeat item 1 over Safari and Preview. *Expected: the page neither zooms nor scrolls, including after you lift your fingers. Then, without ⌥, pinch and scroll once: the page zooms and scrolls normally.*
3. Turn off System Settings ▸ Trackpad ▸ Scroll & Zoom ▸ "Zoom in or out". Run `tap-listen --seconds 30 --label "pinch setting off"` and pinch 10 times. Turn the setting back on. *Report: did any pinch lines appear?*
4. Run `mt-stream --seconds 30 --label "system gestures"`. While it runs, swipe between Spaces with four fingers (or ⌃← / ⌃→) 10 times and open Mission Control 10 times. *Expected: every swipe and Mission Control works.*
5. Run `rescan --seconds 120 --label "sleep"`. Choose Apple menu ▸ Sleep, wake the Mac, then pinch. *Expected: lines for the wake and for touches after it.*
6. **N/A** (05-SPIKE C5): reconnecting an external trackpad can't be tested on a Mac with only the built-in trackpad.
7. Run `compare --seconds 30 --label "latency"` and pinch and pan 10 times each.

Then tell the agent where the `out.jsonl` files are (the CLI prints each path), plus your answers.

### Phase UAT checklist (Transom running, zoom on)

## Logging (consume and pass decisions; VNC can't show toasts or hear beeps)

`os.Logger` subsystem `com.eightabyte.transom`. New category **`gesture`**. Existing `camera` lines cover the snap's move and settle unchanged. Every value is interpolated `.public` (no window titles appear in these lines).

**Never log from the tap callback** (RESEARCH: under 1 ms, no logging). The callback only updates counters and the latch. Lines are written on main, once per gesture, when the gesture ends (lift, momentum end or timeout), from a summary the callback filled in. Ordinary scrolls that pass on the PID short-circuit (no ⌥, a non-Finder app under the pointer) are **not logged** and are counted only in the summary: they are almost every scroll on the system.

| Level | When | Message |
|---|---|---|
| default | Gesture taken, at its end | "took {kind} {seq}: {reason}, {e} events, {ms} ms, {outcome}" · `{kind}` pinch / pan · `{reason}` "⌥ held" / "wallpaper" · `{outcome}` "moved to {node}" / "sprang back" / "too small" / the refusal reason ("already home", "nothing to zoom in to", "no area {edge}") |
| default | Gesture ended by timeout | "released {kind} {seq} by timeout after {ms} ms ({e} events)" |
| debug | Passed with ⌥ held | "passed {kind} with ⌥: {reason}" · `{reason}` "zoom paused" / "not ready" / "full screen" / "not a desk display" / "⌃ or ⌘ also held" / "not a trackpad" / "⌥ pressed mid-gesture" / "rect zoom or drag in progress" |
| debug | Passed without ⌥ after the wallpaper test | "passed {kind}: window under pointer" / "passed {kind}: menu or popover under pointer" |
| default | Retarget | Phase 4 camera line, with the gesture as the command: "retarget gesture {kind} during {phase}" |
| default | Gesture tap lifecycle | "gesture tap started" / "gesture tap stopped: {reason}" (`zoom off`, `access lost`, `quit`) / "gesture tap re-enabled after {timeout | user input}" / "gesture tap failed to start" |
| default | State re-published | "gesture state re-published: {wake | display change | space change}" |
| default | Pinch setting (only if the "pan only" value ships) | "pinch is off in Trackpad settings; gestures are pan only" (once per change) |
| default | Multitouch, **only if it ships** | "multitouch: {n} devices" / "multitouch: added {built-in | external} family {f}" / "multitouch: removed registry {id}" / "multitouch: rescan after wake" / "multitouch off: crash canary from last launch (build {b}, version {v})" |
| debug | Session counters, every 60 s while any gesture was taken | "gesture counters: {t} taken, {p} passed with ⌥, {s} short-circuited, {o} timeouts" |

`{seq}` is a per-launch sequence number (`#12`) so a tester can match "took" to "retarget" lines. `{node}` is the NodeID as Phase 4 logs it.
